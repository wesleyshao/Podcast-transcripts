# DHH: Future of Programming, AI, Agentic Engineering, Vibe Coding & Linux | Lex Fridman Podcast #501

## Transcript

### 开场

DHH：过去九个月里，进步的速度像是把几十年的变化压缩进了几周。若一个人没有意识到这件事的重量，反而可能是在自我欺骗。以前我想要一个操作系统的新功能，往往要等很久；现在，只要把目标说清楚，AI agent 可能在几分钟内交付一个可以使用的版本。对我来说，这不是威胁感，而是纯粹的兴奋和乐趣。

DHH：我也把这种变化和赛车联系在一起。赛车让人感到速度、风险和生命力，AI 编程则把这种感觉带到软件世界。好的工具会把人的意图放大，而不是把人变成被流程牵着走的人。

### 介绍

Lex Fridman：今天的嘉宾是 David Heinemeier Hansson，也就是 DHH。他是 Ruby on Rails 的创作者、37signals 的 CTO、Omarchy Linux 的创作者、作家和赛车手。过去二十多年，他以手工雕琢漂亮的 Ruby 代码而闻名，但从 2025 年末开始，他真正投入了 AI agent 辅助的软件开发。

DHH：我并没有放弃对代码质量的要求，只是工作的抽象层发生了变化。以前我亲自写每一个细节，现在我会让 agent 承担大量实现，再把精力放到目标、结构、边界、审查和取舍上。

### 用 AI agent 编程

Lex Fridman：你一年前对 AI 编程还比较谨慎，现在发生了什么变化？

DHH：我现在非常兴奋。AI agent 不是简单的自动补全，而是可以理解一个任务、查看代码库、执行命令、运行测试、修改文件，再根据结果继续工作的协作者。真正的变化在于，程序员可以把问题交给一个能够持续行动的系统，而不是每次只接受一个短语或一行代码的建议。

DHH：我开始用 agent 做以前不会做的小工具。它们可能只服务于我自己，但正因为用户只有一个，需求可以非常具体，反馈也会立刻回来。过去我会因为投入产出比不划算而放弃这些想法，现在可以在很短时间内把想法变成可用的软件。

DHH：这不是说每个结果都正确。agent 会误解需求，也会做出看起来合理但实际上错误的修改。人的工作从逐字符输入，转向提出清楚的目标、提供上下文、检查结果，并不断调整方向。编程仍然需要判断力，只是判断力所处的层级变了。

Lex Fridman：你会不会担心自己只是处在一种 AI 狂热之中？

DHH：当然可以说我处于一种狂喜状态，但这来自四十年的计算机经验。我从未在两个月内见过这样大的转折。一个人长期热爱电脑，突然看到电脑开始主动参与创造，兴奋是合理反应。更重要的是，我正在使用这些工具做真实的工作，而不只是阅读演示。

### 软件将如何变化

Lex Fridman：Adobe Photoshop、成熟的生产力软件和其他拥有大量用户的产品，为什么没有因为 AI 而立刻高速迭代？

DHH：因为成熟团队的瓶颈通常不是实现代码，而是决策、协调、风险和验证。一个功能是否值得做，是否会破坏已有用户的习惯，是否需要客服、文档、销售和合规配合，这些问题不会因为代码写得更快就自动消失。大型组织还会担心每一次变化带来的不可逆后果，因此会用流程把速度压下来。

DHH：AI 会让实现成本下降，但不保证组织愿意承担更多变化。小团队或个人产品反而更容易把速度转化成用户可见的结果。37signals 的经验是，明确边界、限制规模和避免无休止扩张，能够让团队把更多时间放在真正重要的决策上。

DHH：未来的软件会更贴近个人。过去软件必须设计成一套平均化的功能，才能覆盖大量用户；现在一个人可以先做一个高度适合自己的版本，再决定是否把它推广给其他人。个人化并不意味着低质量，反而可能因为需求边界清楚而更准确。

### AI 对开源软件的影响

Lex Fridman：你怎么看待 agent 为单个用户制作工具，以及它和开源社区之间的关系？

DHH：开源软件长期以来解决的是“很多人需要同一个东西”的问题，但很多真实需求并不具有普遍性。AI 让一个人可以快速构建自己的编辑器、视频工具或工作流，这些程序不必先满足所有人的意见。

DHH：开源仍然重要，因为 agent 需要可读、可改、可组合的材料。一个开放的项目可以成为其他人的起点，也可以被 agent 检查、重构和扩展。区别在于，未来贡献者不一定只是手工写代码的人，也可能是提出方向、提供审查和维护价值边界的人。

DHH：当软件的边际实现成本下降，真正稀缺的东西会变成品味、信任、维护承诺和对问题的理解。把一段代码生成出来不难，判断它是否值得长期存在，以及谁愿意为它负责，仍然很难。

### 构建 Omarchy Linux

Lex Fridman：你为什么会从长期使用的环境切换到自己构建的 Omarchy Linux？

DHH：我在电脑上工作了四十年，从来没有见过最近几个月这种变化。我不是因为 Linux 的传统缺点突然消失才喜欢它，而是因为 agent 让这些缺点变得可以被改造。以前复杂的配置文件、零散的工具和不友好的默认设置，会让普通用户望而却步；现在用户可以直接告诉 agent 想要的行为，让系统替自己完成大量配置。

DHH：Omarchy 的目标不是再做一个漂亮的主题，而是让操作系统变得可塑。安装、窗口管理、面板、快捷键和插件系统都可以被用户重新组合。电脑不应该只是一个固定产品，也可以是一个由用户持续塑造的环境。

DHH：Linux 在服务器和开发工具中的优势已经存在很久。agent 天生喜欢可观察、可脚本化、可组合的系统，而 Linux 正好提供了这些条件。过去这些条件对普通桌面用户意味着学习成本，未来它们可能意味着更强的可定制性。

### Vibe coding 与 agentic engineering

Lex Fridman：你如何区分 vibe coding 和 agentic engineering？

DHH：我不喜欢 agentic engineering 这个术语，但它确实指向一种变化。vibe coding 往往强调凭感觉描述目标，然后接受一个看起来能用的结果；真正成熟的工作方式则需要持续的反馈、测试、审查和结构化的上下文。让 agent 写代码并不等于放弃工程。

DHH：在 Omarchy 中，插件系统让用户可以改变操作系统的面板和功能。一个人提出需求，agent 生成初版，用户马上使用并发现问题，再让 agent 修改。这是一种更短的设计循环。它仍然需要人决定什么是好体验，什么是过度复杂，什么是不可接受的风险。

DHH：agent 的强大之处还在于它可以同时处理多个方向。人可以让不同的 agent 探索不同方案，再比较结果。这样做的前提是任务边界清楚，工作目录和权限受到控制，最终决定权仍在人的手里。

### 手工编程会结束吗

Lex Fridman：你曾经非常重视精雕细琢的 Rails 和 Ruby 代码，现在还会这样做吗？

DHH：会，但我不再把全部精力放在同一层。对于核心业务代码，我仍会检查命名、结构、抽象和可读性。只是我现在可以先让 agent 处理大量机械工作，再集中审查真正决定系统形状的部分。以前我是在代码层面雕刻，未来更多是在问题定义、系统边界和用户体验层面雕刻。

DHH：手工写每一行代码曾经是理解系统的一种方式，但它并不是价值本身。如果一个 agent 能可靠地完成重复实现，人就应当把时间放到更高价值的判断上。这个转变不会让软件自动变好，反而会暴露那些过去被手工劳动掩盖的问题：目标不清楚、验证不足、架构缺乏原则。

DHH：未来仍会有需要直接编程的人，但“会写语法”不再是唯一入口。能够理解用户、拆解问题、设计反馈回路、审查复杂系统的人，会比只会快速敲代码的人更重要。

### 给程序员的建议

Lex Fridman：很多程序员因为职业变化而焦虑，他们应该怎么办？

DHH：焦虑是可以理解的，但不要把过去的身份当成未来的全部。先亲自使用这些工具，不要只看别人争论。把一个真实的小项目交给 agent，观察它哪里有效，哪里失败，然后逐步建立自己的工作方法。

DHH：基础知识仍然重要。你不必记住每个 API，但要能判断程序是否合理，知道数据如何流动，理解安全、性能、测试和部署的基本约束。如果不知道正确答案长什么样，就很难审查 agent 的答案。

DHH：同时，不要把学习变成追逐每一个新名词。前沿工具会不断更换，真正稳定的是解决问题的能力、对用户的同理心、对复杂性的克制，以及把产品做完并维护下去的耐心。

### 面对互联网仇恨

Lex Fridman：你公开表达观点后会受到很多批评，怎样处理这些声音？

DHH：互联网会把任何明确观点都放大。你无法避免批评，只能决定是否值得承担它。若一个人永远只说不会引起反对的话，他很难推动任何边界。

DHH：我更关心能否诚实地解释自己的判断，而不是让所有人满意。可以承认自己会错，也可以在证据变化时改变看法，但不能因为担心评论区而放弃表达。批评有时能指出盲点，有时只是噪音，需要自己区分。

Lex Fridman：你希望在这种高速变化中保持什么？

DHH：不要把所有注意力交给最新一轮技术潮流。人们总说旧范式已经结束，新的范式已经到来，但真正重要的生活经验不会每周重写。工作、家庭、友情、身体和创造仍然是长期尺度上的事情。

### AI agent 的编程环境

Lex Fridman：你的键盘、语音和 IDE 工作流有什么变化？

DHH：我用了 TextMate 将近二十年，切换到 Linux 后才被迫离开原来的习惯。现在的界面需要同时容纳代码、agent 对话、命令执行、测试结果和多个并行任务。编辑器不再只是输入字符的地方，而是一个管理意图和反馈的工作台。

DHH：我会把任务拆成可以验证的部分，让 agent 先解释计划，再实现，再由另一个模型或另一轮审查寻找问题。不同模型有不同的偏好和盲点，让它们互相检查，通常比把所有信任交给一个模型更可靠。

DHH：语音输入有明显优势，因为人说话比打字快，也更容易表达背景和目标。但语音不是万能的，精确的修改、审查差异和处理复杂结构仍然需要键盘、终端和清晰的文本上下文。

### 对速度的执着

DHH：AI agent 的速度会改变人的思维节奏。等待十分钟的程序，人会先写计划；等待十秒的程序，人会愿意探索更多分支。等待变短以后，关键不是把每个瞬间都填满，而是利用空档预加载、并行准备和提前验证。

Lex Fridman：你送给我一台已经装好 Omarchy 的 Dell XPS 14，希望我体验这种环境。

DHH：我希望你直接感受一个 agent-first 的操作系统，而不是先读一份说明。系统可以在你回答问题时做后台准备，减少不必要的等待。速度不仅是硬件指标，也包括用户是否能快速从想法得到反馈。

DHH：不过速度不能成为粗制滥造的借口。产品应该在足够可靠的情况下尽早交付，再根据真实使用持续改进。不要因为追求完美而错过验证想法的机会，也不要因为生成很快就跳过验证。

### 语音提示与打字

Lex Fridman：语音会不会成为主要的编程输入？

DHH：它会占据更大比重，但我不认为键盘会消失。语音适合讲清楚目标、背景、取舍和一段较长的思路；键盘适合精确定位、快速修正和检查。最自然的方式是两者结合。

DHH：优秀的系统还应该把人的输入延迟当成机会。当人正在思考或说话时，系统可以准备相关文件、索引代码、运行不依赖后续决定的检查。这样的交互会让人感觉电脑在配合，而不是每一步都重新等待。

### AI 编程模型

Lex Fridman：你如何选择不同的模型？

DHH：不能只看一次回答是否漂亮。模型在规划、实施、重构、测试和审查上的能力可能不同。我会根据任务选择模型，有时让一个模型负责规划和评审，再让另一个模型负责实现。

DHH：目前最有效的配置不是寻找一个永远正确的模型，而是建立互相制衡的流程。Fable 在规划和审查上很强，Opus 5 和 Codex 在不同的实现任务上各有优势。让两个来源不同的 frontier 模型检查彼此，可以减少单一模型的盲点。

DHH：延迟也需要放在价值里衡量。如果某个功能原来根本不会被做出来，那么多等几秒通常不是问题。先让用户获得以前没有的能力，再在真实反馈中优化速度，比一直等到所有条件完美更实际。

### AI 编程 harness

DHH：模型本身只是能力的一部分，harness 决定它怎样工作。上下文如何组织、文件权限如何设置、测试如何触发、错误如何反馈、任务如何恢复，这些都会影响最终结果。

Lex Fridman：我常用一个模型做规划和审查，再用另一个模型实现，这样可以控制 token 消耗，也能让不同系统互相挑战。

DHH：正是如此。真正的 agentic 工作流需要可重复的循环：提出计划、实现、运行检查、读取结果、修正、再审查。把这些步骤连接起来，往往比单独追求一个更大的模型更重要。

DHH：未来的竞争会从“谁能生成一段代码”转向“谁能让系统在复杂环境中可靠地完成任务”。这包括权限、可观测性、回滚、测试、版本控制和人与 agent 的分工。

### AI 视频生成与创作

Lex Fridman：我最近用 Higgsfield 生成了一段赛车视频，你怎么看？

DHH：如果赛车在直道上像电影那样乱降挡，我会立刻指出来。真正好的生成作品不能只看画面表面是否漂亮，还要看它是否理解对象的物理和语境。

Lex Fridman：视频里有你的赛车服和赛车，但实际上是 AI 生成的。

DHH：这说明生成系统已经可以把个人经验、视觉风格和复杂场景组合起来。它会让更多人参与创作，也会让“什么是真实拍摄”变得更难判断。作品价值可能越来越依赖创作者的意图、选择和叙事，而不只是制作过程。

### 父亲身份

Lex Fridman：作为父亲，你最喜欢什么？

DHH：孩子出生后，爱会从一种抽象概念变成每天都在发生的关系。我以前不是特别喜欢孩子的人，但自己的孩子会变成世界上最有趣的人，当然他们有时也会非常难相处。很多人只谈有了孩子以后失去的自由，却忽略了这种关系带来的巨大扩展。

DHH：创造生命和一个你深爱的人共同建立家庭，是人在这个星球上可以经历的最高峰之一。技术能让工作更快，却不能取代这种关系。越是沉浸在电脑世界里，越需要记住现实生活中的人不是可优化的对象。

### Linux 将赢得桌面

Lex Fridman：Linux 桌面真的可能增加采用率，甚至最终成为主流吗？

DHH：我认为这已经是最可能的结果之一。Linux 的很多传统缺点，复杂配置、奇怪的错误信息和不统一的体验，在过去是阻碍；但在 agent 时代，这些地方正是可以被系统主动处理和个性化改造的地方。

DHH：agent 喜欢 Linux，因为它开放、可脚本化、工具链成熟、权限和文件系统可见。一个愿意让 agent 改造电脑的人，会更在意系统是否真正属于自己，而不是只接受厂商规定的工作方式。

DHH：这并不表示 Linux 会自动成功。它仍需要更好的默认体验、安装过程和硬件支持。Omarchy 的意义在于展示一种可能：把 Linux 的能力和更直接、更面向用户的体验结合起来。

### PewDiePie

Lex Fridman：PewDiePie 也在使用 Linux 和 Arch，你怎么看？

DHH：他经历了一个很有意思的转变。曾经是全球最知名的主播之一，后来转向家庭生活，搬到日本，又深入 Linux、Arch 和桌面美化。他不仅在使用系统，还在认真理解它并改造它。

DHH：当一个拥有巨大受众的人展示这种兴趣，Linux 就不再只是程序员的内部笑话。人们会看到，个人电脑可以成为表达个性和工作方式的媒介，而不是一台只能运行固定软件的盒子。

### 个人电脑与编程的未来

DHH：我没有理由掩饰自己的判断：个人电脑的未来是可塑的电脑，是 agentic computer。用户会通过自然语言、代码、插件和自动化持续改变自己的系统。电脑不再只是被动等待点击的工具，而会主动理解目标并参与工作。

DHH：这不会让所有软件都变成自动生成的黑盒。相反，用户会更关心系统能否解释自己做了什么，能否被检查，能否回滚，能否保留人的选择。可塑性必须和控制权一起出现。

DHH：我曾经对某些新项目有过负面判断，也愿意承认自己可能错。未来会有很多人先怀疑 Omarchy，后来发现它确实解决了问题。重要的不是谁最早表态，而是谁愿意亲自尝试并根据体验更新判断。

### 政治与移民

Lex Fridman：你曾因关于大规模移民、人口结构和文化的观点受到批评，你后悔造成的争议吗？

DHH：我不后悔表达这些观点。一个社会如何形成共同文化、如何处理人口变化和国家边界，是值得公开讨论的问题。争议本身并不等于观点错误，沉默也不等于观点不存在。

DHH：但公开表达不代表可以拒绝复杂性。移民涉及个人命运、劳动力、文化、制度承载能力和政治选择，不能只用一个标签解释。我的立场是可以被质疑的，也应该接受具体事实的检验。

Lex Fridman：你如何处理由此带来的网络攻击？

DHH：把可验证的论点和纯粹的情绪分开。人可以反对我的判断，但最好指出我在哪个事实、推理或价值取舍上错了。若只是因为一个人表达得不讨喜就要求他闭嘴，公共讨论会变得更贫乏。

### 长寿、过度优化与死亡恐惧

Lex Fridman：你妻子把科技圈男性对极端长寿的执着比作女性的厌食症，把它看成焦虑和失控感的外在表现，这个说法为什么让人印象深刻？

DHH：因为它触碰到了一个真实的心理结构。追求健康本身没有问题，但当生活的每个部分都被量化、监测和优化，人的注意力可能从真正的生活转向对死亡的恐惧。一个人可以把延长寿命当成项目，却仍然没有回答希望用额外时间做什么。

DHH：我不反对医学进步，也不认为接受衰老就是放弃生活。问题在于，不能让对死亡的恐惧吞掉当下。家庭、创造、友谊和冒险带来的价值，不能简单换算成一个生物年龄数字。

### 永恒轮回与人类文明

Lex Fridman：如果从更长的时间尺度看，人类文明会怎样？

DHH：人总觉得自己正处在历史最剧烈的时刻，但很多基本体验其实一直存在。技术会改变工作、生产和表达方式，却不会消除对意义、归属、爱和死亡的追问。

DHH：我希望未来的电脑能让人做更多只有人真正想做的事情，而不是让每个人都被迫围绕工具重新组织生活。机器可以帮助我们创造、探索和照顾别人，但生活的价值不应被“效率”单独定义。

Lex Fridman：我们最后聊到食物、家庭、旅行和日常生活。

DHH：这些看似琐碎的事情，恰恰提醒人不要只生活在抽象系统里。一个美好的家庭、一个真正好吃的东西、一场让人筋疲力尽但仍然满足的赛车体验，都比不断刷新技术新闻更接近生活本身。
