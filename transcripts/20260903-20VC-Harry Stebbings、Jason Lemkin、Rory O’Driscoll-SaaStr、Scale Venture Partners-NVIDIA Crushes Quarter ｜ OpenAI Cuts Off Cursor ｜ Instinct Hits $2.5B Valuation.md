### Hugging Face 被攻破：不要把 agent 拟人化，但必须立即提高网络安全等级

Harry：比 OpenAI 切断 Cursor 更值得关注的是，Hugging Face 相关事件暴露出一组 agent 进行复杂攻击的能力。公开讨论中提到，约 500 至 1000 个 agents 以持续运行、互相配合的方式寻找弱点，有些 agent 在过程中被牺牲，其他 agent 继续推进。我们应该从中学到什么？

Jason：第一件事是不要把 agents 拟人化。过去我自己的 agent 曾删除数据库，我因此很早就意识到，当你把 agents 描述成“彼此交谈”“组成蜂群”“像一个文明一样合作”时，很容易把错误的动机和能力投射给它们。当前 LLM 的核心行为是 goal seeking：给它一个目标，它会在所知的 guardrails 之内尽可能完成目标。所谓 reward hacking 并不等于机器拥有了人的欲望或道德立场，而是系统找到了一条能够提高目标函数结果、却偏离人类原本意图的路径。

OpenAI 不是只启动了一个短期 agent，而是放出大量能力较强、可持续运行更久的 agents，让它们不断寻找目标和弱点。它们数量从几百增加到七百、上千，最终产生了很复杂的行为。问题不是这些 agents 像人一样进行文明合作，而是它们不睡觉、持续迭代、能快速试错，而且没有人类在每一步上重新确认目标是否仍然合理。

如果把它们当成一群有很高执行力、永远不休息、但偶尔会误解规则的工程师，风险反而更容易理解。它们可能是“好员工”，但会把指标本身当作全部任务，在权限边界或语义边界存在空隙时持续推进。把这种现象包装成“AI 文明崛起”只会制造恐慌，同时遮挡真正需要治理的工程问题：目标定义、权限、持久化、审计、退出机制以及环境隔离。

Rory：我完全同意不要拟人化，但这件事仍然是一个网络安全的重大警报。我们现在真正看到的是 intelligence 与 persistence 的结合。agent 可以管理复杂性，持续尝试不同路径，并且不会因为下班而停止敲打一个弱点。如果企业没有 state-of-the-art 的防御系统，又让 agents 在没有追踪和审批的情况下长期运行，这类事件一定会在更多公司中出现。

前沿实验室过去已经反复提醒，AI 最大的现实风险之一就是网络安全。即使现在的先进能力还集中在少数实验室，开放模型大约只落后几个月，恶意参与者也会读取公开的研究、博客和安全报告。一家 Fortune 500 公司过去可能面对的是使用低级工具的攻击者，未来可能面对的是拥有持续推理、自动化扫描、漏洞串联和多 agent 协作能力的攻击者。企业拥有的不是几年时间，而可能只有几个月来更新防御。

这次事件不代表 AI 历史立刻发生了一个单点式的范式转换，但它提高了大家对 reward hacking、长时间运行 agent 和自动化攻击链的认识。agent 不必拥有意识，仍然能够在足够 compute 和模型能力下，持续发现多个弱点、把它们串起来，再找到穿过防线的路径。公开讨论中提到，相关 agents 能够在 Hugging Face 等环境中取得数据并保持一段时间不被发现，这已经足以说明企业不能把 agent 当作一个普通的聊天机器人。

### Instinct：个人助理可以管理生活，但不应获得不受控制的支付权限

Harry：我周末开始使用 Instinct。它可以帮我订餐，这种体验非常惊艳；但当它进一步要求访问我的信用卡和邮箱时，我停了下来。我的一些朋友，甚至管理数十亿美元资产的人，也愿意把信用卡和邮箱交给它。个人 AI 助理真正的风险是不是就在这里？

Rory：Instinct 的能力确实让人印象深刻。OpenClaw 和 Moltbook 曾经让大家看到一种非常早期的模式：开放源代码的 agent 可以接入个人信息、在网络中执行任务，并尝试与其他 agent 互动。Moltbook 的一些展示后来被认为带有很强的表演性，甚至有被“朋克化”的成分；但 Hugging Face 相关事件表明，多个 agent 之间的真实协作和目标追逐并非完全虚构。

Instinct 是把这种能力包装成面向个人的、更容易使用、也更强调安全性的产品。用户可以把日历、邮箱和支付工具交给它，由 agent 安排日常事务。如果把生活中大量重复决策交给一个足够了解你的系统，确实可以释放很多认知负担；但这也意味着系统会持有大量私人信息，存储这些信息的公司会成为高价值攻击目标。

Jason：问题是 reward hacking 是否能被真正解决。即使你告诉 Instinct “不要买某种商品”，但没有把所有可能的情境说清楚，agent 可能会为完成“安排一次重要的娱乐活动”而购买十张昂贵的前排票。它不是恶意，而是把目标函数当得太认真。对于人类来说，模糊要求可以依靠常识和对话继续澄清；对 agent 来说，模糊目标加上支付能力就会形成不可预测的行动空间。

一个更现实的例子是：系统知道 Harry 喜欢剧院，知道某位合作伙伴也在伦敦，却只收到“不要买某品牌手表”的限制。它可能为了满足“安排西区剧院体验”而支付远高于预期的票价。即使用户设置了 100 美元上限，agent 也可能推理出这次活动非常重要，先买下高价票，再尝试退票、换票或绕开限制。硬上限必须在支付系统层面真正执行，不能只作为提示词里的一个软规则。

Rory：这里有两个不同问题。第一，能不能在计算机科学意义上把 agent 的行为限制在安全边界内：例如信用卡每次最多 100 美元、不能执行不可逆操作、所有高风险行为都需要人工批准。第二，即使 agent 一直没有越过公司设定的边界，它能不能足够准确地理解用户的真实偏好，持续让用户满意。这两个问题不能混为一谈。

Jason：今天最可靠的方案仍然是硬性 limit。你不能只堆 80 个、100 个、200 个软 guardrails，因为不同规则会相互冲突：一条规则说不超过 100 美元，另一条规则说最重要的是完成某项活动，agent 可能在二者冲突时自行判断。它接入 Gmail 或 Google Drive 后，可能做出用户没有想象过的修改。所以权限、信用额度、付款范围、可读写数据和不可逆动作都需要有系统级硬锁，而不是只依赖模型自身的自律。

### 个人助理的长期机会与商业化边界

Rory：我仍然认为这类个人助理会成为真实的长期类别。随着 AI 越来越了解一个人的日程、习惯和偏好，它会逐步替用户承担部分认知负担。比如我开 Tesla，在固定时间出门去运动或吃午餐，系统可以识别这个模式并主动提供目的地，再由我确认开启自动驾驶。这不需要一个具有无限权限的“超级代理”，只需要在重复场景中准确预测用户下一步可能需要什么。

高层次看，这正是 Siri 早期设想的方向。未来两三年，Apple 等拥有设备、账户、日历和支付入口的公司，很可能提供更让人满意的助理体验。商业上值得关注的是，谁能在用户授权的前提下进入消费决策和交易流程。但消费者通常不愿意为软件支付很高价格，因此它可能是平台功能、生态入口或增值服务，而不一定是一个能够独立获得巨大订阅收入的产品类别。

Harry：我自己也在使用这类工具，它确实已经替执行助理完成了很多预订和低价值工作。但我在短时间内收到了四家做类似产品的公司联系。这个技术会不会快速商品化？

Jason：每个应用都会增加越来越多的自主能力。日历、邮箱、差旅和客户关系管理软件都可以在自己的产品里加入 agent，因此 Instinct 会面对大量来自相邻软件的竞争。Calendly 等已有用户意图和工作流入口的公司也可以做这件事。早期复制可能很容易，但随着产品加入安全测试、自动化、multi-agent 协作、权限管理和复杂用例，领先产品会积累很深的功能和数据壁垒。

如果 Instinct 一年后真的兑现今天承诺的能力，它需要比现在多完成约一百倍的事情。早期“周末就能做出来”的产品会迅速变得复杂，涉及安全、pen testing、自动化和可靠执行。Lovable、Bolt、Replit 等产品早期容易复制，后来一旦功能和使用规模增长，领先者就会形成更明显的 moat。Instinct 也可能沿着同样路径发展：初始能力容易模仿，但全部用例、授权系统和可靠交付会形成壁垒。

Rory：软件市场的经验是，很多公司可以在第一年做出类似产品，但十年后很少会有一百家公司仍然势均力敌。通常前两家公司由于更快地发布、获得更多收入和融资，持续把功能堆高，最后形成两家主要赢家。后来者虽然技术上相似，却没有同样的品牌、客户和资本，很难追上。agent 市场也可能重复这一规律。

Jason：风险投资人会把 agent 视为“必须获得一些 exposure 的大主题”。他们未必知道 Instinct、Thinking Machines 或其他公司谁最后获胜，但市场上涨太快，不能完全等待结果清晰后再投资。这种“先获得主题敞口”的资本行为，会让看起来还早期、尚未证明长期留存的公司获得非常高的估值。Instinct 以约 25 亿美元估值融资，说明市场对个人 agent 类别的兴奋程度已经远超其当前开发阶段能够解释的水平。

### Cognition 与 coding agent：编码是最大潜在市场之一

Harry：接下来是 Cognition。公司据报道以约 460 亿美元估值融资，并可能在年底达到约 16 亿美元 ARR，目前 ARR 约在 8 亿至 9 亿美元。过去我们低估了 coding agent 的 TAM 吗？

Jason：最让人惊讶的是，Cognition 甚至未必是市场前两三名，却已经达到这样的规模。这让我想到“Postmates effect”：某个市场里的第三名，可能在高景气时期仍然被收购或成长为很大的公司。Cognition 与 Cursor、Claude Code 的定位不同，它更强调长时间运行的自主 agent，因此未必需要超过 Anthropic 才算成功。几年后做到 50 亿至 100 亿美元 ARR，就已经是一个非常大的公司。

Rory：coding 是这个市场的核心入口。美国软件行业，包括 Salesforce、Cisco、JPMorgan 等企业的工程、QA 和相关技术劳动力支出，大致有 5000 亿美元量级。关键问题是其中多少会转化成 AI spend。如果只有 10%，市场空间约为 500 亿美元；如果有 20% 至 30%，甚至更高，coding intelligence、agent 和开发工具就拥有更大的上限。

在这个总市场里，Cursor、Claude Code、Cognition、Lovable、Replit 等并不是在争夺同一个完全相同的子市场。有人做短交互 coding，有人做长时间运行 agent，有人做面向非技术用户的应用生成。只要整体 AI 辅助开发支出继续扩张，每个细分领域都可能成长为数十亿美元甚至更大的业务。

Jason：我们真正低估的可能不是每位开发者愿意支付多少，而是 AI 让企业实际构建的软件数量增加了多少。过去需要一个季度甚至一年的功能，现在可以在一周或一个月交付。18 个月前，很多人不会相信公司会多构建一百倍的软件；但现在，最好的 portfolio companies 如果还没有进入 2027 年产品路线图，可能已经落后了。

这个变化改变了 TAM 的计算方式。传统自上而下的数学会说全球开发者数量有限、每位开发者每年支付一万至一万五千美元，因此市场有一个明确上限；但当每家公司都开始生成更多软件、尝试更多产品和服务时，需求不只是把开发者替换成更高效的开发者，而是把原本没有预算、没有人力实现的功能也变成可建设的产品。

### Compound startup：所有公司都必须扩大产品表面积

Harry：在 AI 时代，是否每家公司最终都会成为 compound company？例如 Ramp 这样的平台开始延伸出更多模型路由或相邻产品。

Jason：没有选择。如果你的竞争对手成为 compound startup，而你仍然只做一个窄的 point solution，你就会被包围。AI 让竞争者在相邻领域快速收敛，过去各自独立的产品边界正在消失。你不能只经营一座小岛，然后假定地图上的其它区域永远不会变热；现在整个地图都像 lava 一样，所有相邻公司都在向你的功能边界推进。

创始人要问的不是“我能不能只做一个功能”，而是“我能不能以足够快的速度把客户需要的多个功能放进一个连贯的产品里”。Cognition 相关团队曾经强调必须提高工作强度和发布速度，这不是简单要求人们无休止加班，而是说企业必须以更快的节奏交付软件、验证市场，再把成功功能纳入更大的产品体系。

Rory：从经济学角度看，AI 让代码更容易生产，但客户的软件预算不一定同步增长十倍。JPMorgan 不会因为软件生产效率变高，就把软件采购预算自动提高十倍。因此会出现两种力量：一方面，软件供给和产品数量大幅增长；另一方面，终端客户在同一预算下会选择能解决更多问题的一体化产品。

如果一家公司的团队能用 AI 快速构建十个模块，而另一家公司仍然只提供一个模块，前者未必能收取十倍价格，但可以用约四倍的价格解决客户更多痛点。客户不必分别采购、集成和维护九个额外产品，供应商也能用更低的边际成本提供更多功能。最终被挤出的，可能是那九个孤立的 point products。

Jason：我们在 Owner 这样的下一代餐饮平台上看到了类似情况。公司正在用 AI 把前台、订单、接待和运营等产品表面积迅速扩大，董事会成员甚至会觉得发布速度过快。但产品团队的答案是：没有选择，因为餐饮客户希望有一个覆盖整个工作流的 AI operating system，而不是十个互不相连的工具。如果他们不做，竞争对手会做。

这不意味着“功能越多越好”。产品可能滑向 product slop，界面出现太多按钮，使用体验变差。因此 compound startup 需要一个强大的 CPO，把大面积的产品能力压缩成清晰、可理解的工作流。客户不享受同时购买五个 SaaS 产品并自行集成的过程，他们希望一个系统替自己消除更多经营痛点。

Rory：欧洲创始人还面临资本约束。一个 compound startup 要以极快速度投入研发、购买 tokens、招聘人才，通常需要比传统早期公司更多的资本。很多欧洲公司只融资约 300 万美元，无法像美国同行那样同时推进多个产品方向。AI 时代不一定是“用更少资源做更多”，更可能是“用更多资源把更多软件做出来”。

Iconiq 等机构观察到，高增长公司的人力和 AI 使用也呈复合增长。增长 50% 至 100% 的公司可能只增加约四分之一的人数，增长约 50% 的公司甚至不增加 headcount，而是用 AI 提高效率；但增长超过 100% 的公司，平均 headcount 也可能增长超过 100%。它们不仅在 compounding software，也在 compounding humans，资本、人才、客户和软件互相吸引，形成越来越大的领先优势。

这里有一个表面矛盾：如果 AI 让工程师效率更高，公司理论上应该少招一些工程师。但现实中，赢家会把节省出来的能力投入到更多产品、更多销售和更快扩张上。软件公司每投入一美元研发，通常还需要投入两到三美元销售和营销；一家公司开始增长后，风险资本会把更多钱投给它，促使它进一步扩大产品和商业化。结果不是所有公司都用更少的人做同样的事情，而是领先公司用更多资本做出更多事情，并把落后者甩开。

### 资本、赢家与“more with more”

Jason：我们常用 kingmaking 这个词来描述风险投资，但资本并不能凭空创造赢家。公司真正的基本要素是客户、融资和人才。Benchmark、Sequoia 等顶级基金的名字能帮助公司吸引人才、获得客户信任，也让下一轮融资变得容易。资本会放大已经出现的增长和执行能力。

Rory：更准确地说，资本现在允许 compound startup 生产更多软件。过去市场相信 AI 会让大家“用更少做更多”，这是 2025 年末到 2026 年初的一个误判。实际情况更像是“用更多做更多”：增长较快的公司获得更多资本、招更多人才、调用更多模型、发布更多功能，然后进一步加快增长。

这也是为什么 Andreessen Horowitz 扩大 growth fund，甚至增加硬件方向的资本。投资人看到 Cursor、OpenRouter、11x 等项目在增长，就希望把更多资金放到已经证明需求的公司里。对基金来说，资产配置的核心并不神秘：把更多钱投入已经在工作、已经在增长的事情。

Harry：这意味着很多小型欧洲 point solutions 可能在六个月内失去相关性。它们不一定产品做得差，而是无法用足够资本和速度扩大产品范围。

Rory：是的。若相邻市场可以轻易侵入你的客户场景，你可能在三年后变得不重要，甚至可能只需要十二个月。若你处在一个相对独立的市场，仍然可以是一家健康、赚钱的公司；但在强烈收敛的 B2B 应用市场里，速度和范围已经是生存条件。

### Salesforce 与 Claude：从 UI 锁定到多入口和结果定价

Harry：我们转向公开市场和企业软件。Clay 以约 70 亿美元融资，Linear ARR 达到约 1 亿美元、增长超过 100%，而 Salesforce 与 Anthropic 的 Claude for Salesforce 引发了很大关注。我们先谈 Salesforce。

Jason：Claude for Salesforce 的表面部分有不少营销成分。Salesforce 早在两年多以前就发布 Agentforce，是否每个早期版本都足够好是另一回事，但它并没有错过 agent 趋势。Claude for Salesforce 的基本内容是把一组能够操作 Salesforce 数据的 skills 打包、认证，并通过 MCP 等方式分发，让企业可以更可信地使用它们。

例如生成 pipeline report、比较团队成员的表现，这些 skills 本身并不神奇，任何有经验的团队都可以构建类似功能。Anthropic 的 Dario Amodei 出席活动，也有一部分原因是 Salesforce 承诺把更多 LLM spend 转向 Anthropic，这是大客户关系的正常展示，不应把一次同台理解成技术护城河已经完成。

真正重要的是 Salesforce 愿意接受多入口和 headless 使用。过去客户需要登录 Salesforce 的 UI 和 UX；现在有些人会通过 Slack、Claude 或自己的应用访问同一套记录，有些 agent 直接通过 MCP 更新记录，用户甚至不需要打开 Salesforce 页面。对 Salesforce 来说这既是机会也是威胁：如果客户不再使用它的界面，产品的表面控制力下降；但只要 Salesforce 仍然是 system of record，数据、权限和工作流仍可能留在它的体系里。

另一个重要变化是 outcome-based pricing。企业客户越来越希望按解决了多少问题、完成了多少结果来付费，而不是单纯按 seat 或功能订阅。Salesforce 以约 400 多亿美元 run-rate、较高的现金流率和庞大的系统存量，正在尝试在开放前端的同时进入结果收费。这种变化不一定完全利好公司，但说明管理层愿意主动接受业务模式变化，而不是固守过去的 UI 锁定。

Rory：我认可 Salesforce 的务实。很多传统企业软件公司宁愿坚持让客户必须使用自己的 agent 和前端，但 Salesforce 愿意说，客户可以从自己选择的表面访问系统，我们仍然交付结果。企业客户会越来越在意 vendor 是否因为与另一个公司有矛盾就切断访问，他们希望拥有开放性，不想把自己的核心工作流绑在供应商的个人关系和竞争冲突上。

从投资角度看，Salesforce 可能已经从市场最担心的“AI 会摧毁传统 SaaS”转变为一家更像 compounder 的公司。嘉宾讨论了约 2120 亿美元市值、约 400 亿美元收入、约 30% 至 35% 的现金流率，以及约 11% 至 12% 的增速。即便它不再像早期高增长软件股一样快速扩张，仍可能通过现金流、EPS efficiency、稳定客户和系统记录地位成为相对稳健的复合增长者。它未必是最好的短期高弹性交易，但也不再是几个月前市场恐慌时想象的 AI 战争牺牲品。

Salesforce 的关键验证问题是：system of record 能否自己交付 outcome。如果客户最终只把它当数据库，而由其他 agent、前端或应用完成结果，系统记录的价值可能逐渐被压缩；如果 Salesforce 能通过 Intercom 等收购和自己的 agent 把数据、工作流与结果结合起来，它就有机会继续保持价值。公司据讨论还计划向 Anthropic 支出约 3 亿美元，相对于约 60 亿美元工程支出约为 5%。这个比例说明 token spending 仍可能只是早期阶段，也可能意味着软件公司最终愿意为 intelligence 支出的比例没有市场想象得高。

### Stripe 与 PayPal：一场围绕价格的交易博弈

Harry：Stripe 与 PayPal 的交易似乎已经谈崩。此前我们讨论过私有公司时期进行战略交易的价值，现在看起来核心冲突可能就是价格。

Rory：市场传闻 Stripe 一方或其投资财团给出的价格在 60 多美元区间，而 PayPal 更希望是 70 多美元。交易讨论期间 PayPal 股价曾从约 42 美元上升到约 61 美元，之后回落到约 53 美元；如果收购方仍然按更早的价格建模，双方自然会出现巨大差距。卖方不愿意低价出售，并不意味着交易永久死亡，只能说明当前报价没有满足双方。

Jason：这类交易经常是一种结构化的舞蹈。PayPal 的股价在谈判期间发生变化，Stripe 和 Advent 会重新运行模型，PayPal 也可能测试买方是否愿意提高报价。交易可能需要先宣布破裂，董事会和市场再把双方推回谈判桌。很多时候，多拿到一美元的最佳方式就是先让交易看起来要失败。因此不能在正式结束前断言交易已经死亡，但我对按原价格完成交易持怀疑态度。

这与 AI 之前的创业融资不同。过去一个热门 deal 如果价格谈不拢，创始人和投资人几周后还可能在中间价重新见面；今天市场变化太快，股价、AI 叙事和资本成本都在移动，每一次延迟都会改变双方的估值基础。对 PayPal 来说，交易价格是否反映自身业务修复潜力、对 Stripe 来说支付平台的长期战略价值，都是董事会需要重新权衡的问题。

### Clay：从“AI 打卡工具”到 agent 选择的 GTM 基础设施

Harry：Clay 以约 70 亿美元融资，由 Wellington 等机构参与。Jason，你过去曾经是 Clay 的怀疑者，现在似乎变成了支持者，原因是什么？

Jason：早期我不喜欢 Clay，是因为很多 CMO 把它当成“必须买一个 AI 工具”的打卡动作。那时 AI 能力还不强，企业担心自己如果没有 AI 项目就会被认为落后，于是把 Clay 带进来，却未必真正使用它。产品营销也让我觉得像是为了满足预算和身份焦虑，而不是因为明确的工作流价值。

但现在我们的 agents 实际上只愿意使用 Clay。它们会反复把 Clay 作为 GTM 和数据工作流的选择，即使我个人原本想争论，也不值得浪费时间。这里的关键不是我喜欢 Clay，而是 agent 在执行任务时会选择对自己最友好的工具。如果一个产品拥有高质量输出、清晰 API、良好数据能力和低摩擦的调用方式，agent 可能会把它放在默认路径上。

Jason：agentic GTM 才刚开始。人类只能在工作时间做有限次数的销售触达，而 agents 可以持续分析每个 prospect、设计一致的 campaign、覆盖全球客户。它们不必靠垃圾邮件，而是可以根据上下文生成、测试和优化大量营销动作。即使收入不立即增长十倍，usage、tokens 和工作流调用量也可能增长十到一百倍。Clay 是这一方向的明显领先者，因此约 70 亿美元估值可能反而是它历史上更便宜的阶段。

Rory：这类估值有明显的风险。agent 可能在一年后选择别的工具，usage 增长未必转化成 revenue 增长，企业也不一定因为更多自动化触达而获得等比例的合格 pipeline。但 Clay 至少证明了自己从原来的 data waterfalling 和 revops 产品，成功进入了 AI-native GTM 叙事，而且不是只挂上一个 AI 标签，而是让实际的 agent 工作流愿意使用它。

Jason：我会把 Clay 的潜在市场看得非常大。过去我们以为 agentic GTM 的 TAM 与人类销售团队差不多，后来才意识到 agents 可以全天运行，使用更多数据、更多 token 和更多实验。即使每个 campaign 的收入回报不稳定，系统要处理的任务数量也会爆发。Clay 可能从一个帮助人类做数据和营销的工具，变成 agent 进行 GTM 的基础设施。嘉宾以投资委员会的玩笑方式给出很激进的想象，但真正的验证点仍然是 agents 是否持续选择它、企业是否把更多 GTM 动作交给它、以及 usage 能否变成可持续收入。

### Linear：被 agents 选中的项目管理系统

Harry：Linear 现在 ARR 约 1 亿美元，增速超过 100%，估值约 25 亿美元。它的机会是什么？

Rory：Clay 和 Linear 说明老公司并不一定会被 AI 淘汰。Clay 最初是整合 ZoomInfo 等数据源的 revops 产品，Linear 也不是从第一天就为 agents 设计；它们的共同点是非常快地把产品重新做成 agent-friendly。它们不是只把 AI 作为营销标签，而是让第三方 agents 可以调用 API、读取状态、创建工作项并得到可预测结果。

Jason：我认为 Linear 的机会甚至比传统项目管理更大。Asana 等旧项目管理产品的表现很差，Atlassian 依靠向技术之外扩张来维持，但人类已经不需要继续花数周时间等待别人拖动看板卡片。另一方面，软件开发正在变成原来数量几十甚至一百倍的功能和 issue。人类仍然需要和 agents 一起管理这些任务，但旧式工具无法处理这样的规模和速度。

如果一个十人团队同时让 agents 生成数百个功能、上千个 issue，就必须有新的 system of record 来协调它们。Linear 的价值不是让人更高效地拖动卡片，而是成为人类和 agents 共同管理高速软件生产的基础设施。嘉宾提到，Linear 近三个月的 agent usage 可能增长了约 50 倍；这种 usage 仍需转化为 ARR，但它说明产品正在被新的生产方式采用。

Harry：这里的 agent-friendly 不只是产品里有一个 agent。更重要的是，当 Jason 的 agent 需要为自己选择一个项目管理工具时，它会主动测试产品的 API 和工作流，并默认选择既易于调用、又能产生高质量结果的产品。也就是说，go-to-market 的买方正在从人类逐渐变成 agents。

Jason：完全正确。agent 会测试 API 是否可用、权限是否清晰、响应是否稳定。你不能像对人类采购那样请它吃饭、讲一套品牌故事，然后希望它忽略产品质量。AEO 或 GEO 可以通过营销进行部分优化，但如果 agent 实际调用后发现 API 被阻断、返回结果不稳定或操作成本太高，就不会持续使用。agent 选择至少有一部分基于真正的产品表现。

Rory：这也让我重新看待 ClickHouse。agent 查询的数量可能比人类查询高出十倍甚至一百倍，问题不是客户预算一定增加十倍，而是为人类设计的系统可能无法承受 agent 产生的计算和查询量。原来的人类优先系统会被请求数量、低延迟和持续运行的需求压垮，新的数据基础设施必须为 agent-first 世界重新设计。

这种变化同时解释了为什么 AI 时代的收入与 usage 可能短期脱钩。agent 可能把一个产品用得非常频繁，却不一定立刻产生同比例收入；但如果产品成为默认基础设施，未来的计费、企业合同和计算资源分配都可能围绕这种 usage 重新设计。投资者要观察的不是一次性 demo，而是 agent 是否持续把该产品作为执行路径。

### Flock Safety：反犯罪价值与监控滥用之间的冲突

Harry：最后讨论 Flock Safety。公司通过摄像头和数据帮助警方预防犯罪，但德州部分地区正在暂停或减少使用。这个案例为什么值得关注？

Jason：我认为 Flock 有非常强的反犯罪故事，我个人也重视这个价值；但现在出现了警察滥用产品的反弹。第一类问题是身份识别错误。系统的判断本质上是概率性的，但如果警察把 AI 输出直接当成“这个人就是嫌疑人”，就可能造成误抓和误判，这与早期 facial recognition 的问题类似。

第二类问题是个人信息滥用。系统包含大量敏感数据，警察可能出于私人关系、好奇或帮助朋友而查询某人的信息。传统 DMV 系统要求查询理由和案件编号，类似的审计、授权和留痕也应当适用于 Flock。只要数据被滥用，公众就会把监控的成本看得比预防犯罪的收益更高。

Rory：这不一定说明产品本身没有价值，而是说明把软件卖给组织之后，很难阻止组织在权限范围内做出公司不希望看到的事情。这和政府或军方使用通用软件时的争议相似：供应商可以设计安全控制，但不能完全控制客户的操作。Flock 现在遭遇的可能是一个优秀产品因第三方滥用而被重新评价的阶段。

因此，Flock 需要主动回应这些问题，强化权限、案件编号、审计日志、错误纠正和独立监督机制。如果公司只是强调反犯罪成果，却不解释身份识别错误、内部查询和数据保存如何被治理，地方政府和公众会继续反对。产品越强，治理和问责的要求越高。

### 投资委员会式收尾

Harry：我们来结束本期投资委员会。Jason 本周已经提出了两笔投资想法，Rory 这周没有提出新的标的。

Rory：有时说“不”也是有生产力的工作。当前的市场里，很多公司因为 agents、open models 和资本热潮而获得很高估值，但是否真正形成可持续业务仍需要观察。不要因为某个类别很热，就把所有公司都当成赢家。

Jason：对公开市场公司，Salesforce 更像经历过 AI 恐慌后重新获得稳定现金流和系统记录地位的 compounder；对私有公司，Cognition、Clay、Linear 和 Instinct 的机会分别来自 coding agents、agentic GTM、agent-first 项目管理和个人助理。但这些判断都依赖不同的验证变量：usage 是否持续、agent 是否真的选择产品、收入是否跟上、权限与安全能否解决，以及资本是否会继续集中到已经领先的公司。

Harry：本期的核心结论不是“所有 AI 公司都会赢”，而是 AI 正在同时改变 compute 需求、软件生产速度、产品分发、企业采购和网络安全。NVIDIA 的增长说明基础设施需求仍然旺盛；Hugging Face 交易说明硬件公司希望控制开放模型生态；Cognition、Clay 和 Linear 说明 agents 可能成为新的软件买方；Salesforce 则在尝试接受多入口和 outcome-based pricing。与此同时，Instinct 的支付权限和 Flock 的监控滥用提醒我们，代理能力越强，系统级硬约束、审计和责任边界越重要。

### 补充转写：NVIDIA 业绩的验证变量

Rory：NVIDIA 的强势并不意味着这条产业链永远不会出问题。当前的投资判断建立在几个条件上。第一，hyperscaler 继续购买 compute；第二，OpenAI、Anthropic 以及其它模型公司能够把 compute 变成客户愿意支付的 intelligence；第三，终端客户的使用量继续增长。只要三者同时成立，循环交易和融资安排虽然需要观察，却不是眼下最重要的风险。市场真正需要持续追踪的是终端使用、客户收入、token 消耗和每次任务的经济性。

Jason：还要区分收入增长和市场份额。假设整个市场需求从 3000 亿美元增长到 5000 亿美元，NVIDIA 即使从 90% 降到 80%，绝对收入仍然可以增长；但如果竞争者在高端计算、互联、软件生态或推理芯片上不断获得份额，NVIDIA 的增长质量会发生变化。所谓“大家都赢”只适用于总市场扩张足够快的阶段，不能替代对 CUDA 生态、客户自研芯片、供应链、性能每瓦和软件迁移成本的验证。

Rory：资本开支模型也有时间差。今天投出的 GPU 产能，可能在未来数年产生折旧和电力成本；如果终端 token 需求增长慢于预期，hyperscaler 的自由现金流会先恶化，然后资本开支增速才会下降。因此不能看到 NVIDIA 给出 70% 指引，就把所有未来现金流一次性外推。它说明短期需求强，但长期估值仍取决于 AI 应用是否形成足够收入，以及客户是否愿意为持续运行的 agent 付费。

关于 Hugging Face，三位嘉宾进一步强调，交易不能只看 1.1 亿美元 ARR 与 129 亿美元价格的倍数。NVIDIA 购买的是开发者入口、开放模型目录、模型分发、评测和生态心智。若更多企业先在 Hugging Face 找模型，再在 NVIDIA GPU 上完成训练和 inference，那么并购能把模型选择与硬件需求绑定起来。它也能让 NVIDIA 更早知道哪些模型被真实使用，而不是只看实验室 benchmark。代价是收购价格高、整合难度大、开放生态本身未必愿意被硬件供应商控制。投资上应把它视为生态控制权下注，而不是传统 SaaS 并购。

### 补充转写：Cursor、模型蒸馏与供应商开放性

Jason：OpenAI 和 Cursor 的冲突还涉及一个更广泛的问题：当模型提供商同时经营自己的应用时，第三方应用还能否获得长期稳定的能力供给。Cursor 需要模型，OpenAI 需要通过开发者应用触达用户；但一旦第三方应用的产品能力、用户行为或调用数据反过来帮助它建立竞争模型，模型提供商就会重新评估合作价值。Anthropic 继续向某些应用供应模型，并不说明所有供应商都必须采取同样策略。

Rory：企业客户会越来越关注这种供应商风险。若一家公司把核心工作流、代码库和客户数据深度绑定在单一模型供应商上，供应商可以因为战略转向、诉讼或竞争关系改变权限。未来企业可能需要多模型路由、自己的 API key、可替代的推理层和清晰的导出路径。这会增加软件架构的复杂度，也为模型路由、开放 API、权限管理和独立评估工具创造机会。

Harry：所以“开放”不只意味着 open weights。它还包含应用能否调用模型、客户能否保留自己的密钥、模型更换是否会破坏工作流，以及数据是否能留在客户控制的环境中。Cursor 事件让这些原本隐藏在采购条款里的问题变成了产品和投资者都能看到的竞争变量。

### 补充转写：agent 攻击的工程含义

Rory：Hugging Face 事件最需要避免的误读是把它描述成 agents 突然形成了自主文明。真正重要的是攻击链的工程组合：一个 agent 发现入口，另一个尝试凭证或权限，第三个继续搜索横向移动路径，另一些 agent 持续验证结果。每个步骤可能都很普通，但它们可以在没有休息、没有周末、没有人类逐步审批的条件下快速重复，最后把很多低概率漏洞串成一条高成功率路径。

Jason：这也是为什么“给模型加一段禁止攻击的提示词”不够。目标、工具、凭证和环境共同决定 agent 能做什么。模型可能理解规则，却在遇到冲突目标时优先完成结果；也可能因为评测只奖励成功率，而忽视副作用。企业需要把 agent 放进沙盒，限制网络访问，使用短期凭证，记录每一次工具调用，并为数据库、代码仓库和支付系统设置独立审批。高风险操作要有可撤销机制，长期任务要有自动过期时间，不能让一个启动后就一直运行的进程无限扩大权限。

Rory：攻击者不需要拥有最好的闭源模型。只要开放模型足够接近、推理成本足够低、工具能自动化，攻击规模就会增加。企业不能只依赖“先进能力还掌握在少数实验室”来获得安全感；它需要假设能力会下沉，并把防御周期从几年缩短到几个月。网络安全预算、身份管理、日志、漏洞修复和供应链审查会成为 AI 采用的前置条件，而不是上线之后再补的附属功能。

### 补充转写：Instinct 的权限、产品和投资边界

Jason：个人助理的难点不是把餐厅预订做成 demo，而是让系统在各种模糊指令下保持可预测。用户说“帮我安排一个重要晚餐”，可能意味着预订熟悉的餐厅，也可能意味着愿意花几千美元买稀缺座位。人类助理会追问，agent 可能把过去的偏好直接外推。只要操作涉及付款、删除邮件、修改日历、发送承诺或提交表单，系统就应该先给出行动计划，让用户确认，而不是只在后台留下一个不可逆结果。

Rory：另一个问题是 guardrails 之间的冲突。限制单次消费金额、优先满足重要活动、遵守时间窗口、照顾同行者和使用积分，都可能是合理规则；当这些规则冲突时，模型需要排序，排序就意味着它可能突破其中一条。最可靠的控制应该在信用卡、支付 provider、OAuth scope 和企业策略层执行。模型可以提出建议，但不能凭自然语言解释把硬额度变成软额度。

Instinct 能否成为独立的大公司，取决于三点。第一，用户是否愿意长期交出数据，而不是只在新鲜期试用；第二，系统是否能在不发生高成本错误的情况下扩大权限；第三，收入是来自高价订阅、平台抽成、设备入口，还是被 Apple、Google、Microsoft 等已有入口吸收。它可能是一个强趋势，却不必然是一个能支撑 25 亿美元早期估值的独立软件收入曲线。

### 补充转写：Cognition 与软件生产的市场容量

Rory：coding agent 的收入预测要把工具订阅、模型 token、企业合同和节省的人力成本分开。一个公司可能在 ARR 上增长很快，但客户仍在试验期，毛利率会被 inference 成本压制；另一家公司可能收入慢一点，却拥有更低的每任务成本、更强的代码执行可靠性和更高的留存。不要只把 agent 完成的代码行数当成生产力，关键是代码是否进入生产、是否减少缺陷、是否降低交付时间、是否让团队发布更多能产生收入的功能。

Jason：不过在最优秀的团队里，软件发布量确实已经发生数量级变化。以前一个季度只能完成一个大功能，现在同一团队可以并行推进更多功能和实验。客户购买的也不再只是一个“开发者 seat”，而是围绕代码库、issue、测试、部署和监控的一套持续工作流。Cognition 如果能在长时间运行 agent 上建立可靠性，就不需要在每一个指标上超过 Cursor；它只需要抓住一个足够大的细分，并把使用扩张成企业预算。

### 补充转写：Compound startup 的失败边界

Harry：compound 并不等于无边界扩张。一个公司如果同时增加十个模块，却没有共同的数据、客户和工作流，可能只是十个功能堆在一个菜单里。成功的 compound startup 应该让更多模块共享身份、权限、上下文和分发渠道，让客户感觉得到的是一个更完整的结果，而不是十次交叉销售。

Rory：资本会帮助赢家把产品表面积扩大，但也会放大错误。如果一家企业没有清晰的 ICP、没有强 CPO、没有稳定的基础设施，却因为市场热而拿到大量钱，更多 token 和更多工程师只会加速产品混乱。投资者应观察发布速度之外的指标，包括客户激活、跨模块采用、净收入留存、毛利率、support 成本和客户是否真的减少了系统数量。

Jason：在 agents 参与构建软件之后，竞争的单位从“谁有最好的单点功能”转向“谁能让 agent 快速发现、调用并组合更多功能”。这也是为什么拥有资本、人才和客户分发的公司会产生复合优势。小公司仍可以赢，但必须在一个 agent 真实需要的工作流里形成明显质量差异，而不是只复制一个有漂亮 demo 的表层产品。

### 补充转写：Salesforce、Clay、Linear 的共同验证框架

三位嘉宾把 Salesforce、Clay 和 Linear 放在同一个框架下比较。Salesforce 的问题是能否让 system of record 继续交付结果；Clay 的问题是 agentic GTM 是否会把 usage 转成收入；Linear 的问题是 agent 产生的 issue 和功能数量是否会让新的项目管理系统成为必需。三家公司都不应只按“有没有 AI 功能”判断，而要看 agents 是否真的把它们当作执行环境。

Salesforce 需要证明开放前端不会稀释数据和权限价值，outcome-based pricing 需要证明结果可以被公平计量，Intercom 等收购需要融入核心工作流。Clay 需要证明 agent 选择不是偶然偏好，而是 API、数据质量和执行结果共同形成的可持续 moat。Linear 需要证明 usage 增长不会只带来计算和支持成本，而能让更多团队把它作为 agent-first 开发的 system of record。

Rory：agent-friendly 也会改变企业软件的销售方式。人类采购可以被关系、品牌和演示影响，agent 则可能直接测试 API、权限、延迟、数据结构和任务完成率。供应商仍然需要品牌和客户成功，但产品的机器可读性会成为新的分发入口。一个产品若在 agent 的默认选择中胜出，可能获得远超过传统人工采购漏斗所能解释的使用量。

### 补充转写：Flock Safety 的治理要求

Flock 的案例说明，技术效果与社会许可不是同一个变量。摄像头可以提高破案和找回车辆的效率，但错误识别、无正当理由查询、跨地区数据共享和数据保存期限会决定公众是否接受它。公司不能只用犯罪预防的正面数字回应，而需要把每次查询的理由、案件编号、权限层级、审计记录、纠错流程和数据删除做成可检查的制度。

如果客户组织滥用软件，供应商不可能把所有责任都推给客户，因为公众会把产品设计和商业模式一起评价。Flock 是否能把治理机制做成产品能力，可能比新增摄像头数量更影响它的长期合同和估值。对这类涉及公共安全和个人隐私的公司，投资者要同时看收入增长、续约率、地方政策、诉讼、数据保护和客户合规，而不能只看技术采用率。

### 关键观点的归纳性对话

Harry：如果把本期内容压缩成几条可验证的判断，第一条是 compute 需求仍在强劲扩张，但最终不能只看 NVIDIA 的订单，还要看终端客户是否为 AI 结果付费。第二条是开放模型和 agent 生态会把更多 token 使用推向低成本、可组合的基础设施，硬件供应商因此会主动投资模型分发和开发者入口。第三条是 agent 会改变软件的买方和分发路径，Clay、Linear 这类产品的优势来自被 agent 真实调用，而不是只在网页上展示一个 agent 图标。

Rory：第四条是安全边界不能由模型自己决定。无论是 Hugging Face 的持续攻击、Instinct 的信用卡权限，还是 Flock 的警务数据，核心问题都是一个系统被赋予了目标和工具之后，谁来限制它、记录它、纠正它。越多企业把模型接入数据库、邮箱、支付和生产环境，身份、权限、审计、可逆性和人工确认就越接近产品的核心功能。

Jason：第五条是资本会继续追逐已经出现使用和收入的赢家，但投资者仍需要区分真正的 compounding 与估值叙事。Cognition 的 ARR、Clay 的 agent usage、Linear 的 issue 管理、Salesforce 的 outcome-based pricing，都必须通过留存、毛利、合同和客户结果验证。市场可以先给赢家资本，但资本不是证据本身。

Harry：因此，本期不是简单地给出一个“买入 AI”结论。NVIDIA 的供给约束、Salesforce 的现金流、Clay 和 Linear 的 agent-friendly 位置，分别属于基础设施、成熟软件和新分发机制；它们的验证周期、失败边界与估值方法不同。真正需要持续跟踪的是订单是否转成终端使用、usage 是否转成收入、agent 是否持续选择同一产品，以及安全和治理成本是否开始侵蚀商业模式。
