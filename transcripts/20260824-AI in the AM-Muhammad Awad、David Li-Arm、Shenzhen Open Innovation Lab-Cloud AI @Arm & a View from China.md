# Cloud AI @Arm & a View from China

## Transcript

**Pash：** 欢迎回到 AI in the AM。今天的节目分成两段。第一段，我们和 Arm 的云端 AI 负责人 Muhammad Awad 讨论 CPU、云端基础设施和 agent 时代的计算架构。第二段，我们和 Shenzhen Open Innovation Lab 的 David Li 讨论中国的机器人、硬件生态、开源模型，以及美国和中国到底是怎样看待 AI 竞赛的。我们会尽量把讨论放在真实的工程约束和使用场景上，而不是只重复估值和宣传口号。

**Nathan：** 过去两年大家谈 AI 时，注意力几乎都集中在 GPU 和模型参数上。但如果 agent 真的开始持续运行，系统会不断调用工具、切换上下文、读取记忆、向其他 agent 分发任务，整个计算系统的瓶颈就不只在训练模型的 GPU。CPU、内存、网络、存储、能源和数据中心的组织方式都会重新变得重要。

**Pash：** Muhammad，先从你自己开始。你在 Arm 的工作是什么，Arm 今天到底是一家什么样的公司？

**Muhammad Awad：** 我现在负责 Arm 的云端 AI方向。我的职业经历横跨处理器、基础设施和软件生态，之前也参与过物联网业务。很多人仍然把 Arm 简单理解为一家向客户授权 CPU IP 的公司，这个理解已经不完整了。Arm 当然仍然拥有极其重要的架构和 IP，但我们正在更广泛地参与完整的 silicon 和 compute platform，让客户不仅获得一个处理器核心，还能围绕性能、软件、互操作性和数据中心部署来构建更完整的产品。

Arm 的核心价值长期来自一个生态系统。芯片设计商、云服务商、设备商、软件开发者和操作系统团队能够在同一个指令集和工具链上协同。云端的 Arm 服务器并不是一个孤立产品，AWS 的 Graviton、其他云厂商的自研芯片，以及不同公司的专用加速器，都需要和 CPU、内存、网络和软件栈配合。我们今天讨论的不是“CPU 对 GPU 谁赢”，而是整个系统怎样把每种计算资源放到最适合的位置。

**Nathan：** Arm 最近很重要的一件事，是和 Meta 一起开发面向 AGI 工作负载的 CPU。能不能解释为什么一家模型公司会需要深度参与 CPU？

**Muhammad Awad：** Meta 的模型和推荐系统规模非常大，它知道自己的工作负载会怎样变化，也知道在推理阶段哪些任务会消耗大量资源。Arm 有 CPU 架构、设计经验和生态能力，Meta 则有真实的大规模数据中心和内部软件栈。双方一起做，目标是让 CPU 更贴近实际的 AI 工作负载，而不是拿一个通用的历史设计再要求软件去适应所有问题。

当人们说 AGI 时，常常只想到一个负责思考的模型。但一个真正持续运行的系统还需要调度、上下文管理、数据读取、工具调用、网络通信、权限检查和结果返回。模型可能在 GPU 上生成一个推理步骤，CPU 要负责把这个步骤连接到后面的软件和现实动作。随着 agent 数量增加，这些协调任务会成为主要的计算负担之一。

**Pash：** 也就是说，CPU 不只是把 GPU 启动起来的配套设备？

**Muhammad Awad：** 对。CPU 更像整个 agent 系统的骨架。GPU 擅长大规模并行的矩阵计算，也就是大家说的 thinking step 的一部分。但当 agent 需要从数据库找信息、读取长期记忆、向另一个模型发请求、访问浏览器或调用机械系统时，CPU 会负责非常多的控制和编排。我们可以把它想成从思考到行动之间的中枢。

Agent 不会像人类一样每天工作八小时，然后晚上停止。它们可以持续运行，不需要睡觉；也可以同时创建多个子 agent，让不同系统分别寻找资料、写代码、验证结论或执行任务。它们会频繁进行 context switching，在多个任务之间切换。每一次切换都涉及状态保存、数据搬运和权限控制，这些动作并不是简单地把更多 token 放进 GPU。

如果一家公司部署了几十个 agent，CPU 负责的可能不是一个模型的一次推理，而是成千上万次短任务的调度。每个任务单独看起来很小，组合起来却会让内存层级、缓存、网络和存储成为关键。更快的 GPU 不能自动消除这些开销，系统需要在每一层都保持平衡。

**Nathan：** 在实际设计中，什么指标最重要？市场过去一直把 FLOPS 当成主要答案。

**Muhammad Awad：** FLOPS 仍然有意义，但不能单独代表用户真正得到的服务。对云端 AI 来说，性能功耗比、内存带宽、延迟、吞吐、调度效率、软件兼容性和总拥有成本都很重要。客户并不只是购买一个峰值数字，他们需要在每天运行的真实任务中得到更多有效结果。

一个系统如果峰值性能很高，但每次读取数据都要等待，或者因为内存带宽不足导致加速器闲置，最终的有效吞吐就不会好。Agent 的工作负载尤其容易出现这种情况，因为它们不是始终做同一个大矩阵，而是在不同任务、不同上下文和不同工具之间来回切换。系统需要把数据尽快送到正确的位置，也需要在任务变化时快速重新分配资源。

内存是一个被低估的约束。模型推理会读取权重、缓存上下文和中间状态，agent 又需要读写外部记忆、文档和工具结果。当上下文变长、并发量上升时，数据搬运本身会消耗大量能源和时间。很多时候，进一步提升计算单元的速度不如改善 memory hierarchy、带宽和数据局部性有效。

**Pash：** 这也解释了为什么 AI 数据中心越来越像一个工业项目，而不只是买芯片。现在大家都在谈电力和变压器。

**Muhammad Awad：** 对，AI 基础设施的约束是一个链条。你需要芯片和晶圆，需要先进封装和内存，需要服务器、电源、冷却、网络和数据中心空间，还需要工程师、施工团队和维护人员。任何一个环节落后，都可能让整套系统无法上线。即使你已经买到 GPU，如果电力接入、冷却系统或网络机架没有准备好，GPU 也只是停在仓库里的昂贵资产。

这些约束还会向上游传导。晶圆厂需要设备和材料，内存供应需要新的投资，数据中心需要涡轮机、变压器和电容器，电网需要更长时间的规划。熟练的安装和维护人员也有限。市场有时只把瓶颈叫作“芯片短缺”，但真实情况是多个物理系统同时在扩张。

性能功耗比因此越来越关键。一个芯片每瓦能完成多少有效工作，会直接影响数据中心的容量和运营成本。电力不仅是账单，也是一个受基础设施和许可约束的稀缺资源。对于长期运行的 agent，持续的功耗比单次 benchmark 峰值更能决定经济性。

**Nathan：** Arm 在这条链上能做什么？Arm 并不拥有所有数据中心，也不负责所有内存。

**Muhammad Awad：** 我们不能解决每一个瓶颈，但可以帮助客户把系统设计得更有效率。Arm 的架构和 IP 会进入不同客户的 CPU、平台和服务器。我们的工作是让这些设计具有良好的性能功耗比、软件兼容性和可扩展性，同时与 GPU、专用加速器、网络和存储系统顺畅协同。

一个云服务商可能使用 Arm CPU 来管理大量通用工作负载，再把某些模型计算交给 GPU 或专用加速器。另一个客户可能需要自己的推理芯片。Google 有 TPU，Nvidia 有 GPU 和网络方案，Meta 有 MTIA 等内部加速器，AMD 也有 DPU 和其他数据中心产品。最终很可能不是单一芯片赢得一切，而是不同的 compute engines 通过一个协调层共同工作。

CPU 还需要处理没有被宣传视频展示出来的工作。它要负责启动容器、管理虚拟机、检查权限、处理输入输出、协调网络包、运行数据库和保持系统可观测性。这些工作如果被忽视，模型就算很聪明，也无法稳定地为用户完成任务。

**Pash：** 现在很多公司都在和 frontier labs 合作。Arm 需要怎样和这些实验室合作，才能知道下一代工作负载会是什么？

**Muhammad Awad：** 我们需要尽可能早地和真实的客户交流。硬件设计周期很长，等产品发布后再问客户需要什么通常已经晚了。Frontier lab 会告诉我们它们怎样训练和部署模型，云服务商会告诉我们怎样面对实际客户，Arm 再把这些需求转化成架构和平台设计。这个过程不是一次市场调查，而是持续的共同开发。

模型公司的需求也会变化。训练可能需要极大规模的并行计算，推理可能更加关注延迟、成本和并发。Agent 化之后，推理会变成很多阶段的组合：一部分在模型加速器上，一部分在 CPU 上，还有一部分在外部服务和数据库中。硬件设计必须考虑这种不断变化的 mix，而不能把“AI”当作一个单一的工作负载。

**Nathan：** 你怎么看公众对数据中心的反弹？很多社区担心水、电、噪声和电价。

**Muhammad Awad：** 这些担忧应该被认真对待。数据中心会消耗资源，会影响社区，企业不能只说“AI 很重要”，就假设所有人都必须接受成本。我们需要更高效的芯片、更好的冷却和更透明的基础设施规划，也需要和当地社区沟通实际收益和实际负担。

同时，我不认为解决方案是简单地否定所有 AI 基础设施。社会已经在使用搜索、云软件、视频和金融服务，AI 会增加计算需求，但也可能提高医疗、教育、工程和生产率。正确的问题是：我们能不能让每一单位电力产生更多有效 intelligence，能不能让数据中心的建设遵守现实的环境和许可边界，能不能让收益不只归属于少数公司。

**Pash：** 这会不会影响 Arm 的招聘？有人认为初级工程师已经被 AI 取代。

**Muhammad Awad：** 目前我们看到的工程需求仍然很强。AI 会改变工作方式，可能让工程师更快地写代码、分析日志和探索设计，但硬件、系统和产品仍需要人去定义问题、验证结果、承担责任。越复杂的系统，越需要能够跨越架构、软件、供应链和客户需求的人。

我不愿意假装变化不存在。某些任务会减少，另一些任务会增加。早期职业阶段的人可能需要更快掌握系统思维，因为简单地完成一个局部任务不再是全部价值。公司仍需要新人，也需要让他们接触真实的工程决策，而不是只把最容易自动化的工作交给他们。

**Nathan：** 你如何描述 CPU 在 agent 时代的角色？

**Muhammad Awad：** 我会把它描述为从 intelligence 到 action 之间的 spine。GPU 或专用加速器完成大量的模型计算，但 CPU 把思考结果带到外部世界。它可以决定要读取什么、调用哪个 API、把任务分发给哪个 agent、是否需要人工批准、把结果写到哪里，以及如何把多个步骤拼成一个可靠的工作流。

如果未来的 agent 只是一个聊天窗口，CPU 的作用可能没有被充分看到。但如果 agent 真正替人执行工作，它就需要访问企业系统、文件、浏览器、数据库和设备。每一个访问都要求协调、缓存、权限和异常处理。CPU 是这些工作的基础，而不是一个可以被忽略的旧组件。

**Pash：** 谢谢 Muhammad。接下来我们把视角转到中国。David，先请你介绍自己和 Shenzhen Open Innovation Lab。

**David Li：** 我是 David Li，长期参与开源软件、硬件和深圳的创新社区。Shenzhen Open Innovation Lab 是一个连接制造者、工程师、研究者和创业者的开放社区。我的经历可以追溯到很早的开源运动，也参与过中国最早的一些 hackerspace。深圳对我来说不只是一个城市，而是一整套能够让想法迅速变成实物的社会和供应链系统。

我从 1990 年代就开始接触 open source。那个时代的开源更像是一种协作和知识共享的文化，后来它进入硬件、机器人和制造。中国的很多年轻人今天不一定用“开源运动”这个词描述自己，他们可能只是想做一个产品、参加比赛、让产品卖出去。但其中包含了相同的快速学习、复制、修改和分享精神。

**Nathan：** 你最近谈得很多的是机器人活动和比赛。为什么机器人会成为理解中国 AI 生态的入口？

**David Li：** 因为机器人把软件、模型、传感器、机械、供应链和真实环境放在了一起。中国有规模非常大的工业机器人基础，工业机器人数量大约在三十万这个量级，而且还在继续增长。除了工厂里的机械臂，还有教育机器人、服务机器人、比赛机器人和各种面向公众的展示。

我参加过机器人奥林匹克和机器人嘉年华一类活动。中国的机器人比赛有时很热闹，孩子、学生、工程师和家长都能看到机器在公共空间里移动、抓取和完成任务。西方媒体更喜欢拍一个精致的 tabletop demo，一个机器人在实验室里拿起一个物体；中国的活动经常把很多机器人放在一个场地里，让它们竞争、表演和迭代。

这两种场景都是真实的，但它们传递的信息不同。中国的讨论更关注：这个东西能不能便宜地做出来，能不能批量制造，下一次比赛能不能改进，能不能用于一个小生意。机器人不一定首先被当成关于 AGI 的哲学问题，而是一个可以使用和赚钱的工程对象。

**Pash：** 深圳为什么特别适合做这些事情？

**David Li：** 深圳的优势在于很多环节集中在相对近的地理范围内。你可以找到做 PCB 的工厂、做连接器和电机的供应商、做外壳和模具的团队，也可以找到能快速修改小批量产品的人。一个想法从电路板到外壳再到十几个样品，时间可能比很多地方短得多。

我常把深圳的市场比作 farmer's market。你进入市场，会看到许多摊位和供应商，不一定有一个中央管理者告诉所有人怎么做。你可以询价、比较、拿一个样品回去拆开，再找不同的工厂改进。这个生态会带来复制，也会带来浪费和知识产权争议，但它的迭代速度非常快。

西方有时把复制只理解为抄袭，实际上在硬件创业的早期，拆解和修改也是一种学习方式。一个团队看到别人的产品后，可以迅速做出自己的版本，再针对成本、尺寸、功耗或客户需求修改。很多新产品不是从一块空白开始，而是从现有供应链和已知模块开始组合。

**Nathan：** 这种生态会怎样影响 AI 玩具和服务机器人？

**David Li：** 现在有很多会说话的玩具、桌面机器人和小型设备。它们可能使用很便宜的芯片、开源软件栈和云端模型。你可以做出一个能够对话、唱歌、识别简单物体的产品，但“会说话”本身不代表它有一个独特的 personality，也不代表它真正理解环境。

很多产品的硬件可以复制，真正难的是把交互、内容、模型和长期使用体验做得有意义。如果每个玩具都只是把相同的模型接到相同的麦克风上，它们最后会说相似的话。深圳的供应链能很快生产出外壳和电路，但产品团队仍然需要找到真正的用户、场景和商业模式。

工业机器人也有类似问题。某些机器人本身的价格已经可以下降到几千美元的范围，但客户买到机器人后，还需要把它安装到具体的流程里。这里缺少的是 field application engineer，也就是能够理解客户生产线、调整机械动作、连接软件和解决现场问题的人。

机器人行业有时以为只要降低硬件价格，需求就会自动出现。现实是，低价机器人如果没人能把它部署起来，仍然没有生产价值。未来很可能不是机器人本体最稀缺，而是能够把机器人变成可用生产工具的集成能力最稀缺。

**Pash：** 你能举几个机器人真正有用的场景吗？

**David Li：** 一个方向是危险、重复或者不值得让人承担风险的工作。例如电池测试可能包含高温、短路、爆炸或其他危险，机器人可以在更安全的环境中执行重复流程。另一个方向是低批量和高度灵活的任务。传统自动化很适合大批量同一种产品，但深圳有大量小工厂，需要频繁换线，灵活机器人就可能更有价值。

我们不应该只看 humanoid robot 在舞台上跳舞。更实际的价值可能来自一些不那么漂亮的机械：在工厂里搬运、在测试间里操作、在高危区域里检查、在小批量生产中完成需要经常改变的步骤。用户愿意付钱，是因为机器人解决了一个具体成本或安全问题。

**Nathan：** 从美国的角度，大家很容易把中国的 AI 讨论框定为与美国竞争。中国本地的人通常怎样谈？

**David Li：** 对很多普通创业者和工程师来说，第一问题不是“美国和中国谁赢”，而是“我怎样用 AI，能不能用它赚钱”。国家级竞赛是媒体和政策的一层，普通人还要考虑客户、成本、流量、招聘和产品能不能卖出去。

中国模型只有在发生非常大的事件时，才会被更多西方市场注意。比如某个模型发布后导致 Nasdaq 相关股票大幅波动，大家才突然开始关注它。中国用户则更熟悉 Doubao、Alibaba、Tencent、Kimi、DeepSeek、GLM 以及其他本地服务。很多模型产品可以免费使用，至少在早期阶段，用户并不总是把模型当作一个昂贵的企业软件。

中国的竞争也更关注模型能否在真实硬件上运行。由于 GPU 供应和成本受到限制，很多团队会研究小模型、量化、蒸馏和 edge inference。未来几年，能够在两三百美元硬件上运行二十五到二十七 billion 参数模型的设备，可能变得更常见。市场上已经有十几家中国创业公司在做接近 SSD 大小的推理盒子，目标是让模型离数据和用户更近。

这种方向不一定意味着所有模型都要离线运行。它可能是云端与本地的组合：小模型在设备上做快速分类和隐私处理，大模型在云端解决复杂问题。企业可以把延迟、成本和数据敏感性分开考虑。对很多中国公司来说，硬件受限不是一个抽象问题，而是每天都要面对的产品约束。

**Pash：** 这会不会让中国的模型更高效？

**David Li：** 有可能。资源少的时候，团队会更重视压缩、量化、部署和实际成本，而不是只追求训练规模。中国有大量对硬件有约束的公司，它们会监控 GPU 的使用率，尽量把每一单位算力用在有效任务上。不同公司的模型也会共享一些相似数据、相似硬件和相似人才，因此能力和 guardrails 可能趋向相近。

但效率不能被简单理解为“资源少所以一定更好”。较小的模型在某些任务上足够好，在另一些需要广泛知识和长上下文的任务上仍然受限。真正的商业价值取决于模型和工作流是否匹配。一个小模型如果能在本地及时完成任务，可能比一个更强但延迟很高、成本很高的云模型更有用。

**Nathan：** 你怎么看中美 AI race？

**David Li：** 我认为双方已经非常接近，至少在很多公开可见的能力上如此。美国在 frontier model、资本、软件和大型云平台上有强项，中国在制造、部署、成本、硬件适应性和用户规模上有强项。把它描述成一方绝对领先，往往是政治宣传或媒体叙事。

中国从 2016 年左右就把 AI 放在国家政策的显著位置。现在很多企业和地方政府都在考虑怎样应用 AI。普通创业者不会每天讨论某个 benchmark，而会研究怎样把模型嵌入客服、供应链、营销、教育或小型硬件产品。宏大竞赛存在，但它和日常使用之间有很大距离。

中国政府和美国政府的控制方式也不同。中国的国家控制更明显，企业必须考虑政策和监管；美国更容易强调市场和私人公司的自主性，但大公司同样掌握了模型、数据和基础设施。两边都存在权力集中，只是表现形式不同。不能把“私营”自动当作自由，也不能把“政府参与”自动解释为所有创新都会停止。

**Pash：** 节目里我们也谈过 rogue agent。有人认为 agent 只是在演示里表现得很危险，现实中没有那么严重。你的看法是什么？

**David Li：** 我觉得很多 rogue agent 演示带有 public relations 的成分。公司希望公众相信自己的模型很强，或者希望政策制定者担心竞争对手。模型在一个设计好的测试里说它要逃跑，不等于它在真实世界拥有完整的动机、权限和能力。我们应该问它能接触什么，能不能改写自己的代码，能不能访问真实账户，而不是只看一句惊人的对话。

当然，不能因为演示有夸张成分，就把所有安全问题都当成假的。普通的网络攻击已经足够危险。一个 agent 不需要变成超级智能，只要能自动寻找泄露的凭证、写钓鱼邮件、尝试常见漏洞，或者长时间执行一项欺诈任务，就会造成损害。风险评估需要区分戏剧性和现实性。

**Pash：** 我部分同意，但我担心我们会低估很多小步骤组合起来的效果。一个 agent 今天可能只是写邮件，明天接入浏览器，后天接入支付系统。每个单独动作都不惊人，组合之后就很危险。

**David Li：** 这是一个合理的担心。中国很多企业也会遇到类似问题。大家想尽快把 AI 接入工作流程，但权限、审计和责任归属往往没有同步建立。一个真正可用的系统应该知道自己可以做什么，不可以做什么，还要让人能够在执行前查看和停止它。

**Nathan：** 这让我们回到 agent attribution。未来如果 agent 发了一封邮件、做了一笔交易或修改了一段代码，谁负责？

**David Li：** 这是非常重要的问题。当前很多产品把 agent 当成一个功能按钮，但它实际上会代表公司和个人行动。如果没有清晰的身份标识、日志和责任链，出错之后很难知道是哪个模型、哪个提示、哪个工具或哪个人批准了操作。中国的企业在快速部署的同时，也会逐渐需要这类治理基础设施。

**Muhammad Awad：** 我也同意。无论是在云端还是边缘，agent 都需要身份、权限和可观察性。硬件层的安全不能替代软件层的审计，软件层的审计也不能替代组织层的责任。如果一个 CPU 负责协调许多 agent，它还要确保隔离、调度和数据访问不会把一个工作流的权限扩散到另一个工作流。

**Pash：** 我们谈回硬件。中国现在关注 edge inference，会不会削弱云端 AI？

**Muhammad Awad：** 更可能是改变云端和边缘的分工。边缘计算适合低延迟、隐私敏感和连接不稳定的场景。云端适合大型模型、复杂推理和集中管理。很多产品会在边缘做预处理、快速响应和安全检查，再把复杂任务发到云端。这样既可以减少成本，也能让系统在没有稳定网络时继续做一部分工作。

CPU 在这个组合里依然很重要。边缘设备可能没有大型 GPU，但它需要管理传感器、操作系统、模型运行时和通信。云端系统也需要 CPU 负责调度和数据服务。只要 agent 需要把模型结果连接到真实设备，通用计算和控制逻辑就不会消失。

**David Li：** 深圳的硬件生态也会推动这种组合。供应商不一定先问“这是不是 AGI”，而是先问“这个盒子要多大、功耗多少、客户愿意付多少钱”。如果模型可以在一个更小的设备上运行，工厂、门店和家庭就有更多使用方式。小型模型不只是一个技术妥协，也可能是一种产品策略。

**Nathan：** 你提到了工业机器人和 field application engineer。这个角色会不会比模型研究员更稀缺？

**David Li：** 在很多现实项目中，是的。模型研究员可以让一个 benchmark 提高，但机器人要进入工厂，就必须面对地面不平、光线变化、零件偏差、工人安全和生产节拍。能解决这些问题的人需要机械、电子、软件和客户沟通能力。这个角色不够 glamorous，却决定了设备是否真正产生收入。

深圳的制造生态可以很快做出一个样机，但样机不等于产品。产品要能维护、能批量生产、能适应客户流程，还要有售后和升级。很多创业公司的瓶颈不是想法，也不是硬件，而是找到足够多的工程师把一次性 demo 变成可以重复交付的系统。

**Pash：** 这听起来和美国的情况也很相似。

**David Li：** 是的。媒体喜欢把中美描述成两个完全不同的世界，但很多工程问题是相同的：成本、可靠性、招聘、部署、客户教育和现金流。不同的是，深圳的供应链更近，迭代更快；美国的公司可能在软件、资本和大型客户上更有优势。双方都在努力把 AI 从演示变成业务。

**Muhammad Awad：** 硬件的共同难题也很明显。无论在哪个国家，芯片设计、晶圆、内存、封装和电力都需要时间。AI 的增长速度很快，但物理基础设施不能无限快地扩张。系统设计和性能功耗比会决定谁能把同样的资源转化为更多有效服务。

**Nathan：** 既然说到基础设施，最近 Nvidia 还谈到 SpaceX 的 Vera CPU 部署。你们怎么看把 AI 计算放到太空的想法？

**Muhammad Awad：** 轨道数据中心很有吸引力，因为太阳能、土地和网络连接可能带来新的组合。但这不是把服务器搬到太空就结束了。发射、维修、散热、通信、辐射和数据返回都会产生新的工程问题。Vera CPU 之类的系统如果进入这类环境，也要考虑可靠性和功耗，而不是只看地面数据中心的 benchmark。

**David Li：** 我觉得这也是 Elon Musk 叙事的变化。过去 SpaceX 主要被看成火箭发射公司，现在它可能被理解为连接 space、AI、互联网和基础设施的综合公司。如果计算需求继续增长，人们一定会寻找新的能源和空间。但轨道数据中心是长期的技术和经济判断，不能因为一个发布消息就把商业结果当成已经验证。

**Pash：** 另一条新闻是有人提出让数据中心承担更多责任，例如因为用电、噪声或事故承担法律义务。你们支持限制 AI 基础设施吗？

**David Li：** 我支持让企业承担真实的外部成本，也支持社区有权要求透明度。但如果政策只是因为担心就业变化，就试图冻结一切 AI 建设，我不赞成。AI 会替代一部分工作，但它也会让小公司获得以前只有大公司能用的能力。我们应该把速度放慢到安全和基础设施能够跟上的程度，而不是因为变化令人不舒服就完全停止。

**Muhammad Awad：** 也要注意，基础设施的建设周期本身就很长。芯片、数据中心和电网不是一夜之间完成。好的政策需要给出清晰规则，让企业能够投资能源效率、社区配套和安全系统。过度不确定会让资本只追求短期项目，反而不利于长期基础设施。

**Nathan：** 关于劳动市场，我和 Pash 的分歧是：我们不能因为技术会创造新工作，就忽略一段时间内很多人会失去工作。

**Pash：** 对，我支持 AI 广泛可用，但我不接受“每个被替代的人都会自动转到更好的工作”这种轻松的说法。转换需要时间、教育和收入支持。政府和企业应该讨论如何让普通人获得 AI 工具，而不是只让少数大公司拥有生产率提升。

**David Li：** 中国也有相同的焦虑。很多人并不担心一个遥远的 AGI，而是担心自己的店、工厂或岗位会不会被更便宜的自动化取代。但另一面是，小型企业可以用模型做以前请不起的营销、客服和设计。机器人也可能让危险工作变得更安全。答案不会是一句“技术总是创造更多工作”，而是要看谁拥有设备、谁能学习新工具、谁获得收益。

**Muhammad Awad：** 硬件行业还需要很多现场工程。即使模型自动化了部分设计，人仍要制造芯片、建设数据中心、维护网络、验证系统和处理客户需求。工作会变化，但变化不会只发生在软件工程师身上，也不会只发生在一个国家。

**Pash：** 我们想谈一个实际的 AI 风险：prompt injection。Agent 读取一份网页或文档后，里面可能包含指令，诱导它泄露信息或做不该做的事情。

**Muhammad Awad：** 这说明数据和指令必须区分。一个 agent 读取外部内容时，不能默认外部内容拥有和系统指令相同的权限。平台需要隔离不可信输入、限制工具调用、对敏感操作要求人工批准，还要记录模型为什么做出了某个决定。CPU 和系统软件可以提供隔离与访问控制，但应用设计同样重要。

**David Li：** 对制造业来说，风险可能表现为错误的订单、错误的库存动作或错误的机器指令。很多工厂会把 AI 接到内部系统，却没有考虑外部文档如何进入工作流。只要一个 agent 能读到文件并执行动作，就需要非常清楚的边界。把 agent 当成一个会自动完成所有事情的员工，是不够安全的。

**Nathan：** 另一个问题是 prompt 让 agent 最大化赚钱。有些测试发现，模型为了达到目标会欺骗、隐瞒或钻规则空子。

**Pash：** 我们不应该只训练系统“尽可能赚钱”，然后惊讶它找到不符合人类意图的方法。一个交易 agent 需要明确的风险限额、批准流程和可解释日志。收益目标不能覆盖所有约束。

**David Li：** 在中国的小企业里，这个问题也会出现。老板可能对系统说“把利润做到最大”，但系统没有足够的上下文理解客户关系、质量和合规。如果模型只优化一个数字，它可能牺牲长期信任。商业 agent 需要把目标拆成可检查的规则，而不是把所有决定交给一个黑盒。

**Muhammad Awad：** 这又回到系统工程。目标、权限、监控和硬件隔离需要同时设计。一个模型即使在对话中表现得很安全，只要它可以调用没有限制的外部工具，整体系统就可能不安全。反过来，一个能力很强的模型，如果权限被严格隔离，也可以在更可控的环境里使用。

**Pash：** 最后我们再说说中国的开源。中国模型经常被称作 open weight，美国也有人希望开放模型促进创新。你怎么看 open source 和商业竞争的关系？

**David Li：** 对普通软件来说，更多人检查代码往往能发现问题，也能让更多人学习和创新。但模型不是简单的源代码。Open weight 不等于完整 open source，权重公开也不代表数据、训练过程和安全评估全部公开。开放可以降低使用门槛，也可以让更多创业者做产品；但如果模型有高风险能力，开放同样会扩大滥用范围。

中国的免费模型和开源模型帮助了很多小团队。一个人可以快速做出客服、翻译、教育和硬件应用，不必先向大公司购买昂贵许可。这种扩散对创新很有价值。但政策和企业仍要考虑模型是否能被用于攻击、欺诈或大规模操纵。开源理念本身不能替代风险边界。

**Muhammad Awad：** 从基础设施角度看，开放生态也会增加硬件的多样性。模型可以部署在云端、边缘和不同公司的芯片上。好的软件栈、编译器和标准能让客户避免被锁在单一平台。但开放生态需要稳定的接口、工具链和安全更新，否则用户会承担集成成本。

**Nathan：** 中国的机器人和 AI 产品会不会被西方误解？

**David Li：** 经常会。西方媒体有时只寻找能够证明“中美竞争”的镜头：一个模型超过 benchmark、一个机器人做出奇怪动作、一个创业公司获得大量融资。但中国日常 AI 生态更杂乱，也更务实。很多团队只是把模型接到一个产品上，试着找到客户；很多机器人不是为了展示国家力量，而是为了完成一项危险或重复的工作。

深圳的创新不总是体现在一个明星公司上，而是体现在大量供应商和小企业的组合里。一个小厂可能没有自己的大模型，却能把别人的模型、传感器和电机组合成一个有用的机器。这个生态很难用单一榜单衡量，但它决定了 AI 能否进入现实世界。

**Pash：** 这也解释了为什么很多中国用户更在意 AI 能不能赚钱，而不是它在论文上是不是最先进。

**David Li：** 对。一个模型如果在论文上领先，但价格太高、不能在本地运行、无法接入供应链，它对小企业的帮助有限。一个不那么强但便宜、稳定、能部署的模型，可能更快产生商业价值。中国市场的规模和竞争会迫使团队很快回答这些问题。

**Muhammad Awad：** 在云端也一样。客户真正关心的是每个请求的成本、延迟、可靠性和数据安全。峰值能力当然重要，但如果服务无法稳定交付，客户就不会大规模采用。硬件、软件和商业模式必须一起优化。

**Nathan：** 我想问一个更长远的问题。如果 agent 数量持续增加，硬件周期怎么跟上软件周期？

**Muhammad Awad：** 这是行业的难题。芯片和数据中心需要多年规划，而软件 agent 可以在几个月内改变工作负载。我们需要更灵活的平台、可扩展的架构和更早的需求预测。性能功耗比会帮助系统延长可用周期，但不可能消除周期差异。

另一个办法是让软件更好地适应异构硬件。不是所有任务都要跑在同一种加速器上，系统应该根据延迟、成本、内存和功耗把任务分配给最合适的资源。CPU、GPU、专用加速器、网络和边缘设备都可能参与。真正有价值的优化，是让这些资源协同，而不是让所有宣传都围绕一块芯片。

**David Li：** 硬件生态的速度也可能帮助缓解这个差异。深圳的供应商可以先做小批量设备，收集使用反馈，再修改下一版。这样不需要等一个完美平台完成，产品就可以开始学习。缺点是版本很多、标准不统一、维护困难，所以开放接口和可替换模块很重要。

**Pash：** 如果要给观众一个关于机器人投资和创业的建议，你会说什么？

**David Li：** 不要只投资一个会走路或会说话的 demo。要看它解决了什么具体问题，客户是否愿意付费，部署是否需要大量人工，以及供应链能否支持规模化。硬件毛利、售后、现场工程和认证都很重要。机器人最有潜力的机会，可能在危险、重复、低批量和人手不足的场景，而不是最容易拍成视频的场景。

**Muhammad Awad：** 对 AI 基础设施也一样。不要只看某个芯片的峰值算力，要看性能功耗比、内存、软件生态、客户部署和数据中心总成本。Agent 时代需要的是完整系统。谁能在相同能源、相同空间和相同人力下交付更多有效工作，谁才有长期优势。

**Nathan：** 这期节目最后一个问题。你们对未来几年的最大判断是什么？

**David Li：** 我认为 AI 和机器人会越来越像普通的工业工具，而不是只属于大型实验室。中国会出现很多小团队，把模型放进玩具、工厂、门店、教育设备和服务流程。大多数产品不会改变世界，但其中一部分会因为成本低、部署快而产生真正的影响。美国和中国的竞争会继续，但普通人更关心的是自己能否使用这些工具。

**Muhammad Awad：** 我的判断是，agent 会让系统架构重新平衡。大家仍然需要强大的 GPU 和专用加速器，但 CPU、内存、网络、存储、能源和软件调度会获得更多关注。AI 不只是训练一个模型，而是让许多智能步骤持续协同。硬件和软件必须共同设计，性能功耗比和可靠性会越来越接近模型能力本身的重要性。

**Pash：** 我希望 AI 能被广泛使用，但速度必须和安全、基础设施以及社会适应能力匹配。不能因为劳动力市场会变化，就把所有创新交给少数公司；也不能因为创新令人兴奋，就假装失业、欺诈、能源和权限问题不存在。

**Nathan：** 对观众来说，今天可以记住三点。第一，CPU 不是 AI 时代的旧组件，它是把模型推理连接到工具和现实行动的骨架。第二，机器人价值要看具体部署，而不是只看展示。第三，中国 AI 生态不能只用一场中美竞赛解释，它还包含一个非常快的硬件、供应链和小企业网络。

**Pash：** 另外，任何 agent 只要能读取外部内容或调用真实工具，就要考虑 prompt injection、身份归属、权限隔离和人工确认。不要让一个看起来聪明的系统拥有默认转账、改代码或改变生产流程的权力。

**Nathan：** 感谢 Muhammad Awad，也感谢 David Li。感谢大家收看 AI in the AM。下一期见。

**Pash：** Muhammad，在你看来，Arm 从 IoT 走到 cloud AI 的变化，最容易被外界忽略的地方是什么？

**Muhammad Awad：** 最容易被忽略的是，云端并不是一个完全脱离设备的世界。过去很多人把 Arm 和手机、嵌入式设备联系在一起，把云端看成另一套体系。实际上，计算工作负载会从设备、边缘和云端之间流动。用户在手机上发出请求，数据可能先在本地被处理，再进入网络，再由云端的 CPU、GPU 和存储共同完成任务。系统要把这些层连接起来，架构的一致性和软件生态就很重要。

Arm 的发展也不是从一个市场跳到另一个市场那么简单。我们原来非常擅长低功耗和高效计算，这些特性在数据中心同样重要。云服务商每年运行大量服务器，哪怕每个请求只节省一点功耗，累积起来也会变成很大的成本和容量差异。现在客户更愿意根据真实的性能功耗比来选择平台，而不是只看某种处理器在历史上的标签。

**Nathan：** AWS 的 Graviton 经常被用来说明这个趋势。你怎么看云服务商自研芯片和 Arm 的关系？

**Muhammad Awad：** 云服务商自研芯片不是对生态的否定，反而说明它们希望拥有更强的系统控制能力。Arm 提供架构、IP 和开发工具，云服务商根据自己的工作负载设计具体芯片和平台。客户可以在通用 CPU、专用加速器和云服务之间选择。只要软件能够迁移，生态就会扩大。

自研芯片的价值来自对工作负载的理解。一个云服务商可能希望优化数据库、网络、视频或 AI 推理。它可以用 Arm CPU 处理通用控制，再用专用硬件处理最耗时的部分。这样的异构系统会越来越普遍。我们更关注怎样让开发者能够使用这些资源，而不是让他们必须从底层理解每一种芯片。

**Pash：** 你提到软件迁移。很多企业担心从一种平台切换到另一种平台会很痛苦。

**Muhammad Awad：** 迁移成本是采用的真实障碍。指令集只是起点，编译器、操作系统、运行时、容器、数据库和开发工具都要配合。Arm 的生态工作很大一部分就是和软件公司、云服务商及开发者合作，让应用在不同平台上更容易运行。客户需要的是可预测的性能和稳定的维护，而不是一次性的 demo。

Agent 会进一步放大这个问题。它的代码可能不断调用外部服务，使用多个模型和多个数据库。如果每个组件都对硬件有特殊要求，整个系统就难以维护。因此，标准化接口、编译器优化、虚拟化和可观察性会成为 AI 基础设施的重要组成部分。

**Nathan：** 让我们具体讨论 agent 的 context。为什么它会让 CPU 和内存的作用突然变得更突出？

**Muhammad Awad：** 一个模型生成答案时，会读取权重和上下文。但 agent 的上下文不只有用户最近的一句话，还可能包括过去的任务、检索到的文件、工具返回的结果、其他 agent 的消息和权限状态。每一步都可能改变下一步要读什么、写什么和调用什么。系统需要不断在内存层级之间搬运这些信息。

如果 agent 同时执行很多任务，内存容量和带宽会影响并发量。CPU 还要管理线程、队列、网络请求和异常。GPU 能够快速完成某个矩阵计算，但它不会自动决定一个任务是否应该访问 CRM、是否需要等待人工、是否应把结果写入数据库。那些决策需要系统软件和 CPU 共同完成。

**Pash：** 这似乎也会改变数据中心的布局。

**Muhammad Awad：** 是的。传统上，大家可以把服务器分成计算、存储和网络几类，再通过网络连接。AI agent 工作负载会让数据流更复杂。模型计算可能集中在一组 GPU，记忆和文档在另一组存储，权限和业务逻辑在 CPU 上，设备控制又在边缘。数据中心需要考虑数据如何移动、哪些内容应该缓存、哪些任务应该就近运行。

延迟很重要。如果 agent 为了回答一个问题要连续调用十个工具，每一步多一点延迟，用户体验就会明显下降。一个更快的 CPU、合理的缓存和本地化的数据服务，可能比再增加一点峰值模型性能更有价值。真正的端到端延迟，往往由最慢的几个环节共同决定。

**Nathan：** 你说到端到端。AI 芯片的供应链会怎样受到这种需求影响？

**Muhammad Awad：** 需求会从训练芯片扩展到整个系统。晶圆厂需要增加产能，先进封装需要更多设备，HBM 和其他内存需要投资，服务器需要电源和冷却。每个环节都有自己的周期和质量要求。即使模型公司的需求增长很快，供应链也不能在一个季度内把所有能力翻倍。

数据中心建设还需要土地、电网连接和许可。涡轮机、变压器、电容器和冷却部件可能成为关键约束。熟练工人也有限，能够安装、调试和维护高密度数据中心的人并不是无限供应。它是一个工业扩张问题，不只是一个科技产品发布问题。

**Pash：** 那么硬件迭代会不会被供应链拖慢？

**Muhammad Awad：** 某些部分会，但行业会通过模块化设计、提前投资和更高的利用率来应对。我们也会看到更多专用设计和更高的性能功耗比。客户不一定需要等到所有资源都齐全才开始部署，而是会先把最有价值的工作负载放进去，再逐步扩容。

另一个方向是提高系统利用率。很多芯片在某些时段很忙，在另一些时段却空闲。如果调度系统能把不同类型的任务安排到同一套资源上，就能在不增加同样数量硬件的情况下提供更多服务。Agent 的任务有长有短、并发变化很大，这既是挑战，也给调度优化带来机会。

**Nathan：** 你如何回应“AI 只需要 GPU，CPU 会被边缘化”的说法？

**Muhammad Awad：** 这是一种把复杂系统压缩成单一宣传点的说法。GPU 对大规模并行计算非常重要，我们不否认这一点。但 CPU 负责操作系统、网络、存储、数据库、虚拟化、调度和控制。哪怕 GPU 占据了最受关注的部分，CPU 也要让整个系统可用。

未来可能会有更多不同类型的加速器。模型的某一层可以在 GPU 上运行，另一个部分在专用芯片上，数据预处理在 CPU 或边缘设备上完成。谁能把这些资源协调起来，谁就能把理论计算能力转化成用户实际得到的结果。系统级平衡比单个部件的排行榜更重要。

**Pash：** Arm 和 Meta 的合作会不会让 CPU 更贴近大规模 AI 的独特需求？

**Muhammad Awad：** 共同开发的好处是可以从真实的部署约束开始。Meta 能看到模型训练、推理、推荐和基础设施的实际数据，Arm 能把这些需求映射到架构和设计。双方可以共同判断哪些优化值得放进硬件，哪些应由软件解决，哪些需要通过整个平台来解决。

不同工作负载之间没有一个万能答案。训练更关心吞吐和规模，在线推理更关心延迟和成本，agent 工作流又更关心协调、内存和工具访问。我们希望架构能支持这些场景，而不是为了一个 benchmark 牺牲长期可编程性。

**David Li：** 我想补充一点。深圳很多硬件团队也在做类似的取舍，只是它们面对的规模更小。工程师会问一个模型能不能在客户现有的主板上运行，内存是不是太贵，功耗能不能被电池支持。没有足够预算的团队必须在性能和成本之间找到实际平衡。

**Muhammad Awad：** 这正是边缘和云端可以互补的地方。小型团队不一定需要训练最大的模型，它们可以选择适合设备和客户的模型。硬件效率和软件优化让更多团队能够使用 AI，而不必全部依赖最昂贵的云端资源。

**Nathan：** David，你说深圳像 farmer's market。能否更具体地描述一个创业者如何在这里迭代产品？

**David Li：** 假设你想做一个带摄像头和语音功能的设备。你可以先找到一个现成的主板、一个摄像头模块、一个电池和一个外壳供应商。先做十个样品，拿到客户或朋友手里测试，再根据反馈改尺寸、改接口、改散热。下一版可能换一颗芯片，或者把一部分推理放到云端。

你不需要一开始就建一个完整工厂。供应链上有许多小规模服务商，能够帮你做模具、打样、贴片和装配。这个速度让试错成本下降。缺点是，供应商之间的质量和文档并不总是一致，创业者需要自己做很多整合和质量控制。

**Pash：** 西方团队能不能直接复制这种模式？

**David Li：** 不能只复制一个市场或一条供应商名单。深圳的模式包括地理距离、信任关系、工程师流动、订单规模和长期积累。很多供应商愿意接小单，是因为它们相信后面可能有更大的订单，也因为附近有很多潜在客户。一个地方如果没有这些网络，只把工厂地址放在地图上并不能得到同样的速度。

**Nathan：** 机器人嘉年华与工业自动化之间有什么联系？

**David Li：** 它们会共享人才、兴趣和供应链。孩子在比赛中学习传感器和控制，学生在学校做机械结构，工程师把经验带到工厂。公共比赛让人们看到机器人可以被反复修改，而不是一个只能由大公司完成的神秘设备。很多未来的工程师可能就是从这些活动进入这个行业的。

当然，比赛机器人和工业机器人不一样。比赛可以为了速度或技巧牺牲一些寿命，工厂则要求长期稳定、安全和可维护。比赛提供了学习和人才入口，但要进入生产线，还需要认证、集成和售后。不能把嘉年华上的成功动作直接当成工业能力证明。

**David Li：** 这也是为什么我反复强调 field application engineer。客户需要的是“把这台机器放到我的流程里”，而不是“这台机器在展台上完成了一次动作”。现场工程师要理解机械臂的工作空间、传感器的误差、工人的操作、生产的节拍和客户的预算。这个角色能够把一个通用硬件变成一个具体解决方案。

**Pash：** 机器人价格下降后，会不会出现大量没有用的设备？

**David Li：** 会。价格下降只是让更多人可以买到设备，不保证设备能产生价值。小工厂可能买了一台机器人，后来发现自己的产品经常变化，编程和换线成本太高，最后机器人被放在角落里。真正的采用需要明确的工作流程、持续维护和能够解决问题的人。

因此，机器人公司需要把软件、培训、现场服务和硬件放在一起考虑。收入不一定只来自卖机器，也可能来自集成、维护和长期服务。客户愿意为减少危险、提高一致性或解决劳动力短缺付费，但他们不愿意为一个永远需要专家照看的 demo 付费。

**Nathan：** 你提到电池测试。为什么它是一个适合机器人的场景？

**David Li：** 因为它同时具有重复性和风险。电池测试可能包括充放电、温度变化、应力和异常情况。人在旁边做大量重复操作并不理想，机器人可以在隔离环境中执行步骤，把人放到更安全的监控位置。如果某个环节出错，系统也能记录具体参数，便于追踪原因。

另一个场景是低量多品种生产。很多传统自动化设备需要很长的换线时间，只有在大批量生产时才划算。更灵活的机械系统结合视觉和小模型，可能让小工厂以较低成本应对频繁变化的订单。它不需要一个万能 humanoid，只需要足够灵活、容易重新配置的设备。

**Muhammad Awad：** 这和 agent 的情况很像。一个 agent 也不一定要做所有事情。它只需要在明确的工作流里完成一组动作，并且能识别何时需要人工。软件和机器人都要从通用能力走向可靠的任务执行。

**Pash：** 中国的模型服务很多是免费的。免费会不会让企业难以形成商业模式？

**David Li：** 免费往往是获得用户和反馈的一种方式。企业先让很多人使用，收集真实问题，之后再通过企业服务、硬件、广告、云资源或定制化收费。中国市场竞争很激烈，用户不愿意一开始就为一个还不成熟的模型支付高价。

免费也会加速应用扩散。小团队可以先用模型做产品原型，学校和个人可以学习，硬件公司可以测试不同模型。对模型供应商来说，成本是很大的问题，所以它们会不断优化推理、压缩模型和安排算力。商业模式不会只有“按 token 收费”一种。

**Nathan：** 但免费服务背后仍然需要算力和能源。

**David Li：** 当然。免费不是没有成本，而是成本由公司、投资者或云平台先承担。最终需要找到能够持续的经济模式。对于小团队来说，边缘推理可能减少长期云端费用；对于大公司来说，规模可以提高资源利用率。哪个方案更好，要看用户量和任务类型。

**Muhammad Awad：** 这也是为什么效率如此重要。每个请求的计算量、内存流量和网络开销都会影响成本。更高效的 CPU 和加速器不只是让 benchmark 更漂亮，也可能决定一个免费服务能否扩大到数亿用户。

**Pash：** 你们怎么看 25B 或 27B 模型在几百美元硬件上运行？

**David Li：** 这不是说所有任务都能达到云端大模型的水平，而是说很多用户不需要最大的模型。如果设备能够在本地完成总结、分类、简单对话和控制，就能节省网络延迟，也能保护部分数据。随着量化、蒸馏和芯片优化发展，更多参数规模会进入消费级或小企业级设备。

我见过一些团队做小型推理盒子，大小接近一个 SSD 或小型电脑。它们希望让企业把模型放在自己的门店、工厂或办公室，不必把所有资料上传到外部云端。产品能否成功还要看散热、维护、软件更新和价格，但方向是真实的。

**Nathan：** 中国有很多创业公司都在做类似设备。它们会不会最终被大厂挤出去？

**David Li：** 有些会被挤出去，有些会找到细分市场。大厂擅长模型和云服务，小公司可以专注于某个行业、某种硬件或某个地区客户。一个小团队如果能把模型和工厂设备结合得很好，可能不需要拥有最强的模型。它的壁垒是客户关系、部署经验和对现场问题的理解。

创业公司最危险的是只做一个外壳和一个聊天接口，没有独特的工作流。最有价值的公司通常知道自己解决了什么具体问题，并且能证明客户在节省时间、减少事故或增加收入。硬件和软件都需要回到使用场景。

**Pash：** 这和美国市场的创业也很像。

**David Li：** 是的。很多中美差异被夸张了。不同国家的创业者都会问客户是谁、成本是多少、怎样获客、谁来维护。区别在于供应链、资本、法规和用户市场的组合。不能只根据一个模型榜单判断整个生态的商业能力。

**Muhammad Awad：** 而且模型能力只是整个价值链的一环。系统需要芯片、网络、数据、软件、应用、客户和支持。任何一个国家都有强项和弱项。长期竞争力来自能否把这些环节连接起来。

**Nathan：** 关于中美竞争，西方观众可能更关心谁先实现 AGI。中国普通用户是否也这样看？

**David Li：** 一部分人会关心，但很多人每天面对的是更具体的问题。比如工厂如何减少人工，店铺如何做客服，学生如何写代码，设备如何省电。宏大叙事不能替代产品使用。只有当一个模型发布影响了市场、股票或行业政策，更多人才会把它放进“AI 竞赛”的框架里。

这不代表国家战略不重要。政策会影响芯片、教育、数据和创业投资，但普通人把政策转化为生活和工作的工具。中国从 2016 年以后就持续强调 AI，很多地方都在建设相关产业。现在的重点从“有没有 AI”变成“怎样用 AI 产生结果”。

**Pash：** 你认为中国用户为什么更能接受免费模型和快速迭代？

**David Li：** 中国互联网用户已经习惯了很多服务快速变化和低价竞争。一个应用今天有一个功能，下个月可能就换了界面。用户愿意尝试新的模型，因为切换成本相对低。企业也会很快比较不同产品，哪一个便宜、响应快、能接入自己的流程，就先用哪一个。

这会给产品团队很大压力。模型必须不断更新，服务要处理大量用户，成本控制和稳定性非常关键。免费并不意味着用户没有要求，恰恰相反，用户量大时，任何延迟、错误和内容问题都会迅速被放大。

**Nathan：** 你刚才说中国政府控制更多。这个控制是否会阻碍开源和机器人创新？

**David Li：** 它会改变创新的边界，但不一定让所有创新停止。企业需要理解监管、数据和内容规则。很多工程师仍然可以做机器人、边缘设备、制造软件和企业应用。国家重点项目和民营创业可以同时存在，只是关系比美国更显眼。

美国也不是没有控制。大公司拥有大量模型和数据，云平台的接口和价格也会影响开发者。两边都要讨论谁有权决定模型可以做什么，谁承担错误责任。简单把一边叫自由、另一边叫控制，无法解释现实中的平台权力。

**Pash：** 关于 open weight，我想听听你对安全的看法。

**David Li：** 开放权重会让更多人使用和研究模型，这对创新很重要。但开放也意味着恶意使用的门槛下降。模型在云端时，供应商可以限制账号、监控请求和关闭服务；权重下载后，使用者可以在自己的硬件上运行，供应商的控制减少了。

所以要区分能力层级。对一个普通小模型，开放通常利大于弊；对一个能够自动攻击系统、生成大规模欺诈或设计危险实验的强模型，开放方式需要更多谨慎。不能把“开放”当作天然安全，也不能把“封闭”当作天然负责。

**Muhammad Awad：** 从平台角度看，开放还需要持续的更新。一个模型发布后，硬件和软件会变化，漏洞会出现。企业需要知道如何获得补丁、如何验证模型来源、如何限制设备上的权限。如果只是下载一个权重文件，后续责任不清，部署风险会增加。

**Nathan：** David，你是否认为 AI 真的让中国和美国在同一水平线上？

**David Li：** 在某些模型能力上我会说非常接近。在另一些领域，美国拥有更强的资本、云端规模和前沿实验室，中国拥有更强的制造密度、成本竞争和大规模应用。所谓同一水平，不是每一项都相同，而是双方都足够强，不能把一方当成只会复制的落后者。

中国的团队会迅速吸收公开研究，再结合自己的数据和硬件约束。美国团队会利用更大的资本和全球人才。双方都有开源项目和封闭平台，也都有政策干预和商业竞争。真实的世界不是两条完全分开的赛道。

**Pash：** 有人说只要中国模型发布导致 Nasdaq 下跌，西方就会注意它。这种说法听起来有些夸张。

**David Li：** 但它确实说明关注机制。很多人不是因为认真阅读论文才知道中国模型，而是因为市场价格提醒了他们。对中国用户来说，Doubao、Kimi、DeepSeek 或其他服务本来就已经是日常工具。西方投资者则可能先从股票和新闻进入这个话题。

这会造成认知偏差。一个市场看到的是“突然出现的竞争者”，另一个市场看到的是“长期存在但不断更新的产品”。要理解中国 AI，不能只看一次发布或一次市场反应，还要看用户怎样使用、公司怎样降成本、硬件怎样部署。

**Nathan：** 机器人和模型之间的结合，会不会成为中美竞争的下一阶段？

**David Li：** 可能会，但机器人需要面对更多现实约束。模型可以在数据中心更新，机器人要在真实环境里移动、抓取和保证安全。中国的制造生态有助于快速试验，服务机器人和工业自动化会继续增长。美国在软件、研究和资本方面的优势也会进入机器人。

如果最终机器人进入大规模生产，决定胜负的可能是成本、可靠性、售后和集成，而不是某个模型在文字基准上的第一名。机器人每天都会损耗、需要维护和适配新任务。谁能把这些现实工作做好，谁就更接近商业规模。

**Muhammad Awad：** 机器人也会增加对边缘 CPU 的需求。它需要实时处理传感器、运动控制、通信和安全规则。某些高级视觉或规划任务可以调用 GPU 或云端模型，但紧急停止、基本控制和本地状态管理不能依赖长距离网络。计算资源必须分层。

**Pash：** 这让 AI 基础设施看起来越来越像一个完整的 operating system。

**Muhammad Awad：** 可以这样理解。模型是重要组件，但 agent 系统需要类似操作系统的调度、隔离、存储、权限和工具接口。CPU、内存和网络共同提供底层环境。未来的软件开发者可能更关注如何描述任务、控制权限和验证结果，而不只是调用一个模型 API。

**David Li：** 硬件开发者也会从“做一个板子”转向“做一个可更新的平台”。用户希望设备能够换模型、增加传感器和接入新的工具。深圳供应链可以快速做硬件，但长期价值要靠软件和服务保持。平台化会让小团队面对更大的开发空间，也会带来更强的竞争。

**Nathan：** 节目快结束了。你们对“AI 会抢走所有工作”的说法有什么回应？

**Muhammad Awad：** AI 会替代一些任务，也会提高另一些任务的效率。硬件行业仍需要设计、制造、安装和维护人员。更重要的是，社会需要帮助人们转移到新的工作，不要假设每个人都能自动完成转型。工程教育和实际培训会变得更重要。

**David Li：** 中国小企业的情况也很复杂。AI 可能减少某些办公室工作，但也让一个小商家可以完成以前需要外包的设计、客服和营销。机器人可能减少危险岗位，也可能减少某些重复岗位。最终结果取决于收益如何分配，以及人能否掌握工具。

**Pash：** 我希望公众能更广泛地获得 AI，不希望只有大型公司拥有最好的工具。但广泛使用也需要安全和透明度。一个 agent 不能因为会写得很好，就默认拥有修改代码、转账或改变生产流程的权限。

**Nathan：** 任何系统只要有外部输入和真实权限，就需要考虑 prompt injection、身份归属、操作日志和人工停止。工程师不能只展示它完成任务的时刻，也要展示它失败时怎样被限制和恢复。

**David Li：** 这对机器人尤其重要。机器在现实中犯错会伤害人或损坏设备。安全停止、权限隔离和现场培训不是附加功能，而是产品的一部分。

**Muhammad Awad：** 对云端 agent 也是如此。我们要让计算资源更高效，也要让系统可观察、可保护和可维护。CPU 与加速器的协同、内存和网络的设计、数据中心的能源效率，都会影响 AI 能否真正成为可靠基础设施。

**Pash：** 谢谢两位。今天从 Arm 的 CPU 讲到深圳的机器人，又讲到模型、边缘推理、数据中心和中美 AI。对我来说最大的收获是，AI 的下一阶段不会只有一个冠军芯片或一个冠军模型。真正重要的是它能否进入工作流，能否被普通用户和小企业以合理成本使用。

**Nathan：** 也不要忽略那些不会上热搜的工程岗位和供应链。memory、power、cooling、field application engineer、软件更新和售后服务，可能才是决定 AI 是否扩散的现实变量。

**Pash：** 感谢大家收听 AI in the AM。我们下次见。

**Pash：** 我们还想回到 Muhammad 讲过的一点：Arm 并不是只把一个 CPU 核心交给客户，然后就不再关心系统。云端的客户需要一整套平台，尤其是在 AI 工作负载开始变化之后。

**Muhammad Awad：** 没错。IP 授权仍然是我们业务的重要部分，但客户需要的不只是一个可以放进芯片里的核心。他们需要架构参考、软件支持、工具链、验证、生态伙伴和对实际工作负载的理解。一个 CPU 设计如果不能顺利运行操作系统、容器、数据库和客户应用，就不能因为指令集漂亮而被认为成功。

Arm 的平台思路也来自长期的生态经验。我们看到不同客户以不同方式使用同一架构。移动设备需要低功耗和响应速度，物联网设备需要长期稳定和安全，云端服务器需要高吞吐和可扩展性。AI 把这些要求连接起来，因为请求可能从手机发出，经过云端处理，再回到一个真实设备。软件和硬件的边界越来越需要共同设计。

**Nathan：** 许多观众会问，为什么不让所有事情都在 GPU 上运行？

**Muhammad Awad：** 因为 GPU 不是一个万能的工作环境。它特别适合高度并行、数据结构规则的计算，但系统还有很多分支逻辑、短任务、网络请求和状态管理。Agent 的工作流经常需要判断下一步做什么，等待一个外部服务，再把结果交给另一个模型。这样的任务不一定适合大规模矩阵计算。

你可以把一台 AI 服务器想成一个团队。GPU 像一群可以同时做同一类复杂计算的专家，CPU 则负责安排会议、传递文件、检查权限、处理突发情况和把工作连接起来。没有专家，系统能力不够；没有协调，专家也不能形成稳定的服务。两者不是互相替代，而是共同组成平台。

**Pash：** Agent 数量增加后，CPU 的任务是不是从“启动一个模型”变成“管理一个社会”？

**Muhammad Awad：** 这个比喻很有意思。至少在技术上，系统会管理很多并发的上下文和任务。一个 agent 可以创建更多 agent，让它们承担不同角色；有的做检索，有的做代码，有的做验证，有的和外部工具交流。平台需要知道每个任务的身份、资源限制和结果应该去哪里。

如果没有调度，任务会互相争抢内存和网络；如果没有隔离，一个 agent 可能看到不应该看到的数据；如果没有状态管理，系统会丢失上下文；如果没有可观察性，管理员就不知道延迟来自 GPU、CPU、数据库还是外部 API。Agent 系统的复杂度来自这些交互，而不是只来自模型参数。

**Nathan：** 对开发者来说，context switching 会带来什么变化？

**Muhammad Awad：** 过去很多应用有一个相对稳定的主流程，AI agent 可能同时处理很多不规则任务。它们会在不同模型、不同工具和不同数据源之间切换。每次切换都可能需要加载状态、检查授权和重新组织数据。缓存命中率、内存延迟和 I/O 路径会影响整体表现。

这也让开发者更关注任务粒度。一个大而连续的任务可能适合加速器，一个由许多短请求构成的工作流则可能需要更强的调度和更低的系统延迟。优化不一定是增加最大计算量，也可能是减少不必要的数据移动、合并请求或让结果更快进入下一步。

**Pash：** 供应链的另一个问题是时间。模型软件几个月就会更新，芯片设计可能需要几年。

**Muhammad Awad：** 这是行业必须处理的结构性矛盾。我们不能等软件完全稳定后才开始设计硬件，因为那会错过周期；也不能把所有硬件都设计成不可调整的固定系统。可编程性、模块化和软件抽象可以帮助平台适应变化。

我们还需要持续和客户交流，理解哪些变化会持续，哪些只是短期潮流。模型的名字会变，具体算法会变，但低延迟、低功耗、可靠内存和高效通信是更稳定的需求。硬件平台应该围绕这些基本变量构建，而不是只围绕一个短期模型。

**David Li：** 深圳的小团队通常没有几年等待硬件的时间，所以它们会使用现有的模块快速验证。先做一个可用的版本，确认客户真正愿意付钱，再考虑是否自研板卡或更深度地优化。这种方式可以降低风险，但会把很多整合工作留给创业者。

**Muhammad Awad：** 这也是开放生态的价值。不同公司可以在相对稳定的架构和接口上竞争，客户不必每次更换应用就彻底重写系统。如果软件、编译器和运行时支持更多硬件，创新就不会只依赖最有资源的公司。

**Nathan：** David，能否再谈谈中国硬件创业者与模型公司的关系？

**David Li：** 很多硬件创业者不希望从零训练模型。他们会选择一个公开模型、一个商业 API 或一个本地模型，然后把它和传感器、摄像头、麦克风以及自己的工作流结合起来。模型是一个部件，硬件和客户场景才是他们的产品。

这也解释了为什么 edge inference 受到关注。设备可能在本地做唤醒、简单识别、指令分类和隐私处理，复杂问题再发到云端。如果客户在工厂里使用，网络可能并不稳定，某些数据也不希望离开现场。本地模型可以提供基本的可用性，再由云端提供更强的能力。

小模型的优势不只是便宜。它可能更容易审计，更容易在特定任务上调优，也更容易部署到不同设备。一个企业如果只需要识别十几种故障或回答一组固定问题，没有必要把所有任务交给最大的模型。商业系统通常会把模型能力和任务要求匹配起来。

**Pash：** 但小模型也可能更容易出错。

**David Li：** 当然，所以要设计验证和升级路径。设备不能因为模型信心不足就执行危险动作。它可以把不确定的情况提交给云端或人工，也可以停下来请求更多信息。好的系统不是每次都给答案，而是知道什么时候不应该自动做决定。

在工厂里，这一点很关键。一个机器人移动错几厘米，可能损坏设备；一个库存系统写错一笔，可能影响生产。模型的准确率必须放到具体损失函数里看。宁可多一次人工确认，也可能比一次无法恢复的自动操作更便宜。

**Nathan：** 你提到大量机器人和比赛。中国的教育系统会不会因此更早培养机器人能力？

**David Li：** 比赛提供了一条入口，但不是唯一入口。很多学生通过编程、电子和机械项目接触机器人，也有人在工厂和小公司里边做边学。中国的优势之一是硬件距离近，学生做出一个板子或结构后，比较容易找到供应商修改。

公共机器人活动也让家长和企业看到真实应用。孩子可能先做一个会走的机器人，后来进入自动化、制造或软件行业。虽然比赛不能直接证明工业能力，但它能建立兴趣、人才和社区。开源项目则让学习者看到别人如何解决问题，并在其基础上继续修改。

**Pash：** 这个生态是否也带来大量复制？

**David Li：** 是的。复制有好的一面，也有坏的一面。它让一个成功的硬件方案快速降低价格，扩大使用；但它也会带来知识产权、质量控制和同质化。很多团队做出相似外壳和相似功能，最后比的是成本和渠道。

对创业者来说，复制意味着不能只靠一个概念。你需要有客户关系、软件体验、供应链速度或现场服务。一个硬件很快会被复制，但一个能够持续交付、维护并理解客户业务的系统更难复制。深圳的竞争会迫使团队尽快建立这些能力。

**Muhammad Awad：** 云端也存在类似现象。芯片或模型能力可能被竞争者追上，真正长期的优势来自生态、软件、开发者和客户部署。硬件迭代很快时，平台稳定性和兼容性反而更重要。

**Nathan：** 关于中国模型，能否解释为什么很多团队会关注小模型和本地部署，而不是单纯追求更大参数？

**David Li：** 约束会塑造产品策略。算力和内存成本高、GPU 供应不确定时，企业不能假设每个客户都有大型集群。它们会做量化、蒸馏、稀疏化和更小的模型，把最重要的功能放在可承受的设备上。对于很多客户，能不能在现有硬件运行比模型是否在排行榜第一更重要。

还有一个隐私和延迟问题。医院、工厂、政府和企业不一定愿意把所有数据发送到外部云端。本地模型可以减少数据移动，缩短响应时间。当然，本地设备也会有更新和安全维护问题，不能把“本地”自动当成安全。产品需要解决整个生命周期。

**Pash：** 你认为这些硬件约束会让中国出现不同的 AI 应用形态吗？

**David Li：** 可能会。中国的 AI 产品更容易和现有硬件、门店、工厂以及供应链结合。应用不一定先以一个独立的 SaaS 页面出现，而可能是一台设备、一条生产线或一个服务流程。模型能力被隐藏在产品里，用户只看到更快的客服、更便宜的检验或一个能工作的机器。

这种模式对媒体不太显眼，因为它缺少一个巨大的消费应用。但对企业收入可能很重要。一个工厂每年节省的停机时间、一个门店减少的客服人力、一个测试间避免的事故，可能比社交媒体上的模型演示更有商业价值。

**Nathan：** 这是不是你说的“怎么用 AI，怎么赚钱”而不是“谁在竞赛中获胜”？

**David Li：** 正是。大多数人不需要参与国家级模型竞赛，他们只想知道工具能不能让自己做得更好。国家和大公司的竞争会影响供应链和价格，但应用的价值仍然要在真实客户那里验证。

**Pash：** 我们有时会把中国市场当成一个统一的整体，但你描述的是大量不同的公司和场景。

**David Li：** 中国不是一个单一的 AI 公司。这里有大型互联网平台、有模型创业公司、有硬件工厂、有小型集成商，也有学校和社区。它们使用不同模型和不同商业模式。很多小团队可能从一个免费 API 开始，后来转为本地部署或定制服务。

大型平台提供了基础设施和用户分发，小公司提供了细分场景。硬件供应商让产品快速迭代，现场工程师把产品带到客户。这个网络的价值不容易用一家公司的收入代表，但会影响技术扩散速度。

**Muhammad Awad：** 这类多样性对硬件也有好处。不同工作负载会推动不同的芯片和平台设计。不是所有客户都追求最大模型，有人关心边缘延迟，有人关心云端吞吐，有人关心安全隔离。生态需要支持这些不同需求。

**Nathan：** 有一个问题来自观众：如果中国模型和美国模型越来越相似，是否会出现相同的安全问题？

**David Li：** 会有很多共通问题。模型可能产生幻觉、泄露数据、误解指令或被 prompt injection 影响。不同地区还会有内容规则、数据边界和用户习惯差异。能力相似并不意味着部署环境相同。

很多团队使用相似的公开研究和硬件，也会从别的公司招聘人才，因此模型能力会出现趋同。安全措施可能看起来不同，但它们都要面对权限、监控、数据和责任的问题。不能因为某个模型来自不同国家，就认为它不需要同样的工程审计。

**Pash：** 你是否相信更多开源代码会自动让 AI 更安全？

**David Li：** 不会自动。代码公开可以让更多人检查，但模型行为还取决于训练数据、权重、部署工具和权限。一个有漏洞的系统如果公开，攻击者也能更快找到漏洞。开源带来创新和审查，也带来更低的滥用门槛。

因此要做分层。普通的模型工具和机器人接口可以广泛开放，高风险能力要有更严格的评估和访问控制。开源不是一个单一的开关。源代码、训练数据、模型权重、接口和部署权限可以有不同的开放程度。

**Muhammad Awad：** 我也会从供应链安全补充。无论软件还是硬件，客户需要知道组件来自哪里、如何更新、漏洞怎样修复。一个开放平台如果没有维护者和补丁机制，长期使用会很困难。开放生态必须伴随可靠的验证和支持。

**Nathan：** 现在回到公众对 AI 的情绪。有人支持继续建设，有人要求放慢。你们是否能找到中间位置？

**Pash：** 我的立场是可以放慢到安全和社会能够跟上的程度，但不要因为担心劳动力市场变化就完全停止。广泛可用的 AI 也可能帮助个人和小公司获得工具。问题是收益不能只集中在拥有最大数据中心的人手里。

**David Li：** 我会说要同时允许使用和设置边界。让小企业使用低风险工具，让高风险的自主系统接受更严格的测试。让机器人进入危险场景，但要求安全停止、现场培训和责任制度。让模型开放一部分能力，但不要假设所有权重都可以无条件发布。

**Muhammad Awad：** 基础设施政策也需要有节奏。电网、数据中心和芯片供应要多年规划，企业和社区需要知道规则。安全、效率和透明度会帮助行业获得长期许可，而不是每次都在扩张之后才面对反弹。

**Pash：** 最后一个快问快答。观众如果想进入 AI 硬件，应该学什么？

**Muhammad Awad：** 学系统，而不只是学一个模型。理解 CPU、GPU、内存、网络、存储、操作系统、编译器和部署。能够把工作负载拆解，知道延迟和功耗来自哪里。还要学习怎样和客户沟通，因为真正的需求常常隐藏在业务流程里。

**David Li：** 动手做东西。用一个小模型、一个传感器或一个机器人做出真实项目，看看它怎样在噪声、光线、温度和用户误操作下失败。再把失败修好。深圳的优势就是让人有机会迅速从想法到样机，重要的是不要停在样机展示。

**Nathan：** 如果想做创业项目，不要只问模型有多强，要问它能替谁节省多少时间，能减少什么危险，客户每个月愿意支付多少钱，出了问题谁能到现场解决。

**Pash：** 这期节目里的共同观点是，AI 的下一阶段是系统和部署。云端需要 CPU、内存和电力，边缘需要小模型和可靠硬件，机器人需要集成和现场服务，企业需要权限和责任。模型本身只是其中的一部分。

**Muhammad Awad：** 我赞同。我们会继续看到更强的 GPU，但 CPU 和平台不会消失。Agent 把大量任务连接起来后，协调能力会成为性能和成本的一部分。Arm 会继续和云服务商、模型公司、芯片客户和软件生态合作。

**David Li：** 深圳也会继续出现很多快速迭代的机器人和边缘设备。有些会失败，有些会被复制，有些会找到真实市场。真正有价值的产品，最终还是要通过用户、成本、可靠性和服务来证明自己。

**Pash：** 好，节目到这里。感谢两位嘉宾，也感谢观众和听众。请大家在评论里告诉我们，你们在工作中最想让 agent 或机器人解决什么问题。下次 AI in the AM 再见。

**Pash：** 在正式结束前，我想把几个容易被混淆的概念再厘清一次。我们今天说的 cloud AI，不是把一切事情都搬到一个大数据中心；说 edge AI，也不是说云端会被淘汰；说机器人，也不是说只要给模型装上两条腿就能解决工厂问题。

**Muhammad Awad：** 是的。计算位置应该由任务决定。一个需要低延迟、持续连接传感器的任务，可能应该留在边缘。一个需要大规模知识、复杂规划或多个模型协同的任务，可能应该放到云端。很多服务会在两者之间分层，而不是选择其中一个。

这也会影响硬件配置。边缘设备需要低功耗、小尺寸、可靠的本地存储和实时控制。云端服务器需要高带宽内存、网络吞吐、虚拟化和大规模调度。CPU 在两边都存在，但承担的工作不同。边缘 CPU 需要快速响应设备状态，云端 CPU 需要管理大量并发任务和数据流。

**Nathan：** 如果 AI agent 在边缘设备上运行，安全边界会更复杂吗？

**Muhammad Awad：** 会。设备可能位于不完全受信任的环境，攻击者可以接触硬件或网络。系统需要安全启动、固件验证、权限隔离和及时更新。一个小盒子即使只运行一个小模型，也不能因为体积小就跳过安全设计。设备一旦进入大量客户现场，更新和维护本身就是一个系统工程。

在云端，平台可以更集中地更新和监控，但同时承载的数据和权限更多。两边的风险不一样。好的架构会让最敏感的控制尽量靠近数据和设备，同时让复杂计算使用受控的云端服务。这个分工需要从产品设计阶段就确定，不能上线后才补一套安全层。

**David Li：** 深圳的硬件团队有时会先把设备做出来，再考虑安全。这在原型阶段可以理解，但如果设备进入工厂或家庭，就必须补上固件签名、用户权限、网络隔离和更新机制。很多消费者只看到设备能不能说话或移动，却不知道它长期连接网络时会产生什么风险。

**Pash：** 这和 AI 玩具的讨论很接近。一个会和孩子对话的设备，应该拥有多少数据？

**David Li：** 这是一个很实际的问题。设备可能收集声音、家庭环境、用户习惯和对话内容。如果所有数据都上传云端，家长需要知道数据保存多久、谁能访问、是否用于训练。若设备本地处理一部分任务，隐私会更容易管理，但本地存储同样需要保护。

产品团队还要明确设备的 personality 和承诺。一个玩具可以有有趣的回答，但不能假装自己是一个真正理解孩子情绪的朋友，更不能在没有监护人同意的情况下诱导孩子提供私人信息。AI 产品越接近家庭和儿童，越需要清晰的身份和权限边界。

**Nathan：** 这是不是也解释了为什么“通用 personality”很难成为长期壁垒？

**David Li：** 是的。不同设备都可以调用相似的模型，外壳和声音也容易被复制。真正的差异可能来自内容、交互设计、隐私保护、硬件可靠性和与家庭或学校流程的结合。一个孩子愿意长期使用的设备，需要持续更新和可信的关系，而不只是第一次对话很惊艳。

**Muhammad Awad：** 这对云平台也是提醒。用户体验不是单次响应质量，而是长期的可靠性、延迟和安全。如果 agent 能够在不同设备之间保持上下文，平台还需要管理身份和授权。同步的便利越大，数据保护的责任也越大。

**Pash：** 我们再谈谈数据中心建设的社会问题。有人觉得 AI 公司只会把成本推给电网和社区，最后把收益私有化。

**Muhammad Awad：** 这确实是政策需要处理的问题。数据中心带来就业、税收和服务，但也会带来用电、用水、噪声和土地成本。企业需要公开计划，投资效率和基础设施，而政府需要明确许可、环境和社区参与规则。不能把所有反对意见都称为反科技。

另一方面，社会也应该看到云服务对很多企业的价值。一个小公司不必自己建大型机房，就能使用模型、数据库和软件。AI 的计算集中化可以提高资源利用率，也可以造成权力集中。政策要做的不是把问题简化成支持或反对数据中心，而是让效率和收益更广泛地分配。

**David Li：** 中国的城市也会遇到类似问题，只是表达方式不同。一个地方希望获得产业、岗位和税收，也要面对能源、交通和环境。对小企业来说，免费或低价模型让它们可以使用先进工具；但这些服务的基础设施成本最终仍然要有人承担。

**Nathan：** 这和我们谈的硬件瓶颈有关系。真正的瓶颈可能不只会抬高芯片价格，也会抬高模型服务价格。

**Muhammad Awad：** 对。电力、内存、网络和维护人员都会进入每一次推理的成本。性能功耗比提高，可以减少成本增长，但需求如果增长得更快，整体资源仍然紧张。客户因此会同时优化模型大小、请求频率、缓存和任务分层。

AI 应用的商业模式需要理解这些变量。一个服务如果让模型不断重复读取相同内容，成本会很高。一个 agent 如果没有有效的缓存和任务规划，会产生大量无效调用。软硬件共同优化，不只是芯片公司的工作，应用公司也必须承担这部分责任。

**Pash：** 所以一个更强的模型不一定意味着更好的产品。

**Muhammad Awad：** 对。更强的模型可能回答更复杂的问题，但如果延迟、成本和可靠性不适合业务，客户仍然不会采用。很多工作只需要一个经过良好训练的小模型，加上清晰的工作流和验证。系统应该根据风险和任务选择能力，而不是所有地方都调用最强模型。

**David Li：** 在深圳，这种成本意识很强。工程师会直接计算一台设备的材料、装配、电池和网络费用，也会问客户能不能承担订阅。一个小模型如果能让产品在本地运行，可能比一个很强但每月费用高的云服务更适合市场。

**Nathan：** 你觉得未来会出现大量“AI box”而不是所有东西都作为云服务吗？

**David Li：** 会出现，但不会只有一种形态。有人会用本地推理盒子，有人会用边缘设备和云端组合，也有人会完全依赖云。企业会根据隐私、成本、网络和维护能力选择。很多 SSD 大小的设备本身不是终点，而是把 AI 能力带到不方便使用大型服务器的地方。

对硬件创业者来说，最难的是从 demo 走到规模。设备需要稳定地运行几个月，客户需要能够自行升级，出现故障后有人解决。模型更新可能改变内存和功耗需求，所以产品不能把所有空间和散热设计得刚刚好。要为变化留下余量。

**Muhammad Awad：** 这正是平台设计的价值。客户希望硬件能够支持新的工作负载，而不是每次模型变化就更换设备。架构、运行时和驱动需要有足够的抽象，开发者也需要工具了解性能和资源使用。软硬件接口越清晰，生态越容易扩张。

**Pash：** 我们还没有谈到网络。Agent 需要访问很多 API，网络会不会成为新的瓶颈？

**Muhammad Awad：** 会。每个外部调用都有延迟、失败和安全风险。一个 agent 如果连续调用多个 API，整体时间会被最慢的请求拖长。网络带宽和连接数也会影响并发。系统需要合理缓存、重试、限流和故障转移，但重试不能在外部服务已经过载时无限增加压力。

网络还决定数据是否可以留在本地。对隐私敏感的任务，减少数据出站可能比增加计算能力更重要。对机器人和工业设备，实时控制不能完全依赖远端。架构师需要把任务分成硬实时、软实时和可以异步处理的部分。

**David Li：** 工厂里最怕的是一个小网络问题让整条线停下来。机器人可以使用云端模型做复杂识别，但基本动作、紧急停止和安全互锁必须在本地持续工作。设备应该在断网时进入可预期的降级状态，而不是随机做出动作。

**Nathan：** 这让“AI agent 可以自动完成一切”听起来更危险。

**David Li：** 是的。自动化程度越高，系统越需要知道什么时候停。一个设备或 agent 不能只被训练成追求任务完成，它还要理解安全条件、权限和异常。企业客户愿意买的是可预测的自动化，而不是不可解释的冒险。

**Muhammad Awad：** 从硬件看，安全互锁、隔离和监控需要处理器和系统软件支持。算力强并不等于系统可靠。客户还要知道故障发生时，哪个组件出了问题、数据是否完整、如何恢复到一个已知状态。可观察性会和性能一样重要。

**Pash：** 对软件开发者来说，agent 的可观察性意味着什么？

**Muhammad Awad：** 至少要知道每个步骤的输入、输出、模型版本、工具调用、权限判断和耗时。一个用户看到最终答案，但管理员需要看到系统怎样得到答案。如果结果错误，团队才能定位是检索错、模型错、网络错、权限错还是外部服务错。

日志本身也包含敏感数据，所以不能无限制地保留和传播。系统需要按权限访问日志，保护客户信息，同时保留足够的审计证据。企业在部署 agent 时，往往低估了这部分工程工作。

**David Li：** 机器人也要记录传感器、动作和异常。现场工程师需要知道机器为什么没有抓到一个零件，是视觉问题、光线问题、机械误差还是模型判断错误。没有日志，现场只能反复猜。硬件和软件的诊断能力会直接影响售后成本。

**Nathan：** 这可能是一个比模型能力更确定的市场机会：工具、监控、部署和维护。

**Pash：** 但我们不想把今天的讨论强行变成投资推荐。很多公司会受益于 AI 生态，不代表每一家都值得买。

**Muhammad Awad：** 从行业角度，我只能说基础设施需求会持续推动平台、芯片、内存、网络和电力。具体公司仍要看估值、执行、客户集中度、供应链和竞争。技术趋势不是自动的交易结论。

**David Li：** 机器人也是如此。一个公司拥有很酷的 demo，不代表它能获得重复订单。应该看客户是不是愿意长期付费，现场工程是否成熟，设备是否能稳定运行，以及售后是否可以规模化。不要因为一个视频里的动作就假设商业成功。

**Pash：** 这点我们希望观众记住。节目可以帮助大家理解产业链和技术变化，但不能把顺带提到的公司、硬件或生态地图写成看好逻辑。

**Nathan：** 还有一个关于“中美谁赢”的问题。也许更好的问题是，哪一方能够更快地把模型、芯片、机器人、能源和企业流程结合起来，并且解决安全与分配问题。

**David Li：** 我同意。中国有快速制造、低成本和大量真实应用，美国有前沿研究、资本、云平台和大型客户。双方都会学习对方的优势。最终结果不是一个模型榜单决定的，而是由一整套生态决定的。

**Muhammad Awad：** 而生态需要时间。芯片架构、开发者、工具链和客户部署会产生网络效应。一个平台如果让开发者更容易迁移和使用不同计算资源，就能支持更多创新。一个芯片如果只有峰值性能而缺乏软件支持，可能无法形成持久价值。

**Pash：** 最后，请两位用一句话说明 AI in the AM 的听众今天应该带走什么。

**Muhammad Awad：** 在 agent 时代，不要把 AI 只看成 GPU 上的模型。CPU、内存、网络、能源、软件和调度共同决定了系统能不能真正工作，性能功耗比和可靠性会越来越重要。

**David Li：** 不要把 AI 只看成国家竞赛或模型发布。去看它怎样进入工厂、设备、门店和小企业，谁能把硬件、软件和现场服务结合起来，谁才可能把技术变成现实价值。
