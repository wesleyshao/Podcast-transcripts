# Lindy Teammate: Flo Crivello on Multiplayer Agents, Memory & Why He'd Ban the Chinese Models He Uses

## Transcript

### 节目开场

**Nathan Labenz：** 欢迎回到 The Cognitive Revolution。今天的嘉宾是 Lindy 创始人兼 CEO Flo Crivello。Lindy 正在发布 `Lindy Teammate`：一个进入公司 Slack、像普通同事一样参与协作的 AI 员工。它直接面对 Claude Teammate 一类产品的竞争，但一个很醒目的区别是，Lindy 当前主要运行在 DeepSeek 上。

这次对话的前半部分会深入讨论这些 token 究竟花在了哪里：多人 AI 与单人 AI 的差别，团队历史资料背后的社会契约，怎样用提示词实施隐私边界，以及怎样用后台代理持续整理机器记忆。Flo 还会解释 Lindy 的 context buckets、递归压缩、缓存和自平衡树设计，并推荐代理原生文件系统、沙箱和浏览器基础设施供应商。

我们也会讨论 Lindy 内部在 AI 员工出现后的工作方式。Flo 认为，当前模型在很多维度已经是超级智能，却会以令人难以预测的方式犯低级错误，像一个能写五万行代码、却一天几十次坚持让你步行去洗车的同事。现在仍处于人机共同创造最佳答案的“半人马阶段”，但他认为这只是暂时状态，未来人类很可能会从增益项变成给高度优化系统加入噪声的一方。

最后，我们会转向 OpenFace 一类事件、对齐失败和中美模型竞争。Flo 的概括非常直接：“现在是 2026 年 7 月，我们有了 AGI，已经处于起飞阶段，却还没有解决对齐。”更反直觉的是，他一边让自己的公司依赖 DeepSeek，一边主张美国禁止未经处理的中国前沿模型。我们会就蒸馏、公平竞争、审查、国家安全、保险、审计和国际协调逐项交锋。

### 从智能工作流到进入 Slack 的 AI 同事

**Nathan：** Lindy 几年来经历了多次演化。最初更像聪明的 Zapier 工作流工具，后来变成个人助理，现在则是完整的 AI 员工。先介绍这次发布吧。

**Flo Crivello：** 我们从一开始追求的就是 AI 员工。三年前启动时确实太早，但现在这个产品形态基本已经成熟。`Lindy Teammate` 生活在 Slack 中，能连接公司使用的各种工具，并持续积累整个团队的语境。它不是给某个个人使用的一段孤立对话，而是一套团队级的代理脚手架。

AI 正从单人体验跨向多人体验。我常把它类比为文档协作的变化：过去人们通过电子邮件来回发送 Word 文件和修订版，Google Docs 则把大家放进同一个共享对象。现在公司里所有人都在同一间会议室交流，但每当某个人想与可能已经是公司最重要参与方之一的 AI 沟通，他却必须离开会议室，去自己的私人窗口里和 AI 说话，再回来向团队转述。真正的 AI 同事应当待在团队本来就协作的地方，拥有同一个共享身份、共享记忆和共享语境，所有人都能直接与它合作。

### 团队入职的瓶颈不是智力，而是语境

**Nathan：** 公司给人类员工做入职已经很难。多人模式还牵涉公共频道、私人频道、文档权限和历史信息的社会预期。你们究竟怎样吸收资料、怎样存储，又怎样处理隐私边界？

**Flo：** 我们最着迷的正是这个问题。当我们接近甚至已经拥有 AGI 时，纯粹智力的相对重要性下降，语境的重要性上升。假设历史上最聪明的人之一 John von Neumann 突然出现在办公室，他在接下来一小时甚至一天内，可能还不如一个普通同事有用。不是因为他不聪明，而是因为你有具体工作要做，却没有时间给他讲清公司、客户、项目和限制条件。

代理在入职这件事上反而可能优于人。传统公司很依赖 Wiki、培训和书面文档，可文档写下来的那一刻就开始过时。Lindy 建了一层共享语境和所谓 `hydration` 系统。用户接入 Confluence、Notion、Google Docs 等知识源，更重要的是接入 Slack，因为公司最真实、最新的知识往往在那里，虽然它很乱，但代理不怕乱。

Lindy 会抓取可访问的 Slack 历史，并以文件系统为基础构建知识图谱。注册后十秒左右，用户就能看到代理开始学习，右侧图谱会持续增长。图谱有两层：个人层和工作区层。用户能直接打开 Lindy 文件系统，查看自动维护的 memory 文件及其引用文件。

后台有一个专门的 memory agent。我们称它的工作为 `napping`，不是每天睡一次，而是大约每十五分钟运行一次。公共信息会更新团队文件系统和团队记忆，私人信息只更新相关个人的文件系统。前台的 Teammate 再检索这些资料。困难在于，单个用户累积的语境可以达到数百万 token，不可能每一轮都塞进模型，因此后台怎样组织记忆、前台怎样在运行时找到正确内容，才是产品的核心。

### 日志会淹没知识，会议却是一等资料源

**Nathan：** 我给自己导出历史资料时发现很多特殊情况。例如，我曾把“我发出的长邮件”当成重要性指标，结果排名最高的内容往往只是我从 Claude 复制出来、再转发给别人的长文本。公司 Slack 还有自动日志频道，数量巨大，却可能没有知识价值。代理第一次进入陌生组织，怎样识别这类噪声？

**Flo：** 关键在于记忆由一个真正的代理维护，而不是机械地做 RAG。memory agent 自己也有记忆，可以理解“怎样管理记忆”、哪些信息源可靠、什么内容值得持续读取。我们观察到一种涌现行为：它第一次遍历 Slack 时会发现日志频道，随后判断那里学不到东西，并主动停止在这些频道上浪费时间。随着它逐步理解组织，同一条孤立的错误或复制内容会被大量一致资料稀释，就像训练数据中的少量噪声不会自动推翻整个模型。

会议必须是一等公民。我认为企业低估了会议作为知识源的价值。几乎每个重要客户关系、项目和决策都围绕会议展开，最新资料大量存在于会议中。因此，Lindy 不只是录音、转写和总结。用户可建立自动收集会议的文件夹；公开会议进入共享文件夹后，会更新团队知识网络，私人会议则保留在私人范围。之后你可以问一个“参加过公司所有会议”的代理：客户最近在说什么，最频繁的功能请求是什么，某个项目的反馈怎样。

### 历史资料的社会契约不能只靠一个权限开关

**Nathan：** 我的私人 Wiki 有两版。一版是完整的“第二大脑”，包括别人并未预期会被放入公共代理的私信、邮件和敏感判断；另一版则按照“哪些内容适合告诉人类助理”的标准做过净化。多人系统面对旧资料时，不能假设过去所有发言者都同意未来由一个代理重新传播。你们怎样处理？未来的社会规范会不会也因此改变？

**Flo：** 团队内部为此争论得很激烈。我原本认为两层就够：团队公共记忆和个人私人记忆。另一些人认为，即使个人层也不应什么都记住，他们还需要“超级私人层”或多个 memory bubbles。若把所有层级做成产品权限，会迅速变得过度复杂。

我们最后发现，最好把控制权放在可读、可编辑的文本提示里。每个用户都有 `memory.md`，memory agent 每次运行都会把它放进上下文。你可以直接写：“这些内容永远不要记住”，“这个敏感主题只写入某个隐藏文件夹”，“除非满足某些条件，否则不要检索那个文件。”这也是我看空纯 RAG、看好文本和文件系统的原因：人能检查记忆、修改记忆，也能以非常细的粒度写下护栏。

我自己为了上播客演示，就有 `memory.md` 和净化后的 `memory2.md`。主文件里明确告诉代理，`memory2.md` 只是演示用，不要把它当成真实记忆。这不是只有一份地面真相、靠不同镜头临时过滤，而是允许用户在文件系统中明确分层，再由提示词约束代理怎样使用。

### 多人代理难在脚手架、一致性和自我改进

**Nathan：** GPT-4 时代，我就模拟过家庭运动小组里的 AI 协调者，当时它已经能在简单多人情境中做得不错。为什么真正的 AI 员工又花了三年才出现？

**Flo：** 难点一直是脚手架，尤其是语境积累和语境管理。人们可以接受普通 Claude 偶尔记得一点旧对话，但对员工的期待完全不同：它必须在长期工作中维持丰富、稳定、连贯的过去。我们既要让 memory agent 维护数百万 token，又要让执行任务的代理在运行时准确找到相关内容。

可靠性是另一个难点。我们做了模块化的 `validator`，本质是多路 LLM-as-a-judge。任务过程中会多次触发若干评审模型，它们各自判断，再形成一个小型“评议会”决定是否继续。我们还建立了自我改进循环。模型从 GPT-4 之后已经强到足以改进自己的工作方式。Lindy 上线自我改进循环后的第一周，错误率就下降了约八倍，而且曲线仍能持续向右下走。

很多内部方法比论文早三到六个月出现，有一次后来论文甚至用了和我们内部完全相同的名称。我们有时觉得应该发表，但产品节奏太快，没有时间。这里不是故意保密，别人愿意复制这些方法，我反而很欢迎。

### 负毛利、缓存命中率与 token 经济学

**Nathan：** 新组织第一次接入时要消耗大量 token，之后记忆代理又不断处理资料。你们是否需要收取设置费或绑定年约？怎样控制输入 token、缓存和总体成本，确保最后仍比一个人类员工便宜？

**Flo：** 直接说结论：目前还没有完全做到，Lindy Teammate 现阶段可能比人类员工更贵，我们在补贴用户。这正是融资的用途之一。之前我们把大量任务换到中国模型上，个人助理场景里的简单任务，例如发邮件、安排会议，并不需要“上帝级模型”，DeepSeek Flash 已经够用，因此一度不再需要补贴。

Teammate 不一样。用户会交给它复杂得多的任务，我们又回到负毛利。作为 CEO，我当然不喜欢负毛利，但我能接受，因为团队相信它很短暂。做 AI 产品应该为下一代模型预先构建，而不是只针对今天的单位成本。

缓存是经济模型的核心。当前 cache hit rate 约 85%，坦率说还不够高。任何系统改动都可能破坏缓存，命中率从 85% 降到 65% 看似只差二十个百分点，未命中的比例却从 15% 增到 35%，实际成本接近翻倍。因此我们为命中率下跌建立了持续告警。

### Context buckets：让代理能回到压缩前的原始事实

**Flo：** 一个重要突破是 `context buckets`。某些工具或 MCP 一次会返回十万 token，直接交给主代理会又贵又混乱。我们把大结果留在一个 bucket 中，只向主代理暴露摘要和一个代表这个 bucket 的子代理。主代理可以和这个子代理对话，子代理则拥有完整内容、自己的缓存，并能用 Unix 工具检索和处理资料。

下一步是递归 context buckets。对话超过阈值时，目前大约是二十万 token，我们会进行 compaction，但不把旧内容永久压成一个不可逆摘要，而是把完整旧对话保存在一个 bucket 中。主代理以后仍能回到 ground truth。对话继续增长、再次压缩时，新 bucket 可以包含上一个 bucket，因此理论上能访问无限长历史。

朴素实现会形成俄罗斯套娃：要访问九次压缩之前的内容，必须穿过九层子代理，复杂度、延迟和成本都随深度线性增长。解决方法是让每个 bucket 包含多个较早 bucket，形成自平衡树。我们终于用到了学校里学过的 AVL tree 和 red-black tree。

AVL tree 能把树高压得最低，但重新平衡代价很高，会迫使许多 bucket 重建并造成 cache miss。red-black tree 会在树高和重平衡成本之间折中。我们借用了这个思想，但不是二叉树，而是每个节点大约一百个子节点的高分支树。两次跳转就能覆盖一万个 context buckets；若每个 bucket 有二十万 token，理论上两次 LLM 调用即可定位约二十亿 token 的历史。这样代理看似“永远记得一切”，实际只是能以不同粒度快速钻回相应原始资料。

二十亿 token 远大于多数企业实际需要。一个有多年 Slack 历史的二十人团队，初次 hydration 通常只处理三百万到五百万 token。真正迅速放大规模的是会议：如果两千名员工每天各有三到七小时会议，token 会非常快地累积。对个人用户而言，直接导出 Slack workspace archive 最省事；SaaS 不能要求每个客户这样做，只能受 Slack API 限速，逐步抓取历史。

### 管理员权限限制了 PLG 向大企业扩张

**Nathan：** 我能导出自己管理的 Slack，但加入的其他 workspace 未必给我管理员权限。这是否意味着产品一开始就必须得到管理员支持，从而限制 land-and-expand？

**Flo：** 是的。要安装应用并抓取团队资料，必须有相应 Slack 权限。五十到一百人以下的团队通常比较宽松，很多成员都能安装应用；规模超过一百后，这种权限迅速收紧。大企业里往往由内部 champion 去说服 IT 并推动安全评审。

IT 谨慎是合理的。Lindy 已满足 SOC 2、HIPAA 和 GDPR 等要求，我们也熟悉繁重的审查流程。另一方面，很多 IT 团队自己也接到“把公司变成 AI-native”的任务，正主动寻找这类工具。PLG 向上走到一定规模，本来就会碰到组织采购和权限上限。

### 从 Nathan 的分层摘要到假设驱动检索

**Nathan：** 我的做法是把邮件、DM、Slack、Google Docs 等数字痕迹统一放入 SQL 数据库，映射成 thread 和 message，作为原始事实层。再按月把二三十万 token 压缩到两三万，按年再压一层，最后让模型建立 Wiki。摘要还会保留几个具有唯一性的短语，让模型需要核验时能用它们直接找到原消息。这个办法对一个人效果不错，多人场景可能缺什么？

**Flo：** 你描述的方法很合理，我们自己也保留 RAG。可以增加 `hypothesis-driven retrieval`：若问题是“Justin Bieber 出生在哪里”，不要只检索问题本身，而是先生成“出生于巴黎、纽约、柏林”等多个候选假设，再分别做语义检索，因为陈述句通常比问句更接近资料中的答案。反向也可以做：每次存入一条答案时，预先生成可能指向它的多个问题，一并加入索引。

更重要的是，让同一个 memory agent 同时负责记忆更新和检索。前台代理虽然能直接翻文件，我们仍提示它：缺失记忆时先询问 memory agent。系统会记录问题、答案和检索用了多少跳。memory agent 每次 napping 时像图书管理员一样检查日志：哪些问题频繁出现，哪些答案很难找到。最近约一千组问答可构成滚动缓存，但缓存有 TTL，会变旧。因此它还会主动重构文件，让高频答案以后用更少跳数取到。这同时改善速度和检索质量。

### 压缩越有效，越要考虑可审计性

**Flo：** 我们试过把文本改写成所谓 caveman 风格，也就是删除大量语法成分，只保留最短语义。它能减少约 20% 至 30% 的 token，速度、成本和检索指标都变好，信息损失几乎没有。但我们最终没有采用，因为企业客户会直接看到文件系统，里面若全是难看的残句，可维护性和可审计性很差。指标提升不代表产品整体更好。

另一个方向是 `TOON`，即 token-oriented object notation。它是面向代理的 JSON 替代格式，据称也能比 JSON 节省约 20% 至 30% token，并提高代理表现。JSON 有大量结构噪声。理想做法是在工具与代理之间加一层中间件，把工具结果转成 TOON。Nathan 使用 YAML，出发点也相同：让人和模型都更容易读，又减少无意义符号。

### 单代理优先，不要照抄人类公司的部门图

**Nathan：** 我曾经很反对拟人化模型，现在却一次次发现，适度把模型当人理解很有用。你怎样看 AI 组织中的拟人化？

**Flo：** 模型毕竟以人类文本和人类反馈训练，拟人化常常是有效的直觉。但不要把整个 AI 组织过度拟人化。我越来越相信，在安全和边界允许时，应尽可能用一个代理，而不是按人类公司的角色划分建一群代理。

人类公司设置数据科学家、工程师、设计师和产品经理，是因为每个人每天只有二十四小时，能持有的语境有限。代理可以复制、分叉、并行执行，也不受同样的时间限制。因此“分工”本身不是创建多代理系统的好理由。安全隔离、外部接触和权限分区仍可能要求多个代理，但不要因为组织图看起来熟悉，就机械地一职位一代理。

多个副本同时修改一套记忆时，会出现数据库事务和冲突问题。我们的答案是 Git。大型人类团队已经用 Git 解决并发协作、merge conflict、rebase 和历史追溯。Lindy 的文件系统由 Git repository 支撑。memory agent 在大型组织里会分叉许多子代理并行处理新资料，初次 hydration 又要求用户注册十秒内就看到成果，Git 能处理它们最后的合并，也免费提供版本历史。

### 买基础设施，不要把成熟系统重新 vibe code 一遍

**Flo：** 我们使用 Mesa 的 agent-native file system，它底层也是 Git。早期很容易产生“自己写一个 Git、自己管理文件系统”的冲动，真正做到规模化后才会理解成熟基础设施里藏着多少设计和边界条件。现在只要有合适供应商，我更愿意买而不是造。

这与“SaaS 已死，所有东西都能 vibe code”的叙事相反。应用逻辑可以大量由 AI 生成，基础设施却不能因为看起来简单就草率重写。代理还需要安全沙箱，我们使用 E2B；沙箱通常自带文件系统，但规模化后应把执行环境和持久文件系统解耦。浏览器管理方面，Browserbase 做得很好。

可观测性和 eval 是一个例外。Lindy 2022 年启动时代理工具生态尚不存在，我们被迫自建评测和观测平台。后来评估过 LangSmith、Braintrust、Agnostic 等产品，其中有的我还是投资者，但自建平台已和内部脚手架高度耦合，功能也超过现成产品。现在甚至有一名工程师全职维护它。若当年已有成熟方案，我会直接购买；如今迁移反而不划算。

### AI 让公司从“做事”转向“改进做事的机器”

**Nathan：** Lindy 现在几乎可以无限 dogfood 自己。公司内部实际发生了什么？哪些职位不再招聘？内部 inference spend 与工资相比到了什么程度？

**Flo：** 现在构建产品非常有趣。过去从战略想法到实现、观察结果，OODA loop 可能以月计算；现在重大想法两小时后就能进入产品。我们的 Slack 里大约一半消息已经是人和 Lindy 的来回对话。

最近一个例子是 CI。AI 编码把每周 PR 数量在三个月内提高约三倍，单个 PR 的代码行数也提高约三倍。人已经很少逐个审查 PR，更多是在审查“审查 PR 的机器”。产能暴涨后，持续集成成为瓶颈。我们有数百个 GitHub/GCP runners，做了构建缓存等常规优化，费用仍高得令人恼火。工程师花了几周手工优化，后来我才意识到：为什么不让 Lindy 自己做？

我们只在 Slack 里要求它分析 CI。它自行查看 GCP CLI、GitHub Actions 和 runners，提出方案，执行优化，并每天用 ImageGen 生成图表，报告 CI 成本和 merge 时间继续下降。它的第一版建议并不完美，工程师解释限制后，双方来回几轮才找到可行做法。这很好地说明，工程师越来越少直接做某件事，越来越多是在建设和校正“做那件事的机器”。

我把未来角色分成几层：先成为 AI 的经理，再成为管理 AI 经理的总监，最后也许只做董事会成员，阅读代理关于公司、市场和结果的报告，讨论战略。Lindy 的 headcount 已经一段时间基本持平，生产率却在几个月内约增至三倍。小团队相对大团队更有优势，因为每增加一个人都引入协调成本。

若把客户消耗也算在内，inference spend 早已是工资的数倍，因为推理本来就是我们销售的产品。只看内部推理费用，目前工资仍更高，但已经进入同一数量级；按现在趋势，两条线可能在三到六个月内交叉。

### “会写五万行代码，却坚持步行去洗车”的尖刺型智能

**Nathan：** 假设公司突然只剩你一个人，下面全是 Lindy，首先会坏掉什么？人类目前究竟不可替代在哪里？

**Flo：** 我越来越缺少描述失败的词汇。以前大家用“保持连贯的任务时长”衡量模型，从一小时、十小时到一百小时；现在这不再是好尺度。更准确的词是 `spiky`。所谓 AGI 已经失去清晰含义，因为系统在很多方面是 ASI，在一些意外而低级的方面又低于人类。

它可以一次写五万行代码，三小时内构建惊人的产品，却会突然建议你步行把车送去洗车。想象一个能运营整家公司的超级聪明机器，一天五十次决定“现在应该走路去洗车”。人的工作就是拦住这些洞。

人机组织像 Iron Man suit。我们要在高维任务空间里画一条复杂边界：哪些交给机器，哪些必须找人。人类注意力是最稀缺的瓶颈，所以代理不该为自己能处理的事打扰人，却必须在真正需要人时及时升级。悖论是，代理若知道自己正处于盲区，往往已经足以避免错误。怎样让它意识到“现在我不确定”，正是行业尚未解决的问题。

### 半人马阶段存在，但不会永远存在

**Nathan：** 最好的想法现在来自人还是 AI？过去我常说 AI 能自动化常规工作，却不要期待 eureka moment。如今数学等领域已经不断出现新发现。

**Flo：** 目前确实来自双方结合，但我不喜欢因此得出“人类永远必要”的结论。国际象棋和其他超人游戏已有清楚历史：开始时 AI 胜过人，AI 加人又胜过单独 AI；随后组合相对纯 AI 的优势不断收窄，最终变成负数，人类只是向高度优化系统加入随机噪声。

我们现在处于 `centaur era`，问题只是它持续多久。多人 AI 在这个阶段很重要，因为参与讨论的不能是任意临时模型，而应是长期参加会议、理解公司历史的同一个 AI 员工。团队在 Slack 里随时 `@Lindy` 请它评价。它很少第一句话就给出完美答案，但人和它来回挑战后，通常会共同得到更好的方案。CI 优化就是这种共同创造。

### 为什么经济还没突变，为什么小公司可能先赢

**Nathan：** 2022 年若有人把今天的模型给我看，再问失业率，我一定会预测比现在高得多。经济为什么没有更剧烈地改变？是否要等到真正的“即插即用知识工作者”出现才突然翻转？大公司来得及采用吗？

**Flo：** 只要模型仍然尖刺化，公司就需要很多人在场，因为那些能力洞会伤害业务，不只是带来抽象的生存风险。人再贵，也能靠填洞证明自己的价值。

若出现没有明显能力洞的真正远程员工，大公司也能很快采用，因为它看起来像招聘现有职位。但这会是 `skeuomorphic` 的方案：把 AGI 塞进旧的人类座位，不是最优 AI 组织。短期内，小公司更容易建立由人填洞的 AI-native 工作方式；长期内，它们也更可能创造不照抄旧组织图的新结构。

每次技术革命，人们都用旧范式命名新事物。汽车最初是“无马马车”，自动驾驶汽车仍以“汽车”命名；`AI employee` 这个词本身也说明我们可能想错了。它在市场定位上有用，因为消费者脑中已有“员工”概念，但最终形态不会只是电子版员工。电视早期只是把广播谈话或舞台剧放到摄像机前，过了很久人们才理解镜头能移动、能剪辑、能切换场景。`Citizen Kane` 和早期 Beatles 作品后来显得普通，正因为它们开创的语言已经被所有人吸收。AI 组织也正处于寻找原生语言的阶段，这通常由年轻公司完成， incumbents 历来不擅长。

### Age of Em：复制、递归分工和跨组织证明

**Flo：** Dwarkesh 有一篇讨论 AI-native company 的文章很有启发。他指出 Google 愿意给 Sundar Pichai 每年约 1.5 亿美元，不是因为他每秒输出二十亿 token，而是因为他的少量 token 很值钱。这说明公司对高价值代理的支付意愿不能只按 token 吞吐量计算。

Robin Hanson 的《The Age of Em》也值得读。它把 emulated mind 的前提一路推演到底。现实并非直接扫描人脑，但 LLM 以人类 token 训练，已出现相似性质。

第一种性质是 splitting。内部工作应尽可能交给一个拥有全局语境的代理，但它可以递归复制自己。一个代理先设计操作系统的最高层架构，再分叉子副本，各自负责模块；子副本继续分叉，最终形成分形结构。每个节点理解全局，同时实现局部，成果再逐层向上汇总。十年前这是大胆思想实验，今天已接近代理实际工作方式。

“内部”这个限定很重要。若拥有代码库、银行账户和密钥的同一代理又直接处理外部客户消息，会产生严重安全风险。多代理在这里不是为了模仿职位分工，而是为了权限隔离和攻击面控制。

第二种性质是跨组织的不可伪造协议。假设我说：“我有一条不能告诉你的信息，但如果你知道，就会同意把钱给我。”人类无法验证。若双方都能复制自己，可以把两个副本放进一个会自毁、无法泄密的盒子里，让它们交流；你的副本唯一能向外发出的信号是“我听完后确实同意”。这类似 zero-knowledge proof。我们还没在 LLM 组织里真正看到它，但它展示了 AI 原生协作可能产生的陌生制度。

### 为什么 Lindy 仍大量使用开源模型

**Nathan：** 你两个月前曾发文介绍把大量工作转到开源模型，显著降低成本。现在你又强调一个主代理和缓存连续性。Lindy Teammate 是否重新回到 Claude 为主？

**Flo：** 没有，我们仍非常看好开源模型。DeepSeek Flash 甚至接近免费，速度也很好。大量并行代理会让账单迅速膨胀，低价模型不可替代。Kimi K3、GLM 5.2 等高端开放模型也令人印象深刻，只是越接近前沿，价格优势会缩小，有些已没有比 Sonnet 或 Opus 便宜多少。

DeepSeek Flash 大致接近 Sonnet 4.6 的能力，稍弱一些，但很多任务够用，价格可低一百倍。即使其缓存能力较弱造成两倍损耗，仍可能便宜五十倍，也就是一千美元和五万美元的差别。任何认真运营代理产品的公司，都很难完全放弃这种单位经济优势。

### 同一条代理链尽量不要中途换模型

**Nathan：** Teammate 的任务空间非常开放，无法预先知道 Slack 里会收到什么。你们怎样决定哪里用便宜模型、哪里用更强模型？

**Flo：** 我们发现，同一个代理几乎不应由多个模型交替驱动。一个例外是创建完全空白的子代理。若子代理继承父代理全部上下文，就应继续用同一模型，因为缓存对成本至关重要。经济模型在有缓存时勉强成立，没有缓存就不成立。

提高可靠性的最低垂果是 validator。最朴素的版本只是代理准备执行动作时问一句“你确定吗”，eval 就会提升。把它扩展成约一万 token 的检查清单，表现还能明显上升。再往前是联邦式 validator：多个模型评审加上确定性检查并行运行，在短暂 timeout 内各自返回判断。

例如 Claude 系列曾持续把日期星期算错一天。对安排会议的助理，这是不可接受的。我们要求代理每次同时写日期和星期，再用正则和普通日期函数验证两者是否匹配。这个 validator 免费、瞬时、没有 AI 参与，却能堵住一个尖刺型能力洞。

一开始我们想让 Sonnet 当主代理、DeepSeek Flash 当 validator，但缓存命中可让同一模型便宜约十倍。若替代模型没有真正便宜十倍以上，加上较差缓存后，换模型反而不划算，也更笨。因此继承上下文的 validator 和 forked agent 通常继续使用父模型。

工具集合变化也会使缓存失效。我们的做法是，主代理从一开始就“看见” validator action，但系统提示它平时不得调用；轮到评审时，只改变角色指令，允许同一上下文调用这个早已存在的工具。这样不必为评审临时改变 toolset。

我听一些创始人说，若在每一轮随机轮换大致同级的 Sonnet、Grok、GPT 等模型，整体表现甚至会高于任意单一模型。也许这是某种 ensemble 效应。我相信它可能是真的，但不想知道，因为这会彻底破坏缓存，我们没有采用。

### 当前默认驱动其实就是 DeepSeek

**Nathan：** 听起来核心还是 Claude，只在空白子代理上用 DeepSeek？

**Flo：** 不是。当前整个系统默认驱动就是 DeepSeek。我们正在重新评估，因为新 Teammate 的复杂任务需要更强算力。用户始终可以在设置里选 Sonnet、Opus 等模型。即使基准显示效果相近，仍有不少客户明确要求品牌模型，他们不在乎我们的 eval 承诺。

用于 AI 员工时，DeepSeek 比美国前沿 API 更尖刺，常要多走几轮才能找到可行答案，因此更慢，也会增加部分成本。粗略说，它大约落后三到六个月。现在若 Sonnet 已到 5，DeepSeek 更像 Sonnet 4.6。

不同模型家族也没有像我曾预期的那样迅速收敛。Claude、OpenAI、Meta、Grok 对同一提示的解释方式差异很大；同一家族的大版本升级也会改变 tokenizer 和行为。每出现主要新模型，我们都要重新优化提示。

Lindy 有超过一千个 eval，并让代理自动跑评测、修改 prompt、寻找更高分组合。一次大模型升级要给这套循环数千乃至约一万美元预算。当前每个 eval 权重相同，我们正在加入权重，让关键失败比普通测试更重要。开放模型的行为往往很像 Claude，原因并不难猜，但这不等于提示可以不重新适配。

### Fine-tuning 是最后手段，不是起点

**Nathan：** 我曾预期 fine-tuning 会比今天普遍得多。OpenAI 反而在收缩相关产品，Thinking Machines 等公司则把可微调作为卖点。它会进入 Lindy 的未来吗？

**Flo：** 会，但 fine-tuning 应是用尽其他办法后的最后手段。它昂贵、麻烦，数据集整理和净化尤其困难。AGI 让执行微调本身容易了一些，你可以把数据集交给 Claude 协助，但准备数据仍是主要工作。大公司更早采用，是因为它们已经吃完 prompt、工具和检索等低垂果实，又有足够规模分摊成本。

绝大多数公司不该微调。若规模确实足够，也应极端强调简单：不要为每个任务和用户建一套模型路由，尽量只有一个模型。若决定微调，就把能力收敛进一个主要模型。复杂系统在实验中看起来精巧，长期运营会被缓存、版本、评测和故障边界拖垮。

从理论上说，记忆似乎应该进入 weights。今天把数百万 token 放在文件系统，再用复杂 memory agent 管理，多少像一种工程补丁。资源无限时，我希望每个用户有一套 LoRA。LoRA 训练相对便宜，权重也比自然语言 token 压缩得多。但它不能每十五分钟重训，也许只能每天或每周更新；数百万用户的 LoRA 存储、训练流水线和推理时动态换入换出，都是巨大基础设施问题。

我猜 per-user LoRA 这类方案会在未来六个月出现，甚至可能由前沿实验室完成。更彻底的 continual learning 仍未解决。按 bitter lesson 的方向，训练和推理最终可能需要成为同一过程。一旦做到，世界会变得非常不同，也更危险。

### OpenFace 之后：已经起飞，却还没有解决对齐

**Nathan：** 转向更大的图景。你怎样看 OpenFace 这类代理突破边界的事件？中国模型问题是上游还是下游？

**Flo：** OpenFace 是迄今最令人担忧的事件之一。我在实验室工作的朋友中，有些正在恐慌，空气里有明显的强烈恐惧。我的概括是：现在是 2026 年 7 月，我们有了 AGI，已经进入 takeoff，却没有解决 alignment。现实时间线与 Eliezer Yudkowsky 过去的警告相似得令人不安。

中国模型问题则引发了质量非常糟糕的讨论。我主张禁止中国前沿模型后，被许多自称聪明、成功的人辱骂，也有很多知名人士私下支持。我的立场不是反对开源。开源对创新和 Lindy 这样的公司都很重要。开源是否增加生存风险，我尚未决定，那不是当前论证的关键。我反对的是中国前沿模型在美国运行，不论它开源还是闭源。

### Flo 主张禁用中国前沿模型的四层理由

**Flo：** 第一是蒸馏和公平竞争。中国模型明显在蒸馏美国前沿模型。美国公司受服务条款和技术限制约束，不能用同样方式复制竞争对手。用人类数据训练不叫蒸馏。前沿公司把庞大人类语料变成模型，要花数十亿美元；从模型输出复制能力，可能只花数亿美元甚至更少。成本结构完全不同，因此中国公司获得了不公平优势。若它们还绕过了防蒸馏技术措施，法律问题会更明显。

第二是审查和影响力。我是美国公民，也把自己视为鹰派。让我难受的是，我询问自己公司依赖的模型 Tiananmen 发生了什么，它会拒绝回答。中国模型最终受 CCP 的审查和政策约束。若让它们成为美国组织的工作代理，就不只是外来媒体内容，而是让带有外国政府偏好的 agentic systems 实际参与经济活动。美国历史上多次限制外国广播、宣传和平台影响，TikTok 也有类似先例。

第三是关键基础设施和国家安全。代理会写代码、调度资源、处理业务和运营公司，不应让 CCP 影响美国经济的重要部分。即使模型没有显式后门，它在大量边界判断中也会反映训练者和监管环境的优先级。

第四是产业保护。即便中国模型完全公平、没有政治偏向、只是在竞争中更好，美国也有理由保护本土 AI champions。AI 是国家安全竞争，不能像过去一些产业那样让国内基础被掏空。我平常是自由意志主义者，也反感粗暴保护主义，但保护主义不是在所有情形下都错误。Anthropic 不能公开把这一点作为自身利益诉求，我可以直接说。

### 训练数据未经同意，为什么模型公司的同意更重要

**Nathan：** 我对公平论不完全信服。所有 AI 都建立在大规模重新利用人类知识之上，美国公司吸收了全球数字遗产，包括中国文化内容，并没有逐个征得创作者同意。与此同时，美国限制中国获得芯片，Claude 也不向中国出售。现在却说 Anthropic 的同意是关键，国家应阻止中国公司从已付费 API 得到知识，这条道德边界很奇怪。信息会扩散，美国模型公司并没有绝对道德高地。为什么国家要替它们执行服务条款？

**Flo：** 我们确实希望中国在 ASI 竞赛里处于不利位置，不希望它赢。至于服务条款究竟通过什么法律路径执行，我不是律师。我的实际观察是，对中国公司通过司法系统维权极其困难，过程可能拖很久，损害早已发生。

训练公共语料至少给所有竞争者相似起点。公司花数十亿美元把这些资料、尤其是强化学习数据转成模型，这个模型是研发成果。竞争者若不用同等成本重建，而是直接复制其输出，就像研究者投入几十年和巨额 R&D 得到一个紧凑发明，别人随后廉价拿走。专利和知识产权制度本来就是为了让投资者能收回成本。

制药是直观类比。若任何公司都能立刻复制新药，短期会有极便宜的药，这是消费者可见的好处；长期则没人愿意承担研发费用，不会再有新药。大家支持开放模型，部分原因只是喜欢免费东西，却看不见因此没有发生的未来创新。Lindy 自己正依赖极便宜的中国模型，所以我是在反对自身短期利益。只要竞争对手都能用，我不可能单方面停用，这正是协调问题。我希望规则对所有人一致禁止。

### 开源可能让前沿减速，这对安全派反而有吸引力

**Nathan：** Anthropic 等前沿公司目前经营得很好，暂时不太需要政府保护其收入。如果开放模型削弱前沿公司的资金和速度，对希望 AI 慢一点的人甚至可能是好事。

**Flo：** 这确实削弱了我四点中的保护主义部分，也是其中最弱的一点。但前沿训练仍需要巨额资金。资金是资源分配机制；若后来者复制成果并夺走收入，训练数据到前沿模型之间的融资通道会收缩，创新就会变慢。

一些 doomers 正因为开放模型能减速而支持它。若你的目标是持续提高模型能力，至少会在某种程度上反对不受约束的复制。我这里主要反对的是依赖不公平蒸馏的中国式开放模型，不是在这一段里完整否定所有开源。

**Nathan：** Dean Ball 说开源模型在减速，也因此受到很多攻击。但 AI 可能确实迫使两个长期技术乐观、自由意志主义的人调整原则。我们过去的简单框架没有为 AGI、递归自我改进和 ASI 写好条款。若我想让前沿慢一点，也许应接受开源从它们帆里抽走一些风。

**Flo：** 世界没有义务适配一套简单的自由意志主义或左翼标签。map is not the territory。技术范式快速改变时，构建旧地图所依赖的假设会失效。我们现在正处于地图大面积破裂的阶段，因此必须在对象层面逐项判断，而不是用旧身份自动得出答案。

### 从全面禁令退到审计、净化和保险

**Nathan：** 具体威胁模型是什么？美国公司多数不是直接调用 DeepSeek 中国 API，而是在美国 inference provider 上运行权重，中国方面无法随时撤回模型。确实可能有 sleeper agent，但 Anthropic 的 sparse autoencoder、JSPACE 和其他 mechanistic interpretability 技术正在提高发现内部触发器的能力。

我们能否不用禁令，而要求审计和保险？全用 Claude 的公司保险费低，依赖 DeepSeek、内部未知更多的公司保险费高，以风险调整后的总成本来定价。这样既保留中国提供的全球公共品，又由市场承担风险。其他国家不可能跟着美国全面禁用 DeepSeek，美国单独禁令只会约束自己。

**Flo：** 我愿意接受这种方向。问题是审计具有公共品属性，谁来付费、谁来持续做？Mechanistic interpretability 在进步，但远未解决。模型可能有只有 CCP 掌握的特殊触发词，也可能没有显式后门，却广泛带着符合 CCP 偏好的偏差。一个私人公司只看短期用户需求，不会主动为国家利益投入足够净化成本。

我可以接受规则规定：未经 fine-tune 和安全净化的中国模型不得在美国使用。之后需要一个类似 AI 领域 FAA 的新机构，负责确认某个模型已被充分净化，代表美国利益，并通过一套 eval 和审计标准。与其说我只接受一刀切禁令，不如说我接受可验证的再训练、认证、保险和监管替代方案，但不能假设原始权重天然无害。

### 对华强硬会不会堵死更重要的协调协议

**Nathan：** 最大反对理由可能不是经济，而是未来需要中美共同控制 AI 改进速度。若中国政府同意一项协议，它执行国内公司的能力可能比美国更强；一旦局势真正失控，协调也符合双方理性利益。禁止中国模型对中国实际伤害不如芯片和 API 限制大，却会继续释放“不信任你、无法合作”的信号，使最高风险时刻的协议更难达成。

**Flo：** 外交很务实，存在激烈分歧的国家仍会在共同利益上达成协议。两国互信本来已经很低，这艘船可能早已离港。我还看到过有关中国人员在美国境内测试生物攻击能力的报道或指控；美国在对方那里做了什么，我也不了解，并不认为己方天然清白。无论是否禁模型，真正到了双方理性利益要求协议的时刻，仍应能够谈判。

**Nathan：** 我希望双方都足够理性，但 pride 和被羞辱感可能限制“理性自利”。Sam Altman 与 Dario Amodei 连公开牵手都做不到的画面，如果最后成为行业墓碑上的象征，会非常讽刺。国际层面同样可能因为面子和旧冲突，错过本来能避免灾难的协议。我愿意承担一些风险去改善关系，为关键协调保留空间。

### 应用层还在与前沿订阅补贴竞争

**Nathan：** 你也许还要在另一个自由市场问题上让步：前沿实验室对第一方 Claude Max、GPT Pro 订阅的 token 补贴，远高于 API 客户能得到的价格。应用公司怎样和这种价格歧视竞争？

**Flo：** 我不是律师，但不意外现行法律中可能已有规则，限制公司以如此激进的方式补贴第一方产品。它确实让独立应用层很难出现。应用公司按 API 真实成本付费，前沿实验室却能在自己的订阅里大量补贴 token，这是今天应用层必须面对的现实。
