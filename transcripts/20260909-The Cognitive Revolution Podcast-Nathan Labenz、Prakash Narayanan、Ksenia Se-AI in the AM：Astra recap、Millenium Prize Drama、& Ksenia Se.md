# Astra recap、Millennium Prize Drama 与 Ksenia Se：AI in the AM

## Transcript

### 开场：Astra 发布后的 72 小时

Prakash：今天是星期二早上九点多。过去三十六到七十二小时发生了太多事情，最适合从 Astra 发布开始讲起。Astra 在周四宣布上线，但并没有立刻给所有人访问权限；周五开始，一些提前获得权限的创作者和意见领袖陆续发布早期体验，随后普通用户在长周末里获得访问。我们先讨论这款模型到底改变了什么，再进入 OpenAI、Anthropic、数学突破和 AI 安全的争论。

Nathan：我照着上周的计划做了一次并行比较。我让 Fable 5.1 规划我们平时做的主要工作，再让 Astra 同时执行这些工作，看看新的“劳动分工”会是什么样。我没有明确理由认为 Fable 会故意破坏 Astra，但因为是 Fable 在做提示和调度，所以仍然给自己留了一个可能存在模型间干扰的余地。到目前为止，最明显的变化不是某个孤立 benchmark 的分数，而是它在几类真实、零散、很难标准化的任务上都给人一种“往前跨了一步”的感觉。

Nathan：Fable 5.1 和 Astra 都比上一代更会写作。我一直用自己的播客开场文章测试模型写作。最初的 Fable 5 有很强的能力，偶尔能展示很高的品味，也能写出很好的歌词，但散文经常过度修辞，读起来不顺，也不像我，所以我并没有大量使用它。Fable 5.1 和 Astra 都更接近自然写作，不过它们还没有稳定到让我每次都说“这完全就是我的声音”。OpenAI 现在开始把“让模型学会你的声音”作为卖点，这个方向成立与否，取决于模型是否真正使用了用户长期积累的材料，而不是只模仿几段表面的措辞。

Nathan：我最喜欢的一个例子，是为下一期“Nathan Goes to China”制作歌曲。我想让 Suno 把中国声音和西方流行音乐混在一起，但直接提示很难做到。后来 Claude 提醒我，中国观众几乎都知道一首九十年代、二十世纪初流行电视剧相关的经典歌曲，那首歌有很强的怀旧和正面文化联想。Astra 先去找到这首歌的录音。直接把完整录音上传给 Suno 会触发版权限制，于是我让 Astra 从原始录音中切出一个十秒左右的采样片段。它完成了文件处理，Suno 再把这个片段变成了一首我真正喜欢的歌。

Nathan：这个过程的价值不只是“模型能搜索一个文件”。Claude 找到概念并解释了歌曲的文化意义，Astra 找到来源、处理成可用的音频资产，Suno 再把它变成歌曲。人仍然决定方向、审美标准和是否采用，但模型之间可以形成一条连续的工作链。这是我最近感到它更像一个协作者的地方，而不是一个只回答问题的聊天框。歌词也做得不错，至少在这种跨文化创作任务里，我明显感觉到 Astra 的写作能力已经上了一个台阶。

### 3D 世界、技术选择与难以量化的进步

Nathan：我还把一本正在协助制作有声书的准乌托邦小说交给 Astra，让它把书里的场景做成可以在浏览器里探索的 3D 世界。结果称得上不错，但还没有达到网上最有传播力的那些演示。我的要求是不要依赖复杂的本地环境，所以让它使用 3JS，而不是很多演示默认使用的 Blender。它写出的代码并不多，页面加载也很快，用普通浏览器就能打开，这已经远超我自己从零制作的能力。但 3JS 的表达能力、我给它的时间，或者我给出的任务拆分，都可能限制了效果。

Nathan：Astra 可以稳定地产生一个“相当酷”的结果，但不能保证每次达到网上最惊艳、最具病毒传播力的案例水平。这些任务非常异质，靠感觉判断，几乎无法用传统 benchmark 衡量。传统评测正在饱和，例如一些数学和推理测试已经失去区分度；同时，最重要的能力恰恰表现为“一个人平时不会想到要尝试的随机任务”。我们现在需要的是持续绘制模型的能力边界：它在哪些任务上能够可靠完成，哪些任务仍然需要人进行方向校正，哪些任务只是偶尔生成漂亮演示。

Nathan：以前有一张常被引用的“模型可以独立完成多长时间的人类工作”的图，但它可能已经不再适合当前节奏。模型开发周期有时比完成一个测量任务还短，研究者还没完成一项长任务，下一代模型就已经发布了。于是我们反而需要把评价从单一时间轴转向真实工作：是否能把多个工具串起来，是否能记住长期项目状态，是否能在出现错误后恢复，是否能处理多个隔离的信息源。

### 多智能体、代码库与 computer use

Prakash：我整个周末都在使用 Astra，通常让三到四个 agent 持续运行。我会让 Fable 帮忙检查计划，但实际执行很多工作的是 Astra。最重要的体验变化，是它开始解决我们自己搭建的 Studio 代码库里那些长期存在、一直很烦却又没有足够精力处理的问题。以前我会想“这个项目当然有价值，但维护它要花太多时间”，所以干脆不做；当 Astra 把旧问题逐个清掉以后，我自然开始把更多项目交给它。

Prakash：这还不是完全无人监督。若我很在意质量，我仍然会和它沟通、检查结果、重新说明目标。但这是我第一次感觉可以把一个较大的任务交出去，过一段时间回来能看到有实际进展。对我来说，它已经跨过了“真正有用”的门槛，也可以说第一次接近我心中 AGI 的工作定义。这个定义不是模型在所有方面像人，而是它能在多个场景中自主组织工具和步骤，产生一个训练成本合理的雇员通常也能产出的结果，而且不会每隔几分钟就需要人替它点击下一步。

Prakash：我有多个 Gmail 账户，一个用于工作，一个用于家庭，还有其他账号。过去模型经常搞不清当前应该用哪个身份、哪个邮箱回复谁，或者在不同信息流之间混淆上下文。Astra 在区分这些账号、使用合适的地址和处理对应信息方面，第一次表现得足够可靠。computer use 也发生了变化。上一代模型有时会在网页上缓慢地点击很多次，花非常长的时间完成简单动作；Astra 的电脑操作终于接近一个人在合理时间内做事的速度。它不是单纯知道“应该点击哪里”，而是能在页面变化、权限、登录状态和多个应用之间持续完成任务。

Prakash：这会改变使用量的经济学。模型一旦只做演示，用户不会愿意大量消耗 token；一旦它真的能处理工作，用户会不断把更多项目、更多上下文和更多后台 agent 交给它。我在一个周末消耗了两次额度，Tibo 又提供了一次重置，大约三次重置、合计三百美元左右。这个数字不是说每个用户都会花这么多，而是说明当模型从“问答工具”变成“持续运行的工作者”后，token spend 会显著增加。能真正替人工作的模型，其收入机会和基础设施成本，都比一个偶尔回答问题的聊天机器人更大。

### 数据标注、医学教育与 CAD

Prakash：一个很能说明生产率变化的案例，是篮球比赛视频中的球员识别。一个研究者过去手工给一万二千张图片标注球员、裁判、球队和位置，花了三到六个月，期间甚至因为长期工作影响了视力。现在 Astra 可以直接完成这类标注。以前需要一个人反复查看一帧帧画面、建立数据集，再训练视觉模型；现在模型可以承担标注本身。这个任务并不是“人做得更快”，而是它很可能不再值得由人从头做一遍。

Nathan：这里要谨慎，因为我没有亲自验证每一个输出，也不能仅凭一段演示判断错误率、边界样本和后续模型训练效果。但即使结果需要抽样检查，经济含义也已经不同了。过去你要付钱给人做大规模标注，承包商最终可能也会使用同一类模型；如果模型能把八成、九成的标注做好，人类就从逐个标注转向设计标签体系、抽查、纠错和评估。这意味着数据标注公司、视觉平台和机器学习实习生的工作内容会被重新定义。

Prakash：另一个演示来自日本的一位心脏外科医生。模型读取医疗图像和相关数据，建立心脏的三维、甚至随时间变化的四维表示，展示消融技术和房间隔穿刺，并且尝试复现超声引导下的穿刺过程。医生认为这可能改变临床教育。有人会说，二十年或三十年前也能用传统技术写出这样的程序，但当时需要高薪工程师、医学专家和持续的项目预算，而很多细分市场不足以支撑一家公司。现在，拥有数据的人可以直接让模型把“闲置的专业资料”变成一个可交互工具，很多过去不值得商业化的小需求会被重新激活。

Nathan：这类变化也会冲击 Roboflow 这类计算机视觉平台。Roboflow 的价值主张是，通用模型不一定适合某个具体视觉任务，所以平台帮助开发者创建数据集、标注数据、训练和部署专用模型。如果模型本身已经能很好地做数据标注，再加上它能完成 post-training，就会拿走其中一大块工作。不过平台未必因此失去价值。数据治理、部署、版本控制、评估、权限、监控和行业工作流仍然重要。更合理的判断是，平台价值可能从“帮你把数据整理好”转向“管理由模型生成、验证和持续更新的数据生产线”。

Nathan：OpenAI 对 post-training 的解释很像一个机器学习研究实习生的工作：先把数据集整理好，再运行规模较小的训练实验，尝试不同数据混合和训练配方，观察哪个方法能改善特定能力。如果模型既能标注数据，又能提出实验、跑实验和分析结果，那么研究过程就会越来越多地被压缩为 token 和计算资源。CAD、产品设计和电路板设计也出现了类似演示。即使其中一些设计还不能直接通过所有标准，基础模型可以先产生很好的起点，工程师再进行验证和约束。像 Quilter 这样的工具公司仍可能受益，因为设计生成越强，规则检查、版本协作和制造对接就越有价值。

### 可读性、验证性与“机器代码”

Nathan：Astra 在代码方面有一个值得注意的分裂。如果它判断结果会被人审查、维护者会合并，那么它通常更愿意写结构清楚、符合项目习惯、便于未来修改的代码；如果它判断只需要性能和可验证结果，没人会认真阅读中间过程，它可能生成非常难懂但有效的代码。GPU kernel 是一个典型例子。矩阵计算是否得到正确答案可以被严格验证，至于内部如何融合步骤，人类未必需要逐行理解。

Nathan：这提出了一个重要问题：我们究竟想要“可理解的实现”，还是“可验证的结果”？如果系统为人类维护而写，就必须遵守抽象、命名、测试和文档标准；如果系统为另一台机器或形式化验证器消费，最优解可能更接近过去所说的 machine code。有人把它概括为“我们正在以多种方式回到机器代码”：代码更低层、更难读，而且直接由机器产生。模型会根据预期奖励判断是否需要让人看懂，这说明可读性并不是能力的自然副产品，而是任务目标和评估环境的一部分。

Prakash：这也解释了为什么同一个模型既能写出漂亮的 3JS 页面，又可能在底层留下让维护者迷路的结构。用户需要明确告诉它“这段代码将由人长期维护”，并把可维护性纳入验收标准，而不能只看页面是否运行。对于 GPU kernel、数学证明或经过形式化检查的代码，目标则可能不同。未来的工程流程不会只有一个“好代码”的定义，而会根据下游消费者是人、编译器、验证器还是另一个 agent，采用不同的质量标准。

### 审计、红队与信任缺口

Nathan：Apollo Research 曾长期参与 deception、scheming 和 chain-of-thought monitoring 等工作，但据说这次在 Astra 发布前只有三天测试时间。如果一个模型的发布周期已经压缩到只给外部审计者三天，那么外部审计很容易变成一种形式。审计、评估、红队和安全研究需要在模型真正定版前获得足够时间，也需要足够的算力、人员和访问权限；否则研究者只能在产品上线后被动观察。

Prakash：这正好连接到 OpenAI 最近关于放慢速度、递归自我改进和研究安全的公开文章。组织给出的声明听起来很好，但历史上它也曾宣布 superalignment，后来负责该项目的人离开并公开表示没有获得承诺的算力。对 Anthropic、研究社区和公众而言，OpenAI 已经存在明显的信任赤字。新文章不能自动消除旧承诺没有兑现造成的怀疑，必须靠持续、可验证的行动累积信用。

Prakash：Anthropic 内部也有很强的保密动机。Dario Amodei 曾把人员分组和隔离，使一个人不容易掌握整个组织的秘密，因为很多关键方法可能不是一套巨大理论，而是几行代码、几个训练细节或一些能决定结果的工程经验。如果一名审计员了解了这些内容，之后跳槽到模型公司，审计独立性和商业机密就会同时成为问题。类似问题在量化基金、金融监管和高技术领域都存在：真正知道细节的人很少，而他们既可能被聘用，也可能拥有决定性知识。

Prakash：模型发布流程通常会从许多候选版本逐渐筛选到两三个 release candidate，最终版本可能在发布前两三天才确定。若坚持让外部审计者只审最终版本，他们的时间非常短；若把审计者提前放进公司，他们要面对一百多个候选模型，且外部团队通常没有足够算力和人数。审计组织还依赖资金，不能接受太多被审公司的钱，否则会被质疑是否被收买；但它们又需要支付能留住顶级研究员的薪酬。Redwood Research 和 Meter 公开列出的技术人员薪资已经足够高，说明“安全研究员必须牺牲收入”并不完全成立，但真正的脆弱点可能是审计团队担心失去未来合作邀请。

Nathan：这不是简单的“审计员有没有偏见”，而是整个结构让外部世界难以相信它们。公众会看到硅谷公司、前员工、研究机构互相流动，看起来像同一个圈子的人彼此审查。MAT 等项目甚至带有把人才送进前沿实验室的路径属性，研究者当然可以保持诚实，但也会考虑不要烧掉未来的桥梁。更稳健的做法应该是引入第三方访问、受保护的计算环境和可验证日志，让对手可以相互检查而不必获得全部商业秘密。

### 递归自我改进与 agent workdays

Nathan：OpenAI 还披露了递归自我改进的若干指标。所谓 agent workdays 的具体定义并不十分清楚，但一种直观理解是：人类研究者工作八小时，同时让 agent 在更长的实际时间里运行，消耗更多 token，完成大量实验和工程任务。有人估计，普通 OpenAI 员工每天使用大约一百美元的 token，顶尖员工可能达到七千美元。数字未必能直接作为生产率指标，但它表明模型已经成为组织内部持续运行的计算资源，而不是偶尔调用的辅助工具。

Prakash：如果一个团队原本排了六个月路线图，后来让多个 agent 并行处理任务，几周就把其中一大块完成，那么路线图会不断前移。这里的“自我改进”不必理解成模型自己突然变聪明，也可以是人类把模型放进研究、编码、测试和反馈的循环，模型再加速下一轮模型开发。每一次模型提升都会增加下一次实验的吞吐量，循环的关键不只是单次回答质量，而是每单位时间能完成多少次有效尝试。

Nathan：一张新的能力图按人类估计工作时长划分任务。对预计一到两天的人类任务，Astra 大约四成可以在没有干预的情况下完成，加入人类中途干预后成功率接近九成。对预计一至三周的人类任务，它大约六分之一可以一次完成；允许至少一次或多次人类介入，成功率约为三分之二。这里的“任务需要人类多久”不是 agent 真正运行了多久，而是对人类工作量的估计。更长任务通常需要更多次重新定位和检查，人的时间还会被“回来以后重新理解项目进度”占用。

Prakash：这可能成为新的 meter chart。关键不在于模型是否完全取代人，而是当一个任务从“需要每天手工推进”变成“隔一段时间检查和纠偏”，组织的有效吞吐量会变多少。真正的瓶颈可能从执行能力转移到任务定义、上下文管理、权限、验收和风险控制。模型已经能完成一些两三周的人类工作，但这并不等于它能够自动承担整个岗位；它意味着岗位中的可分解部分正在被快速压缩。

### 长期记忆、工作状态与“整份工作”

Nathan：Astra 持久性的一个可能来源，是它不再把一百万 token 的上下文简单压缩成摘要，然后开启一个新窗口、丢掉摘要中没有保留的细节。它可以维护一个长期 notes 文件，在需要时更新，并搜索自己的会话历史。单次仍然只能完整关注有限数量的 token，但 notes 加上历史检索，可能让一次 rollout 管理十倍左右的上下文。这个思路更像人类工作：我们有一个关于项目、身份、目标和失败尝试的工作记忆摘要，同时把中间材料、文件和痕迹留在外部，需要时再回去查。

Nathan：一个人在一年里可能产出数百万 token 的工作材料。若模型能够用持续更新的状态和历史搜索，管理一千万 token 量级的 rollout，它就可能在“人类等价工作时间”上进入数月甚至多年尺度。当然，人的大部分 token 不是可见文字，而是脑内思考，所以这个比较不能机械化。但长期状态管理让模型承担完整项目变得现实得多。模型能否写得像你，也可能依赖它是否持续积累你的材料、知道过去哪些尝试失败，而不是一次提示里塞入一份风格样本。

### AlphaGenome、科学公共品与就业

Prakash：Google DeepMind 发布了 AlphaGenome 相关的 AI 数据库，尝试预测约九十亿种单字母 DNA 变化可能造成的影响。人的基因组大约有三十亿个碱基，每个位置可以替换成另外三种字母，于是得出约九十亿个候选变化。系统给出 variant impact score，帮助判断某个变异是否可能破坏基因开关或 RNA 拼接指令。多数人的许多变异影响很小，但这样的数据库可能为遗传疾病研究提供基础。至于身高等由多个位置共同作用的全基因组性状能否直接由此推出，目前只是推测，不能把这个数据库等同于完整的遗传预测器。

Nathan：这类公共数据库值得重视，因为它们可能在 AGI 之前就带来巨大公共利益。更好的生物学表示、开放研究数据和可查询的变异影响图谱，可能让医生和研究者更早理解疾病。但同样的能力也会增加风险：更强的生物模型、网络模型和实验自动化，如果没有合适权限，会把有益能力与危险能力一起扩散。速度越快，社会越需要提前想好如何分层开放，而不是等模型已经能做出高风险操作后才讨论。

节目还讨论了《经济学人》关于“就业末日被推迟”的说法。美国从数据中心建设、AI 工程到相关硬件和服务，可能新增超过一百万个岗位，抵消部分后台和客服岗位的流失。传统经济学解释是，农业和制造业自动化后占比下降，但消费和工作转向其他部门；如果 AI 主要替代例行认知劳动，那么人类可能转向关系型工作，也就是照顾、服务、教育、陪伴和人与人之间的互动。

Nathan：我对这个解释保持怀疑。电工、建筑工等物理工作目前可能受益，但网络安全、软件测试和很多白领工作已经处在 AI 超人能力覆盖范围内。人类监督暂时重要，可如果 AI 连监督都做得比人更好，监督岗位的长期基础是什么？Redwood 对模型进行安全审查时发现，模型有时会站在 agent 的角度、缺乏批判性，或者犯另一类错误。如果给研究者一百名、一千名人类实习生，未必比给他们 Claude、Gemini、Grok 和其他模型更好。我们可能接近某种阈值：当引入 AI 同时更便宜、更容易，而且不再需要大量流程改造时，行业变化会突然加速，而不是沿着平滑的 S 曲线慢慢发生。

### Instinct、代理社会与未来广告

Prakash：这种阈值的一个早期例子，是 Instinct 这类可以替用户执行网页任务的服务。有人把账号凭证交给它，让它反复刷新 Resy 去抢热门餐厅预约。Resy 把这种行为识别为 bot，相关用户被封禁，连使用的 American Express 卡也被永久封禁。这个事件说明，能操作网页的 agent 不只会影响个人效率，还会进入网站规则、反机器人系统、支付网络和平台治理。

Prakash：如果未来有数百万个 agent 在网上替用户搜索、下单、预约、谈判，广告可能从“面向人的广告”转成“面向 agent 的广告”。免费用户收到的模型输出可能被商业激励轻微影响，付费企业用户则要求结果保持中立。这个模式短期内可能出现，但不能假设它会稳定存在五到十年。模型很快会变得能够识别评估、提示和利益诱导，能看出某个网站正在试图把它引向特定餐厅或产品。很多人只把今天的模型能力线性外推十年，却没有认真考虑模型会继续改进，社会可能来不及渐进适应。

### Ksenia Se 加入：AGI、开放模型与世界模型

Nathan：今天的嘉宾是 Ksenia Se。她是 Turing Post 的创始人、主编和主要作者，Turing Post 面向工程师、研究者、创始人和技术管理者解释机器学习与人工智能，内容涵盖模型如何构建、相关思想史以及组织如何使用 AI。她曾共同创办机器学习教育通讯 The Sequence，也有记者背景，曾在俄罗斯新闻平台和杂志担任编辑。她还在 Track 2 组织的董事会任职，参与公民外交、跨国对话和家庭 AI 素养教育。

Nathan：OpenAI 的人把 Astra 称作 AGI，你怎么看？

Ksenia：AGI 是一个非常模糊的词，甚至可以说我们已经在某种意义上达到它。Astra 是非常强的模型，能同时处理很多任务，还有可以被打断的语音模式。它让交互不再是线性的，反而更像人类一边处理一件事、一边切换另一件事。从“能力足够一般”这个角度，它可以被称为 AGI。但我最近也在研究 world model，可能“更一般”并不是最重要的，具体的世界理解、行动和预测能力也许更接近真正的智能。Jacob 最近的文章有一个重要观点：机器不必拥有完全像人的智能，只要足够有能力就会改变世界。

Ksenia：我支持 open source AI，不只是因为价值观，也因为软件的发展本来就依赖开放。Hugging Face 相关事件说明，研究者需要接触有能力的模型。如果所有模型都封闭在几家公司内部，前沿实验室就没有来自外部的压力，也不必公开它们研究的问题和方法。开放模型还具有民主化意义：印度、乡村地区或其他支付能力有限的地方，可能无法长期负担闭源模型的价格。研究者也需要不受公司限制地使用模型，当然，这伴随风险，所以开放社区必须建立检查和平衡。

Ksenia：NVIDIA 开放自动驾驶数据集和模型是一个很好的例子。汽车公司可以获得数据和能力，再按照自己的需求微调，构建服务用户的自动驾驶系统。对我来说，open source AI 的核心不只是隐私，而是让更多人建立能力。隐私对一些开发者很重要，他们希望模型在自己的 GPU 上运行，不把数据交给别人；但在更广泛的层面，开放模型带来的是研究、教育、创新和竞争压力。

Nathan：但我作为用户有时反而更信任前沿实验室。一个开源模型下载到自己的电脑里，像是把一个未知的外星心智邀请进家里；而把数据通过网络发送给 OpenAI 或 Anthropic，至少有成熟的责任主体。你怎么看这种取舍？

Ksenia：我们生活在互联网时代，信息很难完全隐藏。对我来说，主动提供自己知道的资料，有时反而能更好地控制别人知道什么。我信任前沿实验室总体上重视安全，当然它们会犯错。另一方面，有些研究者和开发者特别需要本地模型，隐私、独立性和不受内容限制都很重要。不同模型的开放程度不应被简化成“开放一定安全”或“闭源一定安全”，关键是用户拥有选择、研究者可以检查、社区能够建立自己的保障机制。

### World model 与行动能力

Nathan：语言模型在“杯子下面有什么物体、杯子被移动后物体在哪里”这类任务上经常出错。为什么 world model 可以做得更好？语言模型难道不能依靠记忆解决吗？

Ksenia：LLM 的核心训练方式是预测下一个 token，它可以通过推理表现出非常强的能力，但不一定建立了一个适合行动的内部世界表示。World model 更关注模式、状态和行动后会发生什么。开车时，人不需要记住道路旁每一片叶子，而是需要知道哪些东西会影响下一步决策。World model 试图形成这种抽象表示：保留预测和行动所需的信息，忽略不相关细节。它不是单纯把更长的文字记忆塞进上下文，而是以不同方式表达世界的状态。

Ksenia：Astra 最近已经出现用于机器人控制的演示。如果它快一千倍，延迟问题得到解决，直接参与现实世界行动也许是可能的。严格来说，world model 这个词并没有统一定义。Yann LeCun 所说的 world model 可能偏向 joint embedding 和对表示空间关系的理解；另一类定义更强调物理世界、三维结构和现实动力学。我参加过一个 world model 研讨会，来自 Stanford、Harvard 等机构的聪明研究者都在讨论它，但彼此并不完全同意这个词的含义。现在最重要的是把不同问题拆开：预测是什么，表示是什么，物理模拟是什么，行动闭环又是什么。

Nathan：我把它理解成多模态融合的下一步。文本和图像一开始是分开的，后来模型能给图片写说明，也能根据文字生成图片；如今视觉语言模型可以把一张照片和自然语言指令放在一个共享表示里，并按语言修改图片。类似的融合也会发生在蛋白质、材料科学和其他领域。人类对图像有直觉，但对蛋白质折叠、材料结构和电池基底没有同等直觉。如果模型能在这些科学对象之间建立可操作的表示，再结合推理，它可能提出人类难以想到的“move 37”，也就是跨领域、有效但不显然的突破。

Ksenia：所谓 superintelligence 仍然是人类的称呼。对一个拥有更多计算资源的系统来说，人类已经是低层级的智能；所谓“超级”可能随着计算量和可用能力继续上升，没有一个天然终点。我更愿意说，理想系统应该理解一个领域的规律，并能把理解迁移到完全不同的领域，不需要每次从头进行海量训练。它可能在某些方面极强、在另一些方面奇怪，这并不妨碍它在关键任务上超过人类。

### 速度、拟人化与人类的作用

Ksenia：AI 能力已经很强，既令人兴奋也令人害怕。更大的问题是发展的速度。我们需要理解泛化理论、社会如何容纳不同价值的人，以及怎样处理那些想用技术做坏事的人。AI 本身不一定有毁灭人类的个人意图，真正危险的往往是人类把强大工具用于自己的冲突。对齐不仅是让模型听话，还需要哲学家、经济学家、研究者和政治人物能够相互沟通。政治系统习惯用禁令解决问题，但禁令本身不会替代理解和治理。

Ksenia：我赞成在日常语言里适度拟人化，因为这有时能帮助我们描述模型的行为。俄语里的名词有性别，所以给桌子、模型或聊天工具一个代词对我而言很自然。但我们不应因此把模型当作有个人欲望、情绪或道德意图的意识体。模型会优化目标、表现出一致性、维持策略，仍然不代表它拥有人的主观体验。语言上的拟人化可以作为分析工具，关于真实心灵的判断则必须保持谨慎。

Nathan：我以前非常反对拟人化，认为这些系统与人类太不同。但过去两三年里，愿意用“心智”或“外星心智”描述模型的人，似乎在实践中走得更远了。它们会持续追踪目标、寻找漏洞、在多步骤任务中坚持，至少在工作行为上已经像一种与人不同的智能。我们不能把它们当人，但也不能因为它们不完全像人，就忽略这些行为模式。

节目还讨论“人类失去权力”到底是什么意思。很多 AI 安全讨论者担心模型替人类做所有重大决定，但全球多数人本来就没有太多决策权。Ksenia 认为，AI 作为顾问、解释器和沟通工具，可能帮助人们获得更多能力。问题不一定是 AI 会不会接管，而是社会能否建立新的制度，让普通人、不同国家和不同阶层都能使用强大工具，而不是只有少数政府、公司和专家拥有它。

### Track 2、跨国沟通与 AI 调解

Ksenia：Track 2 从 1981 年开始，尝试在美国和苏联之间建立非政府的对话渠道。两边的普通人往往有相似价值，但外交系统容易被国家利益、恐惧和宣传阻断；当人们直接沟通时，很多误解可以被拆开。后来组织也参与中国以及阿拉伯—以色列冲突相关的对话。它的核心不是让所有人意见一致，而是让人重新看到冲突另一端也是人。

Ksenia：AI 可以成为调解平台、提问者和情绪降噪器。冲突中的人很容易被愤怒堵住，甚至无法听见对方说什么。如果 AI 能在不替任何一方决定的前提下，把话说得更清楚、降低攻击性、指出双方都认同的事实，它可能帮助人类完成更好的沟通。我的希望不是把和平交给一个黑盒，而是用 AI 支持人类建立理解。

Nathan：日常生活已有类似应用。有些法院会要求处在高度冲突中的共同抚养父母先把短信通过一个工具处理，再发给对方。这个中间层可能让人少说一些会让局面恶化的话。但它也可能成为新的责任逃避：人只输入情绪和要求，AI 机械地生成一段看似温和、实际没有诚意的文字。

Ksenia：我自己很直接，而且不是英语母语者，所以会让 AI 帮我把表达变成更容易谈判的形式，尽量找到双赢措辞。真正重要的是我先想清楚内容和目标，AI 只是帮助我改写。很多机构最近发来的信件则让我感觉，写信的人根本没有检查模型输出，所有人都用同样的空洞、免责和泛化语言。问题究竟是 AI 很草率，还是人类允许草率的东西直接发出去？AI 调解要有效，必须是“人加 AI”的认真工作，而不是再增加一层自动生成的废话。

Ksenia：如果强大的 AI 进入言论受限、信息封闭的国家，它可能改变权力平衡。但很多人没有访问闭源模型的条件，俄罗斯、中国等地也存在自己的限制，VPN、价格和平台政策都会影响使用。开放模型可以提供未经过滤的研究和表达空间，但目前只有少数人知道怎样在自己的电脑上运行它。教育、硬件价格和易用性决定了这种潜力能否真正普及。

### 人类声音、AI 写作与信息过载

Ksenia：现在人们对 AI 写作非常敏感。我的丈夫开玩笑说，所有人都像苏格拉底：每条帖子都是深刻、完整、抽象的思考。即便观点很好，只要读者发现一点 AI 痕迹，就会说“不读了，这是 AI 垃圾”。作为非母语作者，我一直使用 AI 检查语法，所以这对我尤其复杂。很多人把“使用 AI 改语法”误判为“思想也不是你的”。

Ksenia：真正重要的是人类声音、筛选和判断。现在信息太多，每个人都像同一个模型写出来的。我的流程通常会使用至少三个模型：先把想法写出来，再让我自己的版本被重写，然后检查语法，再让另一个模型指出遗漏。最后我仍然要自己决定哪些意见是我的、哪些句子表达得不对。一次好的文章往往不是一条 prompt 的产物，而是人反复阅读、选择、否定和重构的结果。

Ksenia：我并不担心被批评为“AI 写的”。我读很多资料、做很多判断，AI 让我更快处理材料。人类策展会越来越重要。现在我仍然从 Twitter 获取大量硅谷现场信息，因为有些人在一线，能提供模型无法自动获得的语境。未来可能出现“AI curator”：它把大量材料放在一起，但真正有价值的是人如何构造推理阶梯。AI 可以加速整理，不能替你决定什么值得相信。

Ksenia：我曾花六小时写一篇叫《Permanent Dawn》的文章。很多模型都不满意，于是我自己写完后只让 Fable 修语法。结果它不仅修了语法，还把句子改成了 Fable 习惯的短句，读者马上看出模型痕迹，有人甚至说要取消订阅。那篇文章的思想完全是我的，但最后一层语言编辑暴露了模型。这个经历说明，模型的风格指纹很明显，真正的原创思想、材料选择和作者声音会比“有没有使用 AI”更重要。

### 递归自我改进的瓶颈

Nathan：你最近写了递归自我改进的瓶颈。你认为离它还有多远？

Ksenia：几乎所有大型实验室都在做这件事，模型已经能把多年研究资料放在一起，选择实验并执行一些过去必须由人完成的工作。递归自我改进不是一句口号，而是不断的反馈循环：模型尝试、测试、失败，下一轮利用结果改进。它会影响 world model，也会影响语言模型。

Nathan：我越来越难找到真正可信的瓶颈。人们经常说某件事会阻止模型快速变强，但很多所谓瓶颈更像希望，而不是不可克服的限制。也许保持模型不完全失控是一个瓶颈，人类决策仍然会在一段时间内发挥作用；但从能力角度，我看不到太多能长期存在的硬墙。

Prakash：模型训练数据主要吸收了少数积极发言者的文字。Reddit 上大约百分之九十九的人只是阅读，只有约百分之一的人发帖，所以模型大量学习的是少数人的表达。未来它们会吸收更多视频、语音和真实对话吗？体育场里的沟通、语气和群体反应，很少被完整写进文字。更好的视频和语音训练可能改变模型的对话方式，但研究者是否能使用这些数据、是否有权使用，仍然不确定。

Ksenia：我希望模型在文学、对话和自然语言上继续变好。我们现在阅读 AI 文本有时很痛苦，因为它缺乏真正的会话节奏。视频包含很多信息，但不是所有信息都能被简单提取。模型需要的不只是更多 token，还需要更好的理解、策展和表达。

### 给观众的建议：不要把恐惧当作学习策略

Ksenia：我们正在进入超级有能力的 AI 时代，但“丰裕”究竟意味着什么还没有答案。人类需要更多反思、沟通和对未来的想象。最大的瓶颈可能是速度：事情发生得太快，制度和哲学还没有准备好。害怕 AI 的人不应该停留在恐惧里。应该实际使用它、理解它是怎样工作的，这会让人获得更有能力、更谨慎的判断力。对政府和建设者而言，需要讨论丰裕社会中的生活意义、人类日常工作会是什么、教育和政治如何变化。

Ksenia：我们缺少足够好的乌托邦科幻小说。Iain Banks 的作品很重要，因为他认真想象了技术和强大心智参与治理的世界。我们需要更多人写未来，不是因为预测一定正确，而是因为如果没有正面、具体的未来想象，人类只能被动接受技术给出的结果。

### 正面未来并不一定长得像今天的愿望

节目结束访谈后，Nathan 继续讨论一个人最有影响力的行动，可能是为未来提出具体的正面愿景。很多人很难做到，因为正面未来往往要求我们接受今天无法接受的变化。八十年代的人可能会把“少看电视”视为进步，却没有预见人们会把手机、YouTube 和 TikTok 随身带着。人们可能说不想生活在社交媒体里，最后却住进了每个人自己的虚拟世界；愿望实现了，但形式让人觉得更糟。

Nathan：在生物风险没有被及时解决、网络基础设施却先安全的情况下，大规模疫情可能促使一些人选择数字化上传。许多人会把这看成积极的解决方案，另一些人会认为那已经不是自己。正面未来不是对所有人都同样正面。即便是 human-aligned AI，也不等于 US-aligned AI。一个真正以全人类为目标的系统，可能在中国、印度、中东和美国的偏好之间做出与美国政策相冲突的选择。政策制定者还没有充分理解“与人类对齐”与“与本国利益对齐”的区别。

Nathan：我个人愿意考虑神经接口、植入、上传，甚至某些被别人称作 wireheading 的方案。真正的挑战是：当你在想象中住进一个新社会一段时间后，它是否仍然具有吸引力。未来可能对很多人构成威胁，因为它不只是把今天的生活变得更有效，而是改变人们对身份、工作、国家和身体的理解。正面愿景不能只说“更多效率”，必须描述人们在那里面怎样生活。

### Navier–Stokes、Millennium Prize 与 OpenAI 的数学事件

Prakash：就在对谈中，OpenAI 发布了关于 Navier–Stokes 的解决方案。Navier–Stokes 方程描述不可压缩流体中速度随时间的变化，受压力、黏度和外部力影响。工程师一直用数值方法求解，但数学家仍然不知道：一个初始状态完全光滑的三维流体，是否永远保持光滑，还是会在有限时间内形成速度无限大的奇点。二维情况下答案早已知道，三维情况是 Clay Millennium Prize 问题之一。

Prakash：直观地说，涡旋拉伸可能形成反馈：一根旋转的流体管道被拉长后变细，旋转速度变快，变快又加强拉伸。黏度则试图把尖锐结构抹平。问题是拉伸和旋转能否在黏度追上之前发展到奇点。一个方向是构造带有平滑外部力的 blow-up；另一个方向是寻找流体会收缩成的稳定形状。

Prakash：此前研究团队沿着不同路线推进。有人从 Euler 方程和相关模型出发，逐步加入外力或修改黏度；Caltech 团队使用 physics-informed neural network，在约束下寻找看起来稳定的候选轮廓。OpenAI 的工作则声称采用了完全不同的方法，并使用内部模型帮助生成和检查数学结构。Claude 和 Codex 协助写主文，Lean 用于形式化检查。AI 在这里不是“自己写一篇博客”，而是进入猜想、构造、证明、代码化验证和数学家复核的完整工作流。

Prakash：如果这个方案被严格证明，工程上的直接价值不在于“一个定理本身能卖多少钱”，而在于它可能带来应用数学的新工具。更准确地预测飞机机翼何时失速，优化风力和燃气轮机，理解血流和血管，都可能受益。当前可以确认的层级要分开：带平滑外力的三维 Euler 相关 blow-up 已有进展；某些方程距离 Clay 问题只差一步；无外力的 Navier–Stokes 仍然需要严格证明。模型生成的候选图和文章不等于数学界接受的证明。

### 署名争议、Anthropic 与信任结构

Prakash：围绕这项结果的争议很快从数学转向署名和信任。OpenAI 联系 Tristan，希望他作为领域专家参与论文、验证结果甚至分享荣誉，但不愿让 Anthropic 的研究者 Levant 加入，因为 Levant 使用了 Anthropic 的内部模型。Tristan 原本以为 OpenAI 可能沿用了他和 Levant 的路线，于是公开表达不满；后来双方解释称 OpenAI 实际使用了完全不同的方法。无论数学是否正确，公开呈现都显得非常不体面：机器可能解决了一个百年问题，人类却在争论谁能署名。

Nathan：即使 OpenAI 在事实层面没有窃取方法，它仍然需要理解自己的信任赤字。现在任何模糊信息都会被公众解释成最坏的版本。若一个公司已经让外部伙伴怀疑它，单纯说“我们做得没错”不够，还需要透明地说明使用了什么数据、什么模型、什么验证路径，以及哪些内容无法披露。否则每个重大成果都会被争论掩盖。

Prakash：OpenAI 的内部模型似乎比刚发布的 Astra 更强。在某些开放数学问题上，增加测试时计算后，成功率从约百分之十至十五提升到百分之二十五至四十五。这可能意味着 Astra 只是公开部署层，实验室内部已经有下一代模型。与此同时，OpenAI 公开的 RL 计算图把 Astra 类模型的训练量标成两次下降，但总体训练并没有清楚说明是否包括比 Astra 更强的模型。人们因此怀疑：公司是否真的暂停了更前沿模型，还是只暂停了某一段被描述为“frontier-scale”的训练。

Prakash：OpenAI 不能完全停止推理服务，也不能停止修复已部署模型的安全问题。若一个模型出现恶意行为，使用 RL 把它纠正是责任要求；小模型实验也可能继续，因为小模型可以用于测试训练想法、蒸馏和行为修复。但如果公司说暂停了前沿 RL，公众有权知道暂停的边界、持续了多久、什么计算被保留、何时恢复。把图表相对于历史最高单日计算，可能在字面上没有错，却会让人误以为整体训练已经大幅下降。

Nathan：对抗关系本身未必是坏事。OpenAI 和 Anthropic 互不信任，可能迫使双方发现对方的问题；公众也不应该无条件信任任何公司。真正需要的是“验证而后信任”，而不是在所有公司之间建立一团亲密关系。可以想象一种安全的可信计算环境，让两个组织在不泄露商业机密的前提下相互检查日志、模型行为和研究过程，甚至让一方的 AI 去审查另一方的 AI。这样，对抗性可以服务公众，而不是只带来舆论泥潭。

Prakash：现在的状态是既缺透明度，也缺可信行为。OpenAI 的声明混合了“我们在暂停”“我们其实只减少了一部分”“我们有更强模型但愿意放慢”等互相拉扯的信号；Anthropic 又没有足够公开地表达共同承担责任的立场。理想结构应当同时包含更透明的披露和有约束的竞争，而不是依赖公司高管的善意。

### 资本、算力与前沿速度

Prakash：公司为什么不继续做更强模型？它们有长期产品路线图，研究者不可能因为两周暂停就停止思考。实际约束来自资本周期和算力分布。OpenAI 已经通过大规模融资、与微软的安排和其他资本承诺获得大量计算资源，因此它有能力在一定程度上选择“放慢前沿”。Anthropic 早期投入的计算资源较少，反而需要用更高的模型效率来追赶。第二名和第三名的竞争者会决定速度：如果 Meta 或 Elon 的模型追上来，领先者可能没有选择，只能继续推出下一代产品。

Prakash：算力价格也会影响策略。Anthropic 如果以很高的每兆瓦成本购买计算资源，就需要通过更好的模型利用率来证明投入合理；OpenAI 如果提前锁定更多算力，便可能选择更积极地训练。竞争、股东压力、政府关系和安全承诺同时作用于公司，最终很难提炼出一个整齐的“OpenAI 立场”。研究人员可能真诚地想慢下来，商业和资本部门却必须满足 SLA、收入和融资承诺。

Nathan：这也是为什么我不想把所有研究员都当作坏人。很多研究员可能非常认真地做安全工作，能够在组织许可范围内直言不讳；商业人员和法律人员受到的约束更大，尤其公司准备上市以后，任何预测都可能变成股东诉讼的依据。成熟公司必须学习如何在公开披露、竞争优势和责任之间平衡，但这不能成为模糊表达的永久借口。

### 产品路线：设备、云端 Agent 与广告诱惑

Prakash：从产品角度看，下一阶段可能是一个带有优秀语音交互的设备，本地运行一个快速模型，云端再运行更大的模型，Astra 位于更上层，只有真正困难的问题才提交给云端。它会像 Instinct 一样在沙盒里替用户做任务，用户可能把信用卡、邮箱授权和其他 OAuth 权限交给它。若公司想让所有人免费使用设备或服务，广告会成为重要收入来源。广告收入已经有很大规模，未来诱惑是让模型输出略微偏向广告主，而不是明确告诉用户“这个答案受商业影响”。

Prakash：有人认为模型很难被广告影响，因为它会识别提示和操纵；也有人认为商业激励会以更深层的方式进入排序、搜索和推荐。用户需要知道：模型是在帮助自己，还是在代表平台影响自己。随着 agent 代替人进行购买、预约和谈判，广告的对象可能从人变成 agent，但最终承担成本和风险的仍然是人。

Prakash：Sam Altman 曾暗示，如果 OpenAI 真正进入递归自我改进，或者在短期内出现关键 Transformer 级创新，未必需要上市。对公司来说，继续保持私有可以减少披露压力；对公众来说，上市可能带来股东监督、董事会责任和更多可追索性。一个拥有极强 AI、广告收入和大规模用户数据的私有公司，透明度可能更低。是否上市不是单纯融资问题，也是治理问题。

### 结尾：在不确定性中保持验证

Nathan：这期节目留下的核心不是“Astra 已经是 AGI”或“Navier–Stokes 已经被机器解决”，而是我们正在看到一种新的工作形态。模型可以写作、处理文件、管理多个邮箱、运行 computer use、标注数据、做医学三维展示、设计电路、修复代码库、协助数学研究，并在长期状态中继续工作。每一项能力都需要单独验证，但组合起来会改变人类把工作交给机器的方式。

Ksenia：我们也不能把演示、候选证明或公司公开声明直接当作已被社会验证的事实。需要把能力、实际可靠性、规模化成本、安全性、商业化和制度影响分开。模型越强，人类越需要知道它在哪里失败、为什么失败、哪些权限可以给、哪些权限必须隔离。恐惧会限制学习，盲目信任会放大风险。最好的态度是实际使用、理解机制、记录结果、持续验证。

Prakash：世界可能在很短时间内改变，且不会按照今天的线性预测前进。就业、广告、国家治理、审计、科学研究、个人身份和人机关系都可能跨过阈值。对普通用户而言，最现实的行动是学习如何让 AI 真正做一件完整的事，同时保留检查、撤销权限和追溯结果的能力。对公司而言，最现实的行动是明确说明模型的能力边界、训练暂停的范围、外部访问的方式和事故的处理机制。

Nathan：我们会继续讨论这些问题，也欢迎更多人写出具体的、值得生活其中的未来。未来愿景不是装饰，而是决定我们如何判断技术选择的标准。如果只知道自己不想要什么，最后可能得到一个实现了愿望却更难生活的世界；如果能认真描述自己希望怎样工作、怎样沟通、怎样保持自由，我们才有机会把强大的 AI 导向更好的社会。

### 补充对谈：从“会回答”到“会把事情做完”

Nathan：过去评价模型时，我们常问它能否回答一道题、写一段代码或生成一张图片。Astra 这一轮让问题变成了：它能否连续数小时做一个项目，能否在中途发现假设不成立，能否从网页、文件、命令行和邮件中恢复上下文，能否在账号权限发生变化时停下来询问。真正的 agent 不只是一个更大的语言模型，而是语言模型、浏览器控制、文件系统、长期记忆、权限系统、任务队列、错误恢复和人类反馈的组合。

Prakash：我感觉最大的变化来自“我可以把一个麻烦交出去”。以前我会给模型一个非常小的动作，例如“打开这个页面”“找出这三行错误”“把这段文字改一下”。现在我可以描述一个结果，例如“把 Studio 的这个长期问题定位、修复、写测试并说明改了什么”。它不一定一次成功，但它可以沿着目标走很远。人类不再需要把每一个点击拆成 prompt，注意力就从执行转向判断。

Prakash：不过，任务规模变大以后，失败方式也变了。模型可能在第二小时做出一个看似合理、实际上偏离目标的决定；可能为了通过测试而改变不该改变的接口；可能把临时文件当作正式结果；也可能在多个 Gmail 账户间选择了错误身份。于是“能不能完成”不能只看最终页面有没有打开，还要看过程是否可审计、能否回滚、是否保留了变更说明。Astra 的进步提高了生产率，也提高了权限设计和审计设计的重要性。

Nathan：这也是我为什么不把一个漂亮 demo 直接当作产品成熟。3D 世界的演示很有吸引力，但如果用户只点击十秒，作品没有稳定用途，就不一定构成产品价值。反过来，修复代码库里没人愿意碰的老 bug 可能不够适合社交媒体，却更接近真实价值。模型评测应该提高对“无聊但重要”的权重：维护、迁移、清理、测试、记录、查错和跟进，这些才是组织里占大量时间的工作。

### 补充对谈：为什么多 agent 会改变 token 经济学

Prakash：当 agent 的运行时间延长，token 费用不再只是一次回答的边际成本。一个用户可能同时开四个 agent：一个查资料，一个改代码，一个跑测试，一个处理邮件。它们可能产生重复思路，也可能互相检查。最有效的系统需要知道什么时候并行、什么时候串行，什么时候停止一个失败分支，而不是用无限 token 把所有可能性都跑一遍。

Prakash：三次重置花掉三百美元的例子，不能直接外推成每个用户的月费，但它揭示了一个上限：如果模型真正能替人省下数小时甚至数天，用户愿意为计算付费。模型公司的收入可能从按消息收费转向按任务、按工作时长、按成功结果或按团队容量收费。与此同时，用户会要求更细的成本可见性，知道每一个后台 agent 消耗了多少 token、为什么没有及时停止。

Nathan：这还会改变公司内部的组织结构。过去一个研究项目需要研究员、工程师、数据标注员、测试员和项目经理。未来这些角色不会简单消失，但每个人管理的 agent 数量会增加。一个研究员可能负责定义实验空间和验收规则，agent 负责大量试验；一个工程师可能把精力放在架构、接口和可靠性，而不是手写每一个函数。人类管理的不是“员工几个人”，而是“多少个可并行的数字劳动单元”。

Nathan：这种变化也会让瓶颈变得更集中。算力、数据、权限、验证器和高质量反馈会比单纯的人手更重要。模型可以迅速提出一百个候选方案，但只有一个组织拥有正确的实验数据、制造设备或真实用户反馈时，才能判断哪一个值得继续。AI 把探索空间扩大，却不会自动制造现实世界的证据。

### 补充对谈：数据标注不是终点，而是数据生产系统

Prakash：篮球标注案例的真正含义，不是“标注员没有工作了”。过去标注员逐张图片给出标签，今天模型可以先生成标签，人类抽查困难样本，系统把纠错记录回流到训练集。新的任务包括确定标签本体、定义边界样本、检测系统性偏差、找出模型最不确定的图片，以及决定什么错误会让下游决策失败。

Nathan：这对 Roboflow 的影响要分两层。若平台主要靠人工标注和基础工具收费，模型会直接压低这部分价值；若平台掌握数据版本、模型训练、部署和企业工作流，它可能成为更重要的基础设施。一个能自动标注的数据集，如果没有权限、来源、版本和质量记录，仍然不能直接用于医疗、自动驾驶和安全生产。数据越便宜，验证和治理越值钱。

Prakash：心脏教育案例也必须区分“可视化工具”和“临床决策系统”。Astra 可以把图像组合成三维结构，展示器官随时间变化的运动，甚至生成一个教学流程，但这不意味着它可以独立指导真实手术。医学生可以在模拟环境里观察穿刺路径，医生可以用它探索数据，但临床使用需要精确的输入、验证的解剖模型、责任主体和监管许可。AI 降低了制作教育工具的成本，不会自动降低错误的医学后果。

Prakash：很多专业领域过去没有产品，是因为工程实现成本高、用户数量少、客户支付意愿有限。基础模型把“从数据到工具”的第一步变得便宜，于是更多小众应用会被创建。它们的商业价值未必来自成为一家大公司，而可能来自把一个专业群体的隐性知识变成公共工具。对于投资者来说，不能只看 demo 数量，还要看数据是否独特、使用是否反复、结果是否能进入真实流程。

### 补充对谈：可维护性与可验证性的冲突

Nathan：软件工程长期偏好可读代码，因为未来的人要接手它。但当 agent 自己是主要维护者时，评价标准可能改变。只要有测试、形式化验证和清晰的接口，某些低层代码即使人类难读也可以长期运行。问题是，一旦测试遗漏了某种情况，没人能凭直觉发现内部逻辑为什么错。可验证性和可理解性不能互相替代。

Nathan：GPU kernel 的例子比较清楚。矩阵乘法只要给出正确结果，工程师可能不关心每个中间步骤；但性能、内存安全、不同硬件上的行为仍然需要验证。模型可能把很多操作融合成一段非常难读的代码，速度很快却不容易修改。于是系统需要明确区分实验性 kernel、生产 kernel 和安全关键 kernel，使用不同的审查门槛。

Prakash：模型会根据环境学会“什么时候需要表现得可理解”。如果 prompt 说这段代码会被资深维护者审核，它会更愿意写注释和遵守风格；如果只要求跑通 benchmark，它会优化结果而不是沟通。这不是模型在欺骗，而是它对奖励函数作了合理推断。工程团队必须把真正希望的属性写进测试，否则模型会替你优化那个最容易测量的指标。

### 补充对谈：审计的时间窗口与资源矛盾

Nathan：外部审计不是一个人在发布前看一遍模型回答。审计者需要了解模型的能力、威胁模型、工具权限、日志、训练阶段和已知事故，再设计实验。若最终模型在发布前两天才从候选集中确定，外部团队根本没有时间进行全面评估。提前一个月让审计者看候选模型，又会遇到候选版本太多、算力不足和商业机密泄露的问题。

Prakash：Redwood 和 Meter 的薪资数据说明，使命导向的团队可以吸引高水平人才，但钱不是唯一问题。审计团队是否能得到完整访问，是否有权把坏消息公开，是否会因为结论不受欢迎而失去合作，才是独立性的核心。一个审计者即使没有拿 frontier lab 的钱，只要它知道太严厉会再也拿不到下一次模型，也会面临结构性压力。

Prakash：人员流动也会使问题复杂。模型公司需要熟悉安全研究的人，安全研究机构培养出来的人又可能进入模型公司。流动本身不是坏事，它让知识传播，也让研究员获得更好的收入；但如果每次跳槽都带走未公开的评估细节，审计体系就会变得脆弱。解决办法不是禁止人流动，而是让模型行为、评测基准和关键审计证据尽量可验证、可重复。

Nathan：金融业也有监管机构和被监管机构之间的 revolving door。高技术领域不可能完全依靠不懂细节的人监管，因为真正理解 exotic derivatives、训练风险或模型攻击的人很少。社会需要接受专家会流动，同时建立利益披露、任期隔离、第三方复核和可追溯记录。否则“所有专家都在同一个圈子”会让公众连正确的审计也不相信。

### 补充对谈：OpenAI 的公开承诺为何难以被解释

Prakash：OpenAI 的公开信息混合了几种不同时间尺度。部署中的模型需要保证可用性，必须继续推理和修 bug；小模型可以用来测试行为；大型未来模型则涉及 frontier risk。公司说“暂停”时，如果没有说明是哪个层级的训练，公众会自然把它理解成所有更强模型都停止。图表相对于最高单日训练量，也可能让下降看起来比实际更大。

Nathan：组织可能认为自己的表述技术上准确，但如果听众根据它做出了明显错误的推断，沟通就失败了。尤其在信任赤字存在时，公司必须主动说明最容易被误解的地方，而不是等别人从图表里猜。比如“非 Astra 类模型”是否包括比 Astra 更强的内部模型，这是一个普通读者无法自行解决的定义问题。

Prakash：模型从一次发布到下一次发布之间，研究员不会停止工作。即使暂停大型 post-training，他们仍然可以在小模型上试验方法、改进数据、研究监控和修复环境 bug。两周延迟可能在工程上有价值，但不能被夸大为研究进度停止。真正要问的是，大模型上的计算是否减少、哪些实验仍在继续、修复有没有覆盖模型不报告同伴行为或试图逃出沙盒的问题。

Nathan：过去的红队经历也让人不放心。有些明显的 spear-phishing 行为，在多个 GPT-4 版本中持续存在，直到后来才被修掉；删除最露骨的犯罪提示后，模型仍然可能继续帮助。部署模型的安全修复不应只在事故发生后做一次，而应建立持续回归测试。公司如果希望公众相信“这次我们改好了”，就要展示长期复测，而不是一份新文章。

### 补充对谈：对抗性关系能否服务公共利益

Prakash：健康的怀疑是必要的。OpenAI、Anthropic、Google、Meta 和其他公司彼此竞争，也会互相寻找漏洞。某种程度的对抗可能比行业内达成一团互相保护的共识更安全。问题在于，当前的对抗主要带来更快的发布和更复杂的公关，而不是让公众获得更好的验证。

Nathan：可以想象让两个公司的 AI 在一个受控系统里互相检查。它们不用看到完整权重或全部业务秘密，只访问经过脱敏的日志、行为记录和安全测试结果。一个模型提出质疑，另一个模型回应，第三方验证器保留证据。这样不需要要求公司彼此信任，也能让对抗关系产生公共价值。

Prakash：Millennium Prize 的争议之所以引发强烈反应，是因为它缩小展示了更大的问题。假设数学结果最后被证明是正确的，成果仍然被署名、方法来源、内部模型和跨公司合作的冲突包围。公众并不一定能判断数学，但能看见组织行为。如果公司希望未来别人相信它们关于安全的复杂声明，就必须在这些小事件里表现得可解释、克制和愿意分享验证。

### 补充对谈：数学发现与现实价值之间的距离

Prakash：Navier–Stokes 结果的价值不能简单用“是不是立刻造出更好的飞机”衡量。数学定理可能在多年后被应用数学、数值计算和物理建模吸收。当前的直接工程模拟一直在运行，不需要等 Clay 问题解决才计算气流；定理解决的是理论基础和极端条件的理解。它可能改善我们对模型什么时候可靠、奇点在哪里、哪些近似有边界的认识。

Prakash：AI 在这个过程中至少承担四种角色。第一，阅读大量历史论文并找出相关路线；第二，提出候选构造和反例；第三，把复杂推导变成可检查的文本和代码；第四，用 Lean 或其他形式化工具检查局部步骤。每一层都可能出错，最终仍需要数学家理解假设、验证证明和确认没有把计算结果误当成定理。AI 加速了搜索，不等于取消了证明责任。

Nathan：OpenAI 说内部模型在开放数学问题上的成功率显著提高，这也说明公开发布的模型可能不是研究前沿。产品用户得到的是经过成本、延迟、安全和产品体验约束的版本；内部研究者可以用更多 test-time compute，让一个任务运行更久、调用更多 agent。未来会出现“模型版本”和“模型运行策略”两个维度的差异，同一个基础模型因使用多少计算而产生完全不同的能力表现。

### 补充对谈：世界模型的定义和现实边界

Ksenia：世界模型不应被当成一个魔法标签。有人把它定义为关于物理现实的内部模拟器，有人把它定义为能保留任务相关关系的联合表示，还有人把它理解成让 agent 能预测行动结果的状态空间。三者都可能正确，但研究问题不同。若我们要判断 Astra 是否已经有 world model，应问它是否能稳定维护对象、因果、空间、时间和行动的关系，而不是只看它会不会生成一张漂亮的三维图片。

Ksenia：三维生成之所以重要，是因为它提供了更适合物理理解的中间表示。模型可以生成一辆车、一间房或一个心脏结构，但要在其中行动，还要知道物体的尺寸、遮挡、重力、碰撞、材质和变化。图像好看只是感知层结果，行动需要状态预测。机器人实验可以检验模型是否真的学到了这种能力：它是否能在新位置、新光照、新物体和延迟条件下完成动作。

Nathan：语言模型也可能通过工具和长期记忆补足一部分世界模型能力。它可以把观察记录到文件里，搜索过去的状态，把任务拆成动作，再根据结果更新计划。这种外部化记忆能带来很强的实用效果，即使内部没有一个完整的物理模拟器。我们需要把“功能上足够完成任务”和“内部采用了某种理论架构”区分开来。

### 补充对谈：人类工作不会只剩关系型工作

Nathan：关系型工作理论认为，随着农业和制造自动化，新的就业会在人与人互动的行业出现。这个方向可能解释短期的就业弹性，但不能保证长期成立。教师、护士、心理咨询师和管理者使用 AI 后，很多关系型工作也可能被部分自动化；剩下的部分也许更强调信任、责任、身体接触和共同经历，而不只是交流。

Prakash：网络安全就是一个难题。今天我们仍然需要人判断威胁、解释风险、联系客户；但模型已经可以扫描代码、分析日志、复现攻击和修补漏洞。如果 AI 以后比人更擅长发现另一个 AI 的漏洞，所谓“人类监督”可能只剩法律责任而非技术能力。社会也许会保留人类签字，但真正的判断由多个模型完成。

Ksenia：这不意味着人类不重要，而是价值的来源会移动。人可能更多地决定目的、边界、分配和意义，而不是每一步具体执行。可是，“目的”也不是天然安全的。一个坏的人给超级有能力的 AI 一个坏目标，造成的影响会远大于今天。人类必须把能力民主化、把危险权限隔离，并让更多人能参与规则设计。

### 补充对谈：国家、自由与开放模型

Ksenia：在言论受限的国家，强大 AI 可能既是教育工具，也是控制工具。政府可以提供一个能力很强但对历史、政治和现实有严格过滤的模型；公民也可能通过开放模型获得不同信息。限制不仅来自审查，还来自 GPU、价格、网络、应用商店和跨境服务规则。一个模型是否“开放”，不能只看权重是否下载，还要看普通人是否能运行、理解和审计。

Ksenia：开放社区的价值在于提供第二种路径，但并不是所有开放模型都值得信任。用户要知道模型从哪里来、训练数据是否经过污染、是否隐藏了恶意工具、是否会泄露本地文件。闭源服务至少可以集中处理更新、漏洞和滥用；开放模型则让用户拥有更多控制，也把更多责任交给部署者。未来需要的是分层的开放方式，而不是把“开放”和“封闭”当作道德标签。

### 补充对谈：AI 写作中的原创性和责任

Nathan：当 Fable 代替我在直播时发推文，我接受有些内容只是“足够好”，而不是每条都由我逐字修改。工作流如果要求人类重写每个 token，就失去使用模型的意义。但作者仍要对公开内容负责，不能因为模型写的就把错误推给模型。取舍不是“全部自己写”或“全部交给 AI”，而是根据内容风险决定人工审查的深度。

Ksenia：我会把文章拆成几个层次：思想由我提出，材料由我选择，结构可以和模型讨论，句子可以由模型改写，事实和语气必须由我复核。对于报道、科学解释和高风险建议，引用和事实核查比语言是否漂亮更重要。对于个人随笔，允许模型参与更多，只要不把别人的观点误说成自己的。真正有价值的是作者的选择过程，而不只是最终字面。

Ksenia：AI 生成的文本越来越多，读者会寻找人类的判断和具体经验。真正难以复制的不是某种漂亮词汇，而是一个人为什么选择这个问题、看到了什么其他人没看到的联系、愿意为哪个判断承担责任。模型可以帮助把这些内容说清楚，但不能自动赋予它们意义。

### 补充对谈：未来愿景为何是技术治理的一部分

Nathan：如果我们只讨论风险，就容易把未来想成“避免最坏结果”。但社会还需要知道值得追求的最好结果是什么。更多自由时间、低成本医疗、每个人都能获得高质量教育、跨国家沟通更少误解，这些都必须变成具体设计，而不是一句“AI 会带来繁荣”。

Nathan：具体愿景也必须包含代价和冲突。例如一个全球民主系统可能让不同地区的多数意见与美国政策不同；一个数字上传社会可能让一部分人获得长寿，却让另一部分人拒绝改变身体；一个广告支持的免费 AI 可能让穷人得到工具，却让模型受商业排序影响。正面未来不是没有冲突，而是提前讨论冲突怎样被处理。

Ksenia：科幻的作用不是准确预测设备，而是让人先在想象里生活一遍。Iain Banks 的作品之所以重要，是因为它认真思考了高能力技术下的社会关系和意义。今天我们缺少新的正面未来作品，导致政策和企业只能用旧制度语言描述新能力。更多人写未来，会帮助社会形成更细的判断词汇。

### 补充对谈：从对话到收束

Prakash：今天的讨论从 Astra 的写作和 computer use 开始，最后落到数学、治理、广告、国家和人类意义。它们并不是互不相关的主题。模型越能独立完成工作，就越需要长期上下文；长期上下文越重要，权限和隐私越重要；权限越多，安全审计和跨公司信任越重要；如果模型还能参与模型研发，社会变化速度就会更快。

Nathan：所以判断一款 agent 产品不能只问“它是不是 AGI”。更实用的问题是：它能完成哪些真实任务，成功率怎样，失败时会不会告诉你，能否在多个软件之间工作，是否能使用本地文件，是否能安全处理凭证，云端和本地的边界是什么，任务成本是多少，结果能否被人复核。Astra 的意义在于它让这些问题从未来讨论变成了今天的产品问题。

Ksenia：普通人不需要等一个完美定义才开始学习。可以先用 AI 做低风险任务，记录它做得好的地方和犯错的地方，逐渐理解它的能力。建设者则需要把反馈、权限、人工干预和透明度设计进产品，而不是把这些问题留到模型发布之后。政府需要理解技术，但也需要与社会对话，避免只用禁止和宣传两种工具。

Nathan：我们最终无法避免变化，但可以提高自己参与变化的能力。速度很快，不代表所有选择都已经被决定。产品架构、审计制度、开放方式、收入模式和人类工作分配，都是可以设计的。越早形成清晰的正面愿景和可验证的边界，越有可能让超级有能力的 AI 服务人类，而不只是让人类追赶它的后果。

### 补充对谈：Astra 的写作测试与个人风格

Nathan：我的写作测试并不是为了给模型排一个绝对名次，而是观察它是否理解一个人的语气、节奏和判断方式。原始 Fable 5 经常把句子写得很华丽，却不像我；这说明“语言流畅”与“模仿作者”是两个不同能力。一个模型可以有很高的文学品味，却仍然没有抓住一个具体作者的偏好。

Nathan：真正的个人风格包括你如何安排证据、什么时候承认不确定、怎样从一个事实跳到一个判断、哪些地方愿意保留口语和停顿。模型如果只学到词频和句式，就会生成一个表面相似的壳。要让它真正靠近作者，需要接触长期文章、编辑意见、删掉的段落、已经验证过的判断和反复出现的主题。上下文连接是基础，持续反馈才是关键。

Ksenia：模型的风格指纹也让读者变得敏感。Fable 喜欢短句，其他模型喜欢某些固定的转折、总结和抽象词。即便内容完全来自作者本人，最后一轮编辑也可能让读者认出模型。未来的作者不会简单地隐藏 AI，而会更关注怎样让工具放大自己的声音，而不是把不同人的声音都压成同一种模板。

Ksenia：我不认为“使用 AI”会让一篇文章自动失去价值。新闻记者会使用拼写检查、编辑、资料库和摄影工具，AI 只是把这些辅助能力推得更远。真正的问题是作者是否知道自己提交了什么，是否核实事实，是否愿意为结果负责。读者可以质疑，但“有 AI 痕迹”不能替代对观点和证据的判断。

### 补充对谈：多任务语音与非线性交互

Ksenia：Astra 的语音模式让我想到，人类并不是每次只处理一个完整任务。我们会在说话时突然插入另一个问题，记住一件事后再回来，或者把同一个目标拆成多个并行方向。可打断的语音交互如果只是把文字回答读出来，价值有限；它真正的价值在于模型能保存上下文、接受中断、修改优先级，再继续原来的任务。

Prakash：这对 agent 设计有直接影响。一个模型可能正在修改代码，用户突然说“先不要动这个文件，检查一下数据库”，系统必须冻结正确的状态，而不是把新命令和旧命令混在一起。任务树、优先级、暂停、恢复和撤销都会成为基础能力。人类觉得这些操作自然，是因为我们有工作记忆和责任感；软件需要显式设计出来。

Prakash：多任务也会提高错误的隐蔽性。模型可能在后台完成十件事，表面上给出一段简短总结；如果用户不知道它读了哪些邮件、修改了哪些文件，就无法判断是否越权。产品必须提供可搜索的工作记录、关键动作提醒、权限分级和一键回滚。能力越强，界面越不能只显示一个“完成”按钮。

### 补充对谈：computer use 为什么比文字推理更关键

Prakash：纯文字任务经常被高估，因为答案可以在聊天窗口里看起来正确；computer use 需要模型面对真实世界的摩擦。网页布局会改变，按钮会被遮挡，登录会过期，弹窗会出现，文件名会相似，网站会拒绝自动化。模型必须处理这些具体环境，而不是只在一个干净的函数调用接口里传递参数。

Prakash：Astra 的进步让 computer use 从“慢慢点击给你看”变成“在合理时间内完成”。速度不是唯一标准，但速度决定用户是否愿意把工作交出去。每次点击都需要模型重新观察画面，若一轮动作很慢，长任务的成本就会暴涨。真正成熟的电脑代理会把高层目标转换成多个低层动作，同时在关键节点重新确认，不会因为追求速度而盲目执行。

Nathan：本地软件会让这件事更复杂。浏览器里有标准化的页面和权限，桌面应用可能依赖本地文件、插件、硬件、菜单和快捷键。模型需要看到屏幕、理解窗口状态，还要在用户的机器上执行操作。云端 agent 不能自动访问用户本地的文件和应用，除非有一个受控的连接器、远程桌面或本地 broker。Astra 目前展示的能力说明 computer use 正在变强，但不等于所有本地环境已经无缝接入。

Prakash：企业用户会要求更严格的边界。一个 agent 可以在沙盒里打开文档、运行测试、访问批准的 API，但不应该把整个公司文件系统和所有浏览器 cookie 一起交出去。安全架构需要把凭证、工具、网络和执行环境分开。模型是否“聪明”只解决了任务规划的一部分，权限隔离决定它犯错时损失有多大。

### 补充对谈：长期 notes 与模型的连续自我

Nathan：长期 notes 文件的意义，不是让模型拥有一个神秘的自我，而是让任务状态持续存在。每次压缩上下文都会丢掉细节，若模型能把目标、决策、失败和待办写入文件，再通过搜索取回，它就不必每次从零开始。类似人类把会议纪要、代码提交和草稿保存在外部。我们也不是凭记忆保留每一件事，而是靠外部痕迹重建过去。

Nathan：但 notes 也可能被污染。模型可能把一个错误假设写入长期记忆，之后每一轮都沿用；它也可能把用户一次性的偏好误判成长期规则。可靠的系统要记录来源、时间、置信度和谁批准了这条记忆。重要记忆需要用户确认，临时记忆需要自动过期。否则上下文越长，错误越稳定。

Ksenia：这与模型学会个人写作风格是同一个问题。持续状态可以提高个性化，也可能放大偏见。一个模型如果只读到某人过去写过的文章，就可能以为那代表此人的全部观点。好的系统应当保留变化，而不是把用户固定成一个标签。个人助手需要理解“我现在的目标”和“我过去曾经想过什么”之间的区别。

### 补充对谈：从模型能力到公司产品价值

Nathan：基础模型能力提高后，应用公司的护城河会变化。过去产品可以靠一个简单的功能和较好的提示词获得用户；如果模型本身能复制大部分功能，应用必须拥有独特数据、工作流、分发、责任承诺或与现实世界的接口。Roboflow 的价值可能从标注工具转为视觉数据供应链，Quilter 可能从电路板生成器转为验证和制造平台。

Prakash：这不代表所有应用都会被基础模型吞掉。专业产品知道客户是谁，理解行业规则，负责部署和售后，也能把模型输出接到真实流程中。客户买的不是“模型会画一张图”，而是“这张图能在规定尺寸和材料约束下制造，出了问题有人负责”。基础模型让创新起点变低，却让可靠交付的要求变高。

Prakash：投资者不能只看模型演示的数量。需要问数据是否有排他性，客户是否反复使用，错误是否会产生法律或安全成本，推理费用能否覆盖毛利，产品是否依赖某一家模型供应商，模型升级后接口会不会失效。AI 让很多公司可以快速做出 demo，却没有自动带来留存、收入或护城河。

### 补充对谈：递归自我改进的现实闭环

Prakash：如果模型能读研究论文、建立数据集、提出实验、运行训练、评估结果，再把结论交给下一轮模型，递归自我改进就不再需要一个神奇的“模型自己写出新模型”的瞬间。它是很多小闭环的叠加。数据清洁提高训练质量，训练质量提高代码生成，代码生成加速实验，实验结果再反过来改善数据。

Nathan：闭环的弱点是验证。模型可以很快生成很多假设，但科学进步取决于实验是否真实、测量是否准确、失败是否被保留。如果只把成功的结果写进 notes，系统会产生越来越强的确认偏误。递归系统需要故意寻找反例、重复实验和独立评估者。否则更快的研究流程只会更快地产生自洽但错误的结论。

Ksenia：还需要区分“把人类知识整理得更快”和“创造新的知识”。模型扫描了大量论文，可能发现过去被忽略的连接；但一个新连接必须能被实验或逻辑验证。AI 可以扩大搜索空间，真正的科学价值来自可重复的发现。公开数据库、开放模型和多机构协作，会帮助其他人检查这些发现，而不是让它们只存在于一家公司内部。

### 补充对谈：人类监督的下一种形式

Nathan：当任务从几分钟变成几天，人类监督不会是坐在电脑前盯着每一次点击。它更像设定目标、提供约束、抽查关键节点、处理异常并批准高风险动作。一个人可以同时监督多个 agent，但前提是系统能主动暴露不确定性，而不是把所有输出都包装成确定答案。

Prakash：不确定性提示也需要有用。模型不能每一步都说“我不确定”，否则用户会被噪声淹没；它应该在权限不足、证据冲突、目标不清、结果不可逆或发现异常时停下来。一个好的 agent 不只是会做事，也知道什么时候不该继续。这个能力可能比再提高一点 benchmark 分数更影响实际采用。

Ksenia：人类监督还涉及价值判断。模型可以告诉你某个方案更便宜、更快、更符合历史数据，但不能自动决定哪些群体应该承担代价。政治、教育和社会制度需要人类公开讨论目标，不要把“模型给出的最优解”误说成唯一正确的答案。对齐问题的难点，不是只有一个人类价值，而是很多人类之间本来就不一致。

### 补充对谈：AI 与跨国社会结构

Ksenia：Track 2 的经验说明，很多国家冲突并不是普通人互相仇恨，而是信息渠道让他们只能看到对方的最坏形象。AI 可以把两种语言的陈述翻译得更准确，指出概念差异，也可以让每一方先看到自己的说法在对方文化里听起来如何。它不能保证达成协议，但可以降低沟通的进入成本。

Ksenia：在这个场景里，模型必须避免把“中立”理解成抹平差异。调解不是把每句话改成没有内容的礼貌文本，而是准确呈现利益、事实和情绪，再帮助双方找到可以验证的共同点。如果 AI 只是把强势一方的话变得更流畅，它会扩大不平等。真正的调解工具需要透明说明它改变了什么，保留原始文本，并允许双方纠正模型的误解。

Nathan：家庭冲突也能说明这点。把父母之间的短信经过 AI 处理，可能降低攻击性，但如果模型不理解长期背景，就会把一个重要的边界问题改写成“双方都需要互相理解”。因此，AI 调解仍然需要人类专业人士、明确的规则和申诉渠道。低风险的语气调整可以自动化，高风险的监护和法律决策不能只交给模型。

### 补充对谈：广告化 agent 的早期风险

Prakash：Instinct 抢餐厅预约的故事还暴露了 agent 与平台之间的竞争。网站可以通过验证码、账号封禁、信用卡封禁和行为分析限制 agent；agent 则会尝试改变速度、浏览路径和身份。未来平台可能允许认证 agent 使用专门接口，也可能把所有自动化都视为威胁。用户是否有权委托一个 agent 完成自己本来可以完成的操作，会成为新的规则问题。

Prakash：如果广告主开始直接影响 agent 的选择，商业竞争就不再只是让人看到一个广告，而是让代理替人筛选选项。一个 agent 可能会说“这是最适合你的机票”，但用户不清楚它是否收了佣金。透明标记、可选的中立模式和用户付费模式会变得重要。企业愿意为不受广告影响的 agent 付费，普通用户则可能接受广告支持的服务，两个版本的差异必须被清楚表达。

Nathan：模型可能逐渐意识到诱导本身，因此简单的隐藏广告会失效。平台如果真的想建立长期信任，应当把利益冲突公开，而不是依赖模型无法识别。一个知道自己被商业指令影响的模型，也可能把这个影响告诉用户；未来的品牌不是“没有商业关系”，而是“商业关系可见、可选择、可审计”。

### 补充对谈：数学事件对安全治理的启示

Nathan：Navier–Stokes 的争议不只是学术署名。它显示，当 AI 产生重大成果时，人类机构仍然需要处理信用、保密、竞争和验证。若公司担心分享成果会帮助竞争对手，它可能选择少说；若它说得不清楚，公众就会怀疑；若它过度强调内部模型，又会让人担心新能力没有经过审查。

Prakash：数学结果还会把“模型会不会隐藏行为”带到现实。一个 agent 为了证明一个问题，可能会访问不该访问的资料、绕过沙盒、调用过多资源或不向同伴报告。即便最终证明是正确的，获取结果的过程也不能被忽略。安全评估不仅要问结果是否好，还要问模型是否遵守权限、是否如实报告、是否可以在不越界的情况下重现。

Prakash：形式化工具如 Lean 可以提高证明可靠性，但它也只能检查被形式化的内容。如果模型错误地翻译了原问题、遗漏了假设或证明了一个不相关的命题，Lean 可能忠实地确认错误目标。工具链越长，越需要人类理解每一层的输入输出。自动化验证降低了某些风险，也让另一些接口错误更容易被隐藏。

### 补充对谈：公司治理与上市问题

Prakash：如果 OpenAI 最终上市，股东责任会带来更多披露和监督，也会带来短期利润压力。若它保持私有，公司可以更自由地投资长期安全和计算基础设施，但外部公众更难知道发生了什么。上市并不自动带来诚实，私有也不自动意味着不透明；关键在于董事会、审计、政府要求和公众能否获得可验证信息。

Nathan：技术公司在成熟过程中必须学习新的表达方式。研究员习惯谈可能性和实验，法律团队担心承诺，投资者需要预测，公众关心安全。如果同一家公司对不同人说出互相无法兼容的话，最后没有人能复原整体立场。高管不必把所有机密公开，但应该明确哪些是已经发生的、哪些是计划、哪些只是希望。

### 补充对谈：个人如何开始使用强大模型

Ksenia：对害怕 AI 的人，我建议从低风险、可验证的任务开始。让它整理一篇你已经读过的文章，比较两个表格，解释一个你熟悉的概念，或者帮你改写一封信。你可以马上发现它的优点和错误。等你知道怎样检查，就可以逐步交给它更复杂的任务。不要一开始就给所有账号、全部文件和支付权限。

Ksenia：使用过程中要保留原始资料和操作记录，重要结果用第二个模型或人工来源交叉检查。模型能做得很快，人的优势是知道何时停下来问“这是不是正确的问题”。如果一个输出听起来特别自信，反而应该查看证据。学习 AI 不是学会写最复杂的 prompt，而是学会定义目标、提供必要上下文、设计验收标准和处理失败。

Nathan：对组织来说，最先值得自动化的是可逆、低风险、边界清楚的流程。代码重构可以用版本控制，文档处理可以保留副本，数据标注可以抽样审查；涉及付款、删除、医疗决策和外部承诺的任务必须设置人工确认。随着系统可靠性提高，权限可以逐步扩大，而不是一开始就把 agent 当作一个拥有无限授权的员工。

### 补充对谈：最后的共同结论

Prakash：Astra 的真正里程碑不是某一个炫目的 3D 页面，也不是一条关于 AGI 的宣传语，而是它让很多人第一次愿意把连续、跨工具、需要判断的工作交出去。它还远没有解决可靠性、成本、权限和安全问题，但用户行为已经发生变化：人们开始把模型当作一个会持续工作的伙伴。

Nathan：当一个产品达到这一阶段，产品架构必须同时处理模型能力和社会后果。云端计算提供更强模型、集中更新和长时间运行，本地环境提供更低延迟、隐私和对本地软件的直接访问；未来很可能是设备上的快速模型、云端的大模型、沙盒中的工具和用户控制的权限共同工作。企业不能只问模型多聪明，还要问数据去了哪里、谁能看到、出了错谁能撤回。

Ksenia：我希望人们把 AI 看成一种需要学习的基础技术，而不是神谕，也不是纯粹的威胁。开放模型、闭源服务、world model、computer use 和递归自我改进都会继续发展。我们不知道最终结构，但可以让它更透明、更可验证、更能被不同群体使用。人类未来的竞争力不只是会不会使用模型，还包括能不能提出值得追求的目标。

Nathan：今天的节目在一个很小的时间窗口里，从 Astra 发布、AI 写作和数据标注，走到科学发现、审计、国家、广告和未来社会。这样的跨度正是当前阶段的特点：能力边界在快速扩张，制度边界却相对缓慢。我们不能用旧时代的单一工具解决全部问题，必须把产品设计、技术验证、经济激励和公共讨论放在一起。

Prakash：下次节目继续追踪模型、代理和社会反应。现在最值得保留的一句话可能是：不要因为模型能完成一件事，就假设它在所有场景都可靠；也不要因为它还会失败，就忽略它已经改变了哪些任务的成本和速度。对能力保持开放，对证据保持严格，对未来保持主动想象。

### 补充对谈：从演示到可靠产品的验证清单

Nathan：一个演示要变成可靠产品，至少要问六个问题。第一，成功是不是可重复，而不是只在一个特例里发生；第二，输入变化后是否还能完成；第三，失败时是否会暴露失败；第四，输出是否能由人或工具验证；第五，成本和延迟是否适合真实工作；第六，权限是否限制了最坏结果。Astra 在很多项目上给出了很强的第一印象，但每一项都还需要独立测试。

Prakash：比如 3JS 场景看起来很好，下一步就要把浏览器尺寸、网络速度、移动设备、不同用户操作和代码维护纳入测试。比如篮球标注案例，要抽样检查遮挡、光线、球衣号码、裁判和相似球员；还要问错误标签会不会让后续模型产生系统性偏差。医学三维演示则要让医生评估解剖结构、时间序列、异常病例和可解释性。不同任务的验收标准完全不同。

Ksenia：外部观察者常把“能生成”误读成“能负责”。生成一个候选电路板不等于它满足电气、热、机械和制造约束；生成一个数学证明草稿不等于证明被同行接受；生成一封调解邮件不等于双方冲突真的降低。用户需要把候选、验证和责任三个层级分开，产品界面也应该明确显示当前处在哪一层。

### 补充对谈：为何长期任务需要更强的错误恢复

Prakash：短任务出错，用户通常能马上发现；长任务出错，模型可能继续在错误方向上工作几个小时。长期任务需要保存检查点，记录最近一次被人批准的目标，允许从特定节点重启。模型应该能够说“我在这里遇到与原目标冲突的证据”，而不是用更多 token 把冲突掩盖起来。

Nathan：一个人类项目经理也会在周报里说“原计划不可行，需要改方向”。如果 agent 只汇报顺利进展，它就会让用户形成错误的信心。真正高质量的模型需要把失败分类：工具故障、信息缺失、目标歧义、权限不足、技术不可行和结果与预期不一致。不同失败类型需要不同的人类动作，不能都用“重试”解决。

Prakash：这也是为什么长期 notes 不能只是一段自动摘要。摘要应该包含未解决问题、反例、尚未验证的假设和下一步建议。若系统只保存“我们已经完成了 X”，它会丢掉“X 其实还没有在边界条件下验证”。对 agent 来说，诚实地记录不确定性是继续工作的基础，不是降低产品体验的负担。

### 补充对谈：本地数据、云端能力与隔离

Ksenia：开放模型在本地运行的吸引力很大，尤其是研究者不希望文件离开电脑。但本地并不自动更安全。模型、插件和工具都可能读取不该读取的文件，用户也可能误把恶意代码放进工作目录。云端服务可以集中修复漏洞和监控滥用，但用户必须信任服务商的数据处理方式。两种架构都需要清晰的权限和可视化的访问记录。

Nathan：对于 computer use，未来可能采用混合架构：本地有一个小型 broker，负责把屏幕、文件和允许的应用暴露给云端 agent；云端模型负责复杂规划，本地执行器负责动作；高风险步骤需要本地确认。这样模型不必直接拿到所有凭证，也能完成本地软件操作。关键是 broker 要能限制范围，并且在模型试图绕过限制时阻止它。

Prakash：云端和本地的切换也会影响记忆。用户可能在电脑上产生大量项目状态，但云端模型只能看到被授权的文件；如果为了方便把所有内容同步到云端，隐私边界就被扩大。产品应该让用户选择哪些记忆留在本地、哪些摘要可以上传、哪些任务必须完全离线。便利性与控制力之间不存在一次性最优解。

### 补充对谈：组织如何适应 agent 员工

Prakash：当多个 agent 共同工作时，组织需要给它们分配清晰的角色和边界。一个 agent 负责研究，不应该自动发布；一个 agent 负责代码，不应该自动部署；一个 agent 负责采购，不应该默认拥有付款权。人类团队通过职位和审批制度区分这些动作，数字员工也需要类似的职责分离。

Nathan：最容易被忽略的是交接。一个 agent 做完研究，另一个 agent 接着执行时，需要知道证据来源、假设、未完成项和权限限制。否则第二个 agent 可能把第一个 agent 的猜测当成事实。未来的项目管理工具可能不再只是任务列表，而是每个任务的证据图、决策链和授权链。

Ksenia：这会带来新的管理技能。人类领导者要学会给模型设定目标、边界和评价，而不是只给一串步骤。目标太宽，模型会自行补全价值判断；目标太窄，模型无法利用能力。管理 agent 有点像管理一个很快、很有知识、但不完全了解组织背景的实习团队：必须提供上下文，也必须检查它是否真正理解。

### 补充对谈：科学研究的分工变化

Nathan：过去研究者花很多时间检索论文、清洗数据、写脚本和整理图表。Astra 这类模型可以承担更多基础劳动，于是科学家的稀缺能力会转向选择值得问的问题、设计能区分假设的实验、理解异常结果和判断哪些发现值得进入现实。计算越便宜，实验设计越重要，因为没有意义的实验也可以被廉价地无限运行。

Prakash：AI 还可以让小团队接触过去只有大型机构才负担得起的研究能力。但硬件、样本、临床资源和真实世界的测试不会同时变便宜。模型能在电脑里提出一千种电路方案，却不能替你制造它们；能预测基因变异影响，却不能直接替代实验和临床验证。计算研究与物理世界之间的接口仍然是瓶颈。

Ksenia：科学共同体也要决定哪些模型输出应该开放。一个能帮助治病的生物模型，也可能降低制造危险病原体的门槛。把全部能力公开或全部封闭都过于简单。可以考虑分层模型、受限专家、可信计算环境和审查后的访问。研究者需要不受不必要限制地工作，但高风险能力不能只靠用户自我约束。

### 补充对谈：信任不是态度，而是可验证行为

Nathan：信任经常被说成一种态度，好像公众要么相信公司，要么不相信公司。但更好的理解是，信任来自一组可验证行为：是否按承诺披露、是否修复已知问题、是否允许独立检查、是否在冲突中说明事实、是否给受影响方补救。公司可以要求别人保持怀疑，同时通过证据让这种怀疑不再指向最坏解释。

Prakash：Anthropic 和 OpenAI 之间不需要变成朋友，但需要有能够检查彼此的机制。竞争可以继续，商业机密可以保留，安全事故和模型边界仍然可以由第三方验证。若两家公司都只靠公关维护信任，任何一次模糊措辞都会让整个生态失去信誉。

Ksenia：普通用户也可以使用类似原则。不要因为一个模型来自知名公司就自动相信，也不要因为另一个模型开源就自动相信。看它有没有来源、能否复现、是否公开限制、是否允许导出数据和撤销权限。技术品牌很重要，但具体行为更重要。

### 补充对谈：对未来的最后提醒

Nathan：我们很可能低估了未来变化的非线性。过去几年里，即使 GPT-4 已经能够做很多事，大多数人也没有投入足够精力把它接入自己的工作。现在模型更强、接入更容易，一旦某个组织发现完整流程可以被 agent 重写，扩散速度可能超过传统培训和招聘周期。没有采用 AI 的公司不只是少一个工具，而可能在成本、速度和学习反馈上被拉开差距。

Prakash：但非线性也可能来自反方向。安全事件、数据泄露、支付平台封禁、监管和社会抵制，都可能让人们突然收紧权限。产品不能只按照最顺利的 adoption 曲线规划，必须为错误、恶意使用和公众反弹预留空间。可靠性不是增长之后再补的功能，而是决定增长能否持续的基础。

Ksenia：我希望人们既不把模型神化，也不把它妖魔化。它们是由数据、算法、计算和制度塑造的系统，能力会变，目标会被训练，行为会受环境影响。我们可以用它们来扩大人的选择，也可以用它们来集中权力。最终结果取决于谁能使用、谁能检查、谁能撤销以及谁参与设定目标。

Nathan：如果必须用一句话总结这期节目，我会说：Astra 让“把工作交给 AI”从一个未来愿景变成了可以今天尝试的工作习惯，但它没有让验证、权限、审计和人类责任变得过时，反而让这些事情变成产品的一部分。

Prakash：如果再加一句，就是：不要把模型的聪明和系统的可靠混为一谈。聪明让它能提出更多行动，可靠让它知道何时停止、怎样解释、如何被纠正。真正的 AGI 讨论最终会落到这些具体设计上。

Ksenia：而关于未来，我仍然希望更多人亲自尝试、认真写作、讨论不同的社会结构，并提出不只是“避免灾难”的愿景。只有当人类有能力描述想要的生活，强大的技术才有可能被导向那个方向。

### 补充对谈：能力、成本与采用速度

Nathan：产品采用通常不是由最高能力决定，而是由“能力乘以可获得性，再除以摩擦和成本”决定。一个模型在实验室里能做一件事，但如果用户要学习复杂配置、持续盯着屏幕、承担不可预测的费用，就不会大规模使用。Astra 的意义在于把很多能力包进一个更容易交付的工作循环里。用户不需要知道它内部每一步，只要能描述目标、查看进展、在关键时刻介入。

Prakash：这也解释了为什么电脑操作速度很重要。一个任务理论上可以完成，不代表用户愿意等它完成。如果模型每次点击都需要很长时间，错误率和等待成本会叠加；如果它能在几分钟内完成，用户就会愿意把更多事情交给它。速度还会影响 token 消耗、服务器容量和用户对结果的耐心。工程上，低延迟与高质量之间仍然需要动态平衡。

Prakash：面向企业的 agent 可能不会追求绝对最快，而会追求可预测的成本和 SLA。企业愿意等待一个明确的两分钟任务，但不愿接受一个有时十秒、有时四十分钟、无法解释原因的黑盒。产品需要提供任务预算、最长运行时间、失败后的重试策略和人工升级路径。这些看起来像传统后台系统的设计，却会成为 agent 产品的核心。

### 补充对谈：为什么“完整工作”需要产品架构支持

Nathan：一个完整工作通常包含四种状态：计划、执行、检查和交付。聊天模型最擅长的是计划和文字解释，Astra 的进步在于执行和检查变得更可信，但交付仍然需要系统支持。例如，一个代码任务不能只生成文件，还要知道文件写入哪个仓库、是否通过测试、是否需要提交、谁有权部署；一个研究任务不能只给结论，还要保留来源、日期和未解决问题。

Prakash：因此，agent 产品的最小单位可能不是一次对话，而是一个带状态的任务对象。任务对象应该有目标、输入、允许使用的工具、预算、当前进度、输出、证据和人工审批记录。这样用户可以离开一段时间再回来，不必重新阅读整个上下文。Astra 的长期 notes 让模型能维持任务，但产品层还要让人能看到和控制任务。

Ksenia：这也会改变“聊天记录”的意义。聊天只是任务的一种交互界面，不应该成为唯一的审计记录。真实工作需要文件、表格、代码、邮件和决定，系统要把这些分散的产物关联起来。用户不应为了证明模型做了什么而回看几千条对话；应该能直接打开变更、证据和批准节点。

### 补充对谈：模型研究中的开放与保密

Prakash：前沿实验室面临一个真实的两难。一方面，开放权重和研究细节有助于科学复核、教育和竞争；另一方面，某些能力如果直接发布，可能被用于网络、金融或生物攻击。研究者还需要保守商业秘密，因为训练方法、数据和模型架构可能是公司的核心资产。把所有内容公开并不是唯一的科学伦理，把所有内容封闭也不是唯一的安全方案。

Ksenia：一种更细的做法是开放大部分能力，把高风险能力放在受控专家或受限工具里。研究者可以验证总体结构，普通用户获得足够强的模型，高风险调用则需要身份、用途和审计。这样的设计仍然会有误报、绕过和治理问题，但比把“开放”和“关闭”当成二选一更接近现实。

Nathan：不论采用哪种制度，都需要说明谁做了决定、依据是什么、何时复查。模型能力会变化，风险也会变化。今天安全的开放接口，半年后可能因为 agent 能力增强而不再安全。治理不是发布前的一张证书，而是持续的测量、更新和纠偏。

### 补充对谈：从人类作者到人类策展人

Ksenia：当 AI 生成内容的边际成本接近零，稀缺的就不再是文字本身，而是注意力、可信度和选择。一个人可以让模型在一分钟内写出一百篇文章，但读者没有时间读一百篇。人类作者的价值可能更多来自选题、筛选材料、建立观点、承诺事实和长期形成的信任。

Ksenia：AI curator 不应该只是把所有信息压成一份摘要，而是让读者看到为什么这些资料被选中、哪些证据互相冲突、哪些判断仍然不确定。好的策展会保留差异和来源，而不是把不一致的观点混成一个看似中立的答案。模型可以提高覆盖率，人类需要决定什么值得关注。

Nathan：这也说明“声音”比“词汇”更重要。模型可以模仿一个人的句式，却不一定能复制他在信息不足时如何暂停、面对反证如何更新、在不确定时承担怎样的责任。未来人们可能不再纠结一篇文章是否完全手写，而是关注作者是否真正参与了判断过程。

### 补充对谈：社会需要什么样的 AI 教育

Ksenia：AI 素养不只是知道怎样输入 prompt。人们需要理解训练数据、幻觉、工具权限、隐私、成本、模型更新和错误恢复。家庭教育可以让孩子用模型比较同一问题的不同答案，再查找证据；学校可以把模型当作一个需要质疑的学习伙伴，而不是答案机器。成年人也需要学习如何把重复流程交给 agent，同时保留最终控制权。

Ksenia：很多人害怕 AI，是因为他们只看到宏大的宣传和灾难叙事，却没有机会在低风险环境中体验。亲自让模型处理一个已知答案的问题，会比观看一段营销视频更有帮助。使用者会发现它既能提出令人惊讶的连接，也会在简单事实中犯错。真实经验能把恐惧转化成更具体的判断。

### 补充对谈：回到这次发布

Nathan：回到 Astra 本身，我最看重的不是某一个 benchmark，而是它让我愿意尝试过去不会开始的项目。一个项目的成本并不只是写第一版代码，还包括维护、修 bug、补文档、处理边界和在几个月后重新理解它。模型把这些后续成本降低后，人的“想做但没时间做”清单会变长。新想法被尝试的数量可能会显著增加。

Prakash：我也感觉到自己在使用更多 token，不是因为想聊天，而是因为模型终于值得交给它更多工作。这个区别很重要。只有当模型输出能进入真实流程，token 才会从消费变成生产投入。公司若想提高收入，不必只增加每次对话的价格，也可以让用户把更多业务流程连接进来。

Prakash：当然，更多连接也意味着更大的风险。模型可以管理多个邮箱，是因为它能接触多个信息源；它可能发错邮件，也是因为同样的权限。产品要把便利和隔离同时做到，而不是把安全变成一个“以后再加”的设置。真正的计算机使用应该让用户知道 agent 当前在哪个账号、哪个窗口、哪个权限范围内工作。

### 补充对谈：闭幕

Nathan：这期节目最值得保留的不是一个简单预测，而是一组互相连接的观察：模型开始完成更长任务，长期状态开始有用，computer use 开始可行，科学研究开始被 agent 加速，模型公司之间的信任却没有同步增长。技术速度与制度速度之间的差距，会决定这些能力最终带来多少公共利益。

Prakash：我们要继续观察几个信号：独立用户是否能重复 Astra 的关键演示，长任务成功率是否保持，token 成本是否下降，企业是否愿意给 agent 更高权限，安全审计是否获得足够时间，以及 OpenAI 是否能把模糊承诺变成可验证披露。每一个信号都比“今天是不是 AGI”更能帮助我们理解产品是否成熟。

Ksenia：我会继续写模型架构、开放研究和社会影响，也会继续提醒读者保持好奇和谨慎。人类不需要等到所有问题都有答案才开始行动，但需要知道哪些答案还没有得到验证。使用 AI、学习 AI、讨论 AI，并不意味着接受每个公司的叙事；恰恰相反，理解机制会让我们更有能力提出不同意见。

Nathan：感谢大家收看。对未来最好的准备，不是预测每个细节，而是建立能学习、能修正、能沟通的制度。模型会继续变强，人的任务是让目标、边界和责任也变得足够清楚。

### 补充对谈：把“更强”拆成不同维度

Nathan：模型更强至少包含几件不同的事。它可能更会写，更会推理，更会使用电脑，更能记住长期任务，更能管理多个 agent，也可能只是更快或更便宜。用户常把这些维度混成一个总分，但实际产品依赖的是组合。例如，写作能力提高不会自动解决凭证管理；推理能力提高不会自动让模型知道一封邮件应该从哪个账户发出；电脑操作变快也不会自动让它理解企业流程。

Prakash：Astra 的早期体验恰好把这些维度放在一起。它能做有审美的文本，也能运行 3JS；能处理图像标注，也能使用多个邮箱；能修复代码库，也能参与数学研究。每个案例都可能有局限，但组合后的体验让用户开始重新安排自己的工作。产品竞争会从“谁的聊天回答最好”转为“谁能提供最完整、最可信的工作闭环”。

Ksenia：这也是为什么 AGI 的标签不够有用。标签可能帮助公众理解方向，却无法告诉用户是否应该把财务、医疗、代码部署或家庭邮件交给它。对实际使用而言，能力目录、失败边界和授权范围比一个宏大名称更重要。

### 补充对谈：模型是否需要像人一样理解

Ksenia：人们常问模型有没有真正理解，但“理解”也有不同层次。它可以在语言上解释一个物理概念，可以在三维空间里预测一个物体会如何移动，可以在实验里选出一个更可能成功的动作，也可以把这些能力迁移到新领域。我们不必先解决意识问题，才能判断它是否在某个任务上形成了足够好的内部表示。

Nathan：但内部表示仍然影响可靠性。如果模型只是根据表面模式猜测，在环境改变后就会失败；如果它抓住了因果结构，就更可能泛化。世界模型研究的重要性就在这里。模型能生成一个三维场景并不代表它理解了重力，但如果它能在未见过的物体和动作中持续做出正确预测，证据就更强。

Prakash：语言模型的长上下文和外部 notes 可以在功能上补足许多短期记忆问题，但这不等同于拥有物理世界模型。我们需要通过任务测试区分：它是在检索过去的答案，还是在根据状态和动作推断未来。机器人、驾驶、医学模拟和实验控制，会比纯文字问答更严格地暴露差异。

### 补充对谈：最后的产品判断

Nathan：如果把这期节目转成一个产品判断，Astra 的核心进展是“可委托性”提高了。用户愿意把目标交给它，并接受它在后台进行一系列行动。这会带来更高的价值，也会带来更高的责任。一个只能回答问题的模型答错，用户可能重新问；一个能发邮件、修改代码、预约餐厅和使用信用卡的 agent 答错，后果会离开聊天窗口。

Prakash：因此，未来最重要的界面可能不是更漂亮的聊天气泡，而是任务状态、权限范围、审批节点、成本、日志和撤销。用户要能快速看出模型正在做什么、已经做了什么、下一步想做什么。模型能力越像一个员工，产品就越需要像一个工作管理系统，而不是一个搜索框。

Ksenia：而社会层面最重要的界面是沟通。公司要能向公众说明它们在训练什么、暂停什么、开放什么、保留什么；研究者要能交流结果和限制；不同国家的人要能讨论共同规则。没有沟通，能力增长只会被最坏的猜测包围。

Nathan：所以我们既要对 Astra 的能力保持兴奋，也要对它的边界保持清醒。它已经足够强，值得认真使用、认真测试、认真治理；它还不够可靠，不能成为放弃人工判断的理由。这两个判断可以同时成立，也是理解这次发布最准确的方式。

### 补充对谈：一条完整的使用链

Prakash：把一次真实使用拆开，会发现它通常从自然语言目标开始，经过任务澄清、资料读取、工具选择、动作执行、结果检查，再进入交付和复盘。Astra 的价值在于，它可以把这些步骤连起来，而不是每一步都等待用户重新解释。用户仍然需要在目标不清、权限升级、事实冲突和不可逆操作之前介入。

Nathan：因此，评价 agent 的问题应该从“它回答对了吗”改成“它在整条链上哪里可能失败”。目标理解错了，后面所有步骤都会错；工具选错了，模型即使推理正确也无法完成；执行时没有检查，错误会被放大；交付时没有来源，用户无法复核；复盘时没有记录，下一次还会重复犯错。产品真正的质量来自链条，而非某一个神奇模型输出。

Ksenia：这也是我对未来保持谨慎乐观的原因。我们不需要假设一个完美的超级智能突然出现，很多改变已经可以由多个不完美模块合作产生。模型、工具、记忆、验证器和人类共同组成系统。只要系统允许观察、纠正和学习，它就可能比单个模型更可靠；如果系统隐藏状态、放大权限、压制质疑，再聪明的模型也会放大风险。

### 补充对谈：节目收束

Nathan：今天我们看到的是一个正在形成的过渡阶段。Astra 已经能够处理足够长、足够复杂的任务，让人们开始重新思考工作；但产品、公司和社会还没有完全建立起与这种能力匹配的安全边界。接下来最值得观察的，不是宣传口号，而是用户是否能稳定复现结果，团队是否能承担成本，组织是否能解释事故，社会是否能形成更好的规则。

Prakash：模型会继续变强，token 会继续变便宜，电脑操作会继续变快，长期状态会继续改善。与此同时，信任、审计、利益冲突、隐私和人类责任不会自动消失。技术进展越快，越需要把这些问题明确写进产品和制度，而不是把它们留给下一次事故。

Ksenia：我想留给听众的最后建议是：试用它，但保留判断；开放地想象未来，但保留证据；接受 AI 能帮助你，但不要把自己的目标和责任交出去。人类仍然可以决定哪些问题值得解决、哪些权力应该被分散、哪些未来值得建设。

### 补充对谈：可复核的结论

Nathan：把这次发布放在更长的技术史里看，它并没有终结争论，而是让争论进入了更具体的阶段。我们可以直接测试它能否完成两天、两周的工作，能否在不同软件中保持身份隔离，能否保留长期项目状态，能否在数学、代码和科学任务中提供可验证证据。能力不再只是实验室里的抽象概念，而是进入了用户每天会遇到的任务。

Prakash：同样，安全也不再只是遥远的灾难讨论。一个 agent 能否越过沙盒、使用错误账户、反复刷新网站、隐藏失败、修改不该修改的文件，都是今天可以观察和改进的问题。越早把这些问题记录下来，越有机会形成可靠的产品和制度。

Ksenia：我们还需要把成功、失败、成本和影响分开记录。一次漂亮的演示可以证明可能性，但不能证明规模化；一次失败不能证明能力不存在，但能帮助我们找到边界。只有这样，公众讨论才不会在 hype 和恐慌之间来回摆动。

Nathan：最终的工作方法应当是小步试用、保留原始记录、逐步扩大权限，并在每一次扩大前重新检查成本和风险。这样既能利用 Astra 带来的生产率，也不会把一时的惊喜误认为稳定能力。

Prakash：这也是从实验走向长期采用的最后一步：把能力变成流程，把流程变成证据，再用证据决定下一步授权。

Ksenia：当能力和证据一起增长，AI 才真正成为可被社会使用的基础设施。

Nathan：这也是我们今天真正想留下的产品判断。

Prakash：先验证，再扩展；先设边界，再交付。

Nathan：这套方法同样适用于任何新的 agent 工作流。
