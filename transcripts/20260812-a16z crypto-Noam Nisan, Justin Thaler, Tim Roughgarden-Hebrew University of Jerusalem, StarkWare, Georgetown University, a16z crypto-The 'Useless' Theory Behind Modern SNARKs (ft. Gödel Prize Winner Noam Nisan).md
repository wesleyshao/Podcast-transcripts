主持人 Tim Roughgarden：1999 年，你和 Éva Tardos 合作的 algorithmic mechanism design 论文发表，算法博弈论和计算机科学与经济学的交叉领域随后快速发展。你当时已经从 Popcorn project 里看到了激励和协调问题，是不是正在主动寻找更经济学的研究？

Noam Nisan：我想研究激励与计算，却不知道经济学里有一个很贴近这些问题的子领域叫 mechanism design。我知道 game theory，但只了解一些基础。Éva 来找我时，拿来了一篇 mechanism design 的论文。我先觉得它和我们的问题相关，于是让她去了解一点 game theory。她后来拿出微观经济学教材，逐渐发现 mechanism design 正好研究如何在不同人的信息和目标不一致时设计规则，让结果符合设计者想要的性质。

Noam Nisan：当时还有其他平行的研究线索。Christos Papadimitriou、Éva Tardos 以及不同大学的研究者，分别从计算、博弈论和经济机制的角度进入这个空间。我们后来发现，完全不同的人从不同方向都在研究类似问题，这说明这里可能真的有一个新领域。那几年大概只有几所大学开设算法博弈论、经济学与计算等课程，名称还不统一。大家会查看彼此的课程，然后互相借用材料。

主持人 Tim Roughgarden：这很像一个开放的共同研究项目。大家一边写论文，一边共同学习。

Noam Nisan：计算机科学有一个经常被批评的习惯，就是在还没有完全理解问题时就先写论文。严肃的其他学科可能会再等一两年，把所有细节弄清楚之后再发表。计算机科学常常是有一个有趣想法就先写出来，在会议上交流；即使有错误，也可以在下一篇论文里修正。这个习惯有风险，但对早期的算法博弈论非常有效。它让不同团队迅速知道彼此在做什么，也让大家共同发现新的问题、方法和技术。

主持人 Tim Roughgarden：早期大家其实还不知道自己到底在做什么，但到 2010 年左右，很多人已经掌握了这个领域的语言。

Noam Nisan：是的。有人把这种提前写论文看成缺点，我认为它在那个阶段反而是优势。一个新领域如果要求每个人先把所有问题理解清楚，扩展会非常慢。开放交流让一个群体一起摸索，失败和不完美也变成了下一次研究的输入。

主持人 Tim Roughgarden：接下来我们回到复杂性理论时期的一项工作。Justin，你第一次遇到 sum-check protocol 是什么时候？

Justin Thaler：我本科上复杂性理论课时第一次遇到它。那门课只有我和另一名学生，课程材料是 Arora 和 Barak 的复杂性理论教材草稿。里面有一章讲交互式证明，核心就是 sum-check protocol，以及 Noam 在 LFKN 论文中关于 #SAT 的结果。让我印象深刻的是，这个如此强大的协议已经被完整地放进教材里，读者可以从非常简单的协议直接看到它如何支撑一个困难问题的交互式证明。

Justin Thaler：几年后我开始读博士，cloud computing 变成学术界想要参与的主题。人们开始问：云端服务器替用户完成了大量计算，用户是否只能相信返回的答案？能不能让云端返回一个证明，用户用很小的成本验证它？我手里正好有 sum-check protocol 这个工具。大规模数据集和 streaming algorithms 的很多问题结构非常干净，可以直接用 sum-check 构造接近最优的协议，证明不受信任的 prover 确实完成了计算。

Justin Thaler：这个方向还和 communication complexity 联系起来。Noam 和 Shakhar Kushilevitz 合写的书对我的训练影响很大。后来我学习了 GKR protocol，它在 2008 年把 sum-check 作为子程序。我们开始实现这些交互式证明，发现它们像是 SNARK 的一半。再加上 commitment scheme，就可以形成 SNARK。今天速度最快的一些 SNARK，核心仍然是这条路线。证明者速度是 SNARK 走向广泛应用的关键瓶颈，所以这条理论线和工程实践一直联系得很紧。

主持人 Tim Roughgarden：Noam，回到 1980 年代末和 1990 年代初。当时交互式证明是什么？为什么人们开始研究它？

Noam Nisan：交互式证明的想法来自几位研究者，包括 Shafi Goldwasser、Silvio Micali 和其他人。他们提出了一个扩展后的 proof 概念：它仍然像证明，但不再是教科书中一次性写下的数学推导，而是 verifier 和 prover 之间的互动，并且使用随机性。只有互动和随机性结合起来，才能得到真正新的能力。如果只有其中一个因素，能做的事情并没有本质增加。

Noam Nisan：在那几年，人们研究轮数、zero knowledge、多个 prover、oracle 等不同变体。大家最常见的看法是，交互式证明只是普通 NP proof 的一个有趣扩展，比 NP 多做一点事，类似一个随机化的 NP。它当然很有意思，但没有人普遍认为它会突然证明一个极其困难的函数。

Noam Nisan：转折来自 Richard Lipton 关于 permanent function 的 random self-reducibility 或 self-correction 结果。permanent 是一个公认很难的函数。我最初看到这个结果时，以为一定有错误，因为我知道，如果这种随机自归约可以和交互式证明结合，似乎会得到一个远比预期强大的证明系统。我反复检查后发现没有错误。原来的证明思路通过代数化和多个变量，确实能够绕过之前认为的限制。

Noam Nisan：这就是 LFKN 工作的重要性。它第一次给出了针对困难函数的交互式证明，而不是只得到比 NP 稍微强一点的结果。它把几个当时已经存在但分散的思想结合起来：算术化、随机性、自归约和多变量多项式。Manuel Blum 等人的工作也让这些思想在整个理论计算机科学社区里流动。很多人都在为相同的突破准备材料，只是还没有把它们放到同一个协议里。

主持人 Tim Roughgarden：你后来在南美旅行期间，IP = PSPACE 的结果出现了。能讲讲那段历史吗？

Noam Nisan：我在出发前不到一周找到了一个基本协议。当时我很兴奋，因为它给出了一个 non-relativizing 的结果，这类结果很少。我把一页纸的想法写进电子邮件，发给了大约十几位可能感兴趣的人，然后去了南美。那是还没有稳定互联网的年代，电话也很贵。我大概每两周才能和父母通一次电话，不知道其他人正在做什么。

Noam Nisan：在我离开期间，Babai 和当时还是学生的 Fortnow 把思路推进成普通的 interactive proof，后来 Adi Shamir 又把它推广到正确的复杂性类别，得到 IP = PSPACE。所有这些事情发生时我几乎不知道进展。一次和父母通电话时，我母亲说她又在停车场遇到了 Avi Wigderson。她拿出一张纸，告诉我 Avi 让她转告：Adi Shamir 已经证明 IP = PSPACE。那是我第一次听到这个结果。

Noam Nisan：我的反应是“太好了，这是一个很漂亮的推广”。我当然不知道他们是怎样从我的 oracle-style 证明变成普通的交互式证明，也不知道怎么把结果推进到 PSPACE，但我觉得它非常漂亮。研究中并不是每个后续突破都必须由最初提出想法的人完成。有人把它向前推进，这本身就是研究过程的正常结果。

主持人 Tim Roughgarden：你之后继续关注 PCP theorem 和 hardness of approximation 吗？

Noam Nisan：我关注了几年，也看了 PCP 之前和之后的工作，但没有再作出贡献。研究重点转向了通信复杂性和其他问题。Justin 说得对，PCP 方向和 sum-check 后来出现了分叉。PCP 的目标是 non-interactive proof，所以技术必须去掉互动；sum-check 最擅长的正是利用多轮互动。也许我当时带来了 sum-check，其他人再把技术推进到 PCP，是一个恰当的分工。

Noam Nisan：做研究的人必须接受失败。你会尝试很多方向，真正成功的只占很小一部分。一个人如果不能接受大多数尝试最终没有结果，就很难长期快乐地做研究。成功不是每个想法都正确，而是让少数真正成立的想法足够重要。

主持人 Tim Roughgarden：Justin，请先解释一下 SNARK 到底是什么。

Justin Thaler：SNARK 是一种证明系统，用来证明你知道某些数据，或者某个程序运行满足某种性质，而且证明很短、验证很快。最简单的证明是直接发送原始数据。比如你声称知道一个一 GB 的文件，它经过 SHA hash 后等于某个值。把文件发给 verifier，verifier 自己运行 hash，就能检查。但这需要传输和处理整整一 GB 的文件。

Justin Thaler：SNARK 的想法是把这个大文件压缩成很小的 proof，例如从一 GB 降到 KB 级别。verifier 检查 proof 的成本远低于接收和重新 hash 整个文件。SNARK 里的 S 是 succinct，表示证明短且易检查；N 是 non-interactive，证明可以被写下来、放到网站或区块链上供任何人下载；ARK 表示 argument of knowledge，意思是如果 prover 实际上不知道声称知道的数据，就很难构造一个有说服力的证明，除非它能破解底层密码学假设。

主持人 Tim Roughgarden：这里似乎有一个矛盾。我们刚刚说交互式证明能做普通数学证明做不到的事，但 SNARK 又是 non-interactive。怎么理解？

Justin Thaler：教科书中的数学 proof，如果命题是假的，就根本不存在能说服 verifier 的 proof。SNARK 的安全性不是这个意义上的绝对不可伪造。理论上可能存在一个能骗过 verifier 的短 proof，但找到它需要破解密码学系统，计算成本可能是数百万年。因此，SNARK 把绝对保证换成了在密码学安全假设下不可行的伪造。

Justin Thaler：构建 SNARK 的简化说法是，把交互式证明，例如 Noam 论文里的 sum-check，加上 cryptographic commitment。交互式证明是构件之一，另一个构件是 commitment scheme。它允许 prover 把一份巨大的数据先“塞进”一个很小的盒子，再把这个盒子发送给 verifier。一旦 commitment 完成，prover 就不能改变盒子里的数据。对大文件做 hash 就是一个最简单的 commitment，实际 SNARK 会需要更丰富的性质。

Justin Thaler：为什么 sum-check 对 SNARK 设计特别有用？因为 commitment 很贵。你要先对数据做 hash 或其他密码学处理，之后还要证明 commitment 里的数据不是垃圾，而是真正满足约束的数据。你承诺的数据越少，承诺越快，证明承诺数据正确也越快。sum-check 允许 verifier 保持高效，同时减少需要被 commitment 的数据量。

Justin Thaler：早期 SNARK 主要是 PCP 加 commitment scheme。PCP 本身是 non-interactive proof，但把 PCP 和 commitment 放在一起会重新引入互动，这类系统可以看成 succinct interactive argument。随后需要通过 Fiat-Shamir transformation 把互动去掉。今天越来越多人认为，如果最后无论如何都要用 Fiat-Shamir，那么就没有必要先把 sum-check 变成 PCP，再把 PCP 变回 interactive argument，然后再消除互动。更直接的做法是保留 sum-check 的互动结构，最后只做一次 Fiat-Shamir。

Noam Nisan：从概念层看，互动、随机性、允许极小错误，以及 argument 这类稍微放松的证明定义，共同带来一个新的能力：对很长的陈述给出极短的证明。普通证明通常需要至少触及被证明数据的每个部分，如果陈述涉及一 GB，证明可能也很大。SNARK 允许你用极少信息验证很长的计算，这就是从这些扩展定义中获得的新能力。

Noam Nisan：sum-check 的核心直觉可以概括为“把两个变成一个”。假设你要对所有 2 的 n 次方个二进制输入求和。你可以先把输入按第一位分成以 0 开头和以 1 开头的两组，于是原问题被拆成两个子问题。代数化之后，可以选一个随机组合，把两个子问题合成一个新问题。如果这个合成问题的答案正确，那么两个原问题的答案通常也正确。

Noam Nisan：这个“两个变一个”的过程听起来像魔术。一个数据点居然足以代表两个子问题，原因在于多项式和代数结构提供了约束。它不是百分之百保证，因为随机组合有很小概率掩盖错误。例如某个随机点恰好使差异变成零，verifier 就可能被误导。真实系统必须把这个错误概率压到实际不可能发生的程度。

主持人 Tim Roughgarden：所以 SNARK 接受很小的错误概率，换取普通证明无法达到的压缩？

Justin Thaler：是的。互动和随机性不是免费的，但它们让 verifier 不必读取所有数据。sum-check 甚至不使用密码学，它在互动执行时是 information-theoretically secure。它位于一个极端：没有 cryptographic commitment，却用多轮互动和小概率错误换来很强的验证能力。密码学 commitment 很昂贵，sum-check 让我们尽可能少依赖它。

Justin Thaler：互动是一个资源。通常的 constant-round interactive proof 不一定比 NP 强很多，但 sum-check 使用很多轮，接近输入维度的轮数。再加上 Fiat-Shamir 等密码学工具，互动可以在最后一步被压平为 non-interactive proof。因此，更多互动换来更少 commitment 数据的直觉是成立的。

主持人 Tim Roughgarden：你们如何看待 sum-check 的理论最优性？

Justin Thaler：在某些 communication complexity 模型里，我们能证明它在 Alice、Bob 和不受信任的 Merlin 之间的通信权衡上达到最优，至少接近常数因子。Alice 有输入 X，Bob 有输入 Y，彼此看不到对方的信息，Merlin 知道两者并试图证明 f(X,Y) 的性质。在这些受限模型中，sum-check 的 prover-verifier communication 已经不能显著改善。这是很强的证据。

Justin Thaler：在一般的 SNARK 模型里，我们还不能给出同样干净的最优性定理，但工程数字也提供了边界。今天证明一个程序正确，prover 可能比不带证明地运行该程序慢十万倍左右。十万倍仍然很大，但如果你只再优化一个数量级、再优化一个数量级，就会接近一个现实边界。Moore's law 也改变了这个问题。十万倍的差距可以粗略理解为需要三十年前的计算能力。用 2025 年的机器去做一个 1995 年机器也能完成的任务，虽然不是最优，但已经不是完全不可用。

Noam Nisan：我直到加入 StarkWare，听到 Eli Ben-Sasson 介绍他们正在真正构建 SNARK 系统、筹集大量资金，并且已经把系统部署到 Ethereum 上，才真正相信它是可行的。此前我完全不相信这种理论构造能变成有人愿意投入资金的工程产品。看到系统确实运行，我才接受它可以进入现实世界。

Justin Thaler：对我来说，变化来自 Zcash 和区块链部署。早期 streaming protocols 对非常具体的问题是实用的，但没有足够广泛的需求。GKR 等通用协议的故事通常是让 Amazon cloud 返回 proof，让用户不必信任云计算，但当时证明的开销可能是一百万倍甚至更高，没有客户会愿意让云计算账单变成一百万倍。区块链改变了场景，而不只是改变了技术。

Justin Thaler：区块链是 SNARK 特别合适的第一块土壤。第一，所有人都有巨大的经济激励去欺骗区块链，试图让全网计算机相信自己有实际上没有的代币，因此 adversarial security 是必须的。第二，区块链中许多最终要证明的陈述非常简单，即使 prover 比无证明执行慢几百万倍，也可能在可接受时间内完成。强烈的安全需求和简单的目标计算结合起来，正好给了 SNARK 进入现实的机会。随着技术继续提速，它还会外溢到其他领域。

Noam Nisan：三十年前回头看，一百万倍甚至十亿倍的开销听起来都太乐观了。那时我会猜测是 10 的 50 次方级别。但工程师和理论家用了很多年，把开销从不可想象的数量级降到 10 的 20 次方、再降到今天的数量级。这是长时间、持续的工程积累。

Noam Nisan：我仍然认为 sum-check 的现有形式不会是最终答案。它可能还会有更好的技术，也许可以使用更好的 error-correcting code。核心的“两个变一个”和代数结构可能会保留，但一定会出现更聪明的使用方式。

Justin Thaler：在某些通信模型里，sum-check 的最优性让我有很强信心。工程上也有很多证据表明，未来的改进更可能来自如何使用它，而不是彻底替换它。我们知道任何带有 multiplication property 的 error-correcting code 都可能成为基础，不一定非要使用低次数多项式，但目前实际部署的系统仍然基本使用多项式。

Noam Nisan：我观察到，很多非常优秀的程序员会同时处理二十个参数，却没有把 price 当成其中最重要的参数之一。他们能精细地优化系统，却没有用经济学的方式思考价格、资源分配和激励。区块链里，用户竞争 block space，需要研究 transaction fees、拥堵、效率和激励。这既有博弈论问题，也有算法问题和机制设计问题。

Noam Nisan：我对 tokenomics 的具体研究还没有特别成功，但我认为必须有人认真整理这些问题。费用和拥堵机制会影响系统是否能运行，但代币制度最终可能更直接地影响社会。如果我们只研究技术细节，却不理解代币供应和宏观激励，系统在更大范围内可能会失去稳定性。

主持人 Tim Roughgarden：你写过关于 tokenomics 的 survey blog，把 micro 和 macro 放在同一个框架里。区块链行业不能等传统宏观经济学家来替我们解决所有问题，我们可能需要先自己建立语言，再逐渐发展出真正新的理论。

Noam Nisan：EIP-1559 是一个很有意思的协议。第一次看到它的定义时，我以为应该交给算法博弈论研究者分析，因为里面有很多机制。后来看到 Tim 对它的激励性质、必要的协同条件等做了分析，我才意识到，设计者其实有非常好的直觉。一个生产中的协议能够在没有完整理论分析的情况下做出这么好的结构，说明模拟、讨论和聪明人的经验有时可以先于正式证明。

Noam Nisan：我们后来研究它是否有效分配 block space。结果显示，它确实具有良好的效率性质，甚至某些看似技术性的设计是达到这种效率所必需的。研究者会问，设计者怎么知道这样做是对的？可能是直觉、模拟、经验和大量讨论共同作用。理论分析的价值，是把这种成功解释清楚，指出什么是必要的，什么地方还可以改善。

Noam Nisan：多维费用就没有这么清楚。现在 Ethereum 里普通交易和 blobs 已经有相对独立的 fee markets，但多数 blockchain protocol 仍然把资源压缩成一个 gas 价格。我们还不完全知道，当资源有不同维度、需求又随时间变化时，单一 gas 和多维 pricing 分别带来什么效率。把时间因素和 worst case 加进来后，理论问题会更复杂。

主持人 Tim Roughgarden：EIP-1559 允许区块大小在目标值上下浮动。过去我以为可变区块主要是给价格控制器提供链上反馈，让它学习 market-clearing price。如果神奇地知道清算价格，可能就没必要允许区块大小变化。但你和合作者的工作显示，区块大小的灵活性本身就是接近最优 welfare 的原因之一。

主持人 Tim Roughgarden：当时 Ethereum 社区里有很多很聪明的人，通过模拟和讨论猜到可变区块有助于平滑需求变化。但有趣的是，他们可能没有正式意识到，这种灵活性正是 welfare guarantee 的关键。如果没有可变区块，那个保证可能不成立。这是理论研究审视生产系统时特别有价值的地方。

主持人 Tim Roughgarden：理论计算机科学的特殊之处就在这里。你可以研究漂亮的数学结构，也可能真正影响技术。即使当下的现实连接很弱，计算本身依然是物理世界里存在的现象。

Noam Nisan：这也是一个幸运的时代。区块链和 web3 仍然很年轻，很多显而易见的问题还没有被问过。二十年后的学生可能会觉得我们当时拥有一个非常容易的研究窗口，因为基本问题都还没有解决。当然，早期领域也有困难，模型不成熟、标准不清楚、失败路径很多，但正因为如此，新的子领域会不断出现。

主持人 Tim Roughgarden：每一代研究生都会觉得前一代把所有好问题都解决了。实际上，只要技术继续变化，就会出现新的计算问题。即使错过一波，也还会有下一波。

Noam Nisan：如果明天 AI 替我们做完所有事情，那当然是另一种可能。但还是应该一天一天地研究，不能提前把研究机会全部放弃。

主持人 Tim Roughgarden：感谢 Noam 和 Justin。今天我们讨论了很多内容，其中一个核心是 arithmeticization。sum-check 的强大之处，并不是从一个看似神奇的公式凭空出现，而是把离散计算转成多项式和代数结构，使得一个小的随机检查可以代表许多局部检查。

Justin Thaler：从今天的抽象理解看，真正需要的未必一定是多项式，而是一种具有 multiplication property 的 error-correcting code。两个 code words 做坐标乘法后，会得到同一个 code 或一个紧密相关的 code。这样，sum-check 能够作用在至少两个对象的乘积上。

Justin Thaler：为什么 error-correcting code 对 SNARK 重要？因为 prover 做错的一小部分必须被 verifier 检测出来。验证器需要某种 distance amplification：很小的错误经过编码后变成容易被发现的偏差。error-correcting code 本来就是解决这个问题的工具。今天的理解是，低次数多项式是一个非常好的实例，但理论上也可能有其他代码。

主持人 Tim Roughgarden：Noam 把 sum-check 概括为“把两个变成一个”。你长期使用这个协议之后，是否也认为这是最好的概括？

Justin Thaler：我认为这是准确的，而且这个洞见从最开始就存在。过去我没有立即用这句话理解它。后来我看到 SNARK 的其他部分也在做类似的事：把一个对象拆成两半，再把两半压进一个对象。许多 commitment scheme 看起来是另一类技术，里面有 hash 和密码学；但如果把定义抽象得足够一般，会发现它们也在重新实现 sum-check 的核心思想，只是运行在密码学层面。

Justin Thaler：我正在准备一篇约三十多页的 survey，标题接近《Sum-check is all you need》。它的观点不是只说 sum-check 是某一个 SNARK 组件的工具，而是说它可以用非常复杂的方式同时出现在多项式 IOP 和多项式 commitment scheme 两个组件里。整个 SNARK 从更抽象的角度看，可能就是对 sum-check 的不同重写和组合。

主持人 Tim Roughgarden：算法设计者最重要的品质是永远不满足。既然 sum-check 已经用了三十五年，我们当然应该继续问是否有更好的东西。

Justin Thaler：我对它的最优性有很高信心，但这并不意味着我们已经找到了所有使用它的方法。直接拿 sum-check 来看，它能做什么并不总是显而易见，如何把它放进更大的系统仍然有大量工作。受限模型里已经有不能显著改进的下界，SNARK 工程里也有一个现实边界：当 prover 只比原始程序慢十万倍时，再优化一百倍当然有价值，但不可能无限降低。

Justin Thaler：所以未来更可能的进步是更聪明地使用这个工具，找到更多适合它的“钉子”，而不是立刻发明完全不同的“锤子”。也许会换掉一部分多项式，或者用另一种 multiplication property，但现在的系统仍然依赖低次数多项式。

主持人 Tim Roughgarden：Popcorn project 里一个关键变化，是任务不再由一个机构内部的可信服务器完成，而是由互联网上的多个参与者完成。即使他们愿意合作，参与者也可能能力不同、目标不同，甚至会为了奖励故意提供错误结果。所以验证和激励必须同时考虑。

主持人 Tim Roughgarden：早期算法博弈论的社区合作方式也值得强调。很多论文当时并不完美，但快速公开让整个领域共同校正。

主持人 Tim Roughgarden：回到交互式证明，传统数学 proof 的特点是 verifier 只要读完证明，就能确定命题是否成立。交互式 proof 增加了 prover 和 verifier 的多轮对话，verifier 可以每一轮随机抽取挑战。

Noam Nisan：互动本身不是重点，随机性本身也不是重点。真正重要的是二者结合。prover 必须在不知道 verifier 下一步随机挑战的情况下回答。如果回答错了，最终很难让整个对话看上去正确。这个机制可以把一个巨大计算的正确性压缩成一系列小检查。

Noam Nisan：早期研究者还在问交互多少轮、能否保护 witness 的隐私、多个 prover 是否更强、oracle 能否带来更大的类别。很多人把它看成“随机化的 NP”，因为它比普通 NP proof 更灵活一点，却没有预期它可以处理 permanent 这样的困难函数。

主持人 Tim Roughgarden：Lipton 的 random self-reducibility 结果为什么重要？

Noam Nisan：因为它说明，对某些困难函数，即使你不会直接求出所有输入的答案，也可以利用随机实例之间的关系恢复目标值。把这个思想和交互式证明结合后，你可以让 prover 在随机点上回答，再用低次数多项式的性质把答案带回原问题。我的第一反应是这样的组合不应该成立，因为它会让证明系统强得出乎意料，但检查后发现代数结构恰好允许它成立。

Justin Thaler：这也说明一个结果一旦出现，重要性会很快被共同体识别。Noam 的早期协议、Babai 和 Fortnow 的推进，以及 Shamir 的推广，形成了一条连续的研究链。后来的 PCP theorem 和 hardness of approximation 继续使用了其中一部分思想，但目标已经从多轮验证转向了非交互的局部检查。

主持人 Tim Roughgarden：Justin，你说 sum-check 像一把锤子，云计算里的很多问题像钉子。具体来说，为什么大数据计算特别适合它？

Justin Thaler：因为大数据算法通常把复杂计算拆成规整的求和、矩阵操作或流式更新。验证者没有时间读取全部数据，但可以要求 prover 把计算表示成多项式，然后通过 sum-check 逐轮把一个高维求和问题降成一个单点检查。每轮 verifier 只需要检查很小的关系，最后把复杂性压缩到一个可以直接计算的值。

Justin Thaler：这种协议还让通信复杂性变得可研究。你可以精确计算 verifier 和 prover 各自需要发送多少信息，证明在某类模型里不能更少。理论上的通信下界并不自动等于生产级速度，但它告诉工程师哪些开销是结构上必须承担的，哪些开销只是当前实现不够好。

主持人 Tim Roughgarden：从交互式 proof 到 SNARK，中间看上去像绕了一圈。SNARK 又不互动，为什么仍然需要交互式协议作为底层？

Justin Thaler：因为交互式协议本身提供了压缩能力。通过多轮随机挑战，verifier 能够把很多可能的错误压缩成一次低概率抽查。密码学 commitment 则解决了 prover 在看到挑战后修改原始数据的问题。Fiat-Shamir transformation 最后把 verifier 的随机挑战从真正的互动中变成由 transcript 派生的挑战。因此，SNARK 的 non-interactive 外表，底层仍然可以包含交互式验证的结构。

Justin Thaler：如果一开始就强行把所有互动去掉，往往会产生更大的 commitment 成本。早期 PCP 路线先把互动变成非互动，再加密承诺；后来人们发现，最后本来还要用 Fiat-Shamir，所以直接以 sum-check 作为交互式核心，再一次性消除互动，可能更高效。

Noam Nisan：我从来没有在 1990 年把 sum-check 当作工程工具。那时连 RSA 都需要认真优化 C 代码才能在合理时间运行，更不可能想象今天的区块链。理论家当时要解决的是“这个协议是否存在”和“它在复杂性上有多强”，不是“如何让它在全球网络上服务数十亿次验证”。

Noam Nisan：真正漂亮的地方是“两个变一个”。假设 F 是一个多变量多项式，你要计算所有二进制输入的总和。第一步可以把第一变量固定为 0 和 1，得到两个较低维的和。prover 给出两个和的总和，verifier 随机选择一个域中的点，把两个子问题的组合压成在这个点的一个检查。下一轮继续固定变量，直到只剩单点。

Noam Nisan：如果 prover 在两个子问题中有一个说错了，错误会形成一个非零多项式。随机点落在这个多项式零点集合中的概率很小，所以 verifier 通常会发现。注意这里的正确性是概率性的，并不是普通数学 proof 的绝对正确。系统设计者要选择足够大的有限域，把错误概率降到现实中可以忽略的程度。

主持人 Tim Roughgarden：这就是 SNARK 交换条件的最小例子。你放弃绝对不可骗，获得了对很长陈述的极短证明。

Justin Thaler：对。一个坏 prover 可能理论上找到伪造，但它不能高效找到。SNARK 把错误分成两类：一种是随机检查不幸地落在错误集合里，另一种是破解 commitment 或底层密码学。第一种通过扩大域、增加检查和重复来降低，第二种依赖密码学难题。这样，系统可以把两类风险都控制在可接受范围。

Justin Thaler：sum-check 还有一个优点是它在交互式状态下不需要密码学。它的信息论安全来自协议结构。密码学主要负责把数据固定下来并在最后消除互动。这种分工降低了需要做昂贵密码学运算的数据量，所以对 prover 和 verifier 都有帮助。

主持人 Tim Roughgarden：为什么区块链是第一个真正的杀手级应用？

Justin Thaler：因为区块链把三个条件同时具备了。第一，安全环境是公开且敌对的，任何人都可以尝试制造错误状态。第二，账本中的状态转移和交易约束通常可以被规整成适合证明的计算。第三，网络中的节点如果每个都重新执行全部历史计算，成本会越来越高，所以一个短 proof 可以让其他节点快速验证。

Justin Thaler：云计算也有信任问题，但早期云计算客户没有足够强的支付意愿来承担证明的巨大额外成本。区块链中的代币价值直接给攻击者制造了高额激励，因此更强的 adversarial proof 有明确价值。它让 SNARK 在技术还不够快的时候也能找到愿意付费的场景。

Noam Nisan：StarkWare 让我第一次看到这种系统不是论文中的概念，而是一个可以部署、可以接收资金、可以放到 Ethereum 上运行的产品。看到实际系统后，我才从“理论上很漂亮”切换到“这确实会成为基础设施”。

主持人 Tim Roughgarden：工程开销从早期的极端数量级降下来，也依赖硬件、编译器、内存布局、并行化和协议设计的共同改进。单看某一篇理论论文，很难预测最终会不会实用。

Justin Thaler：是的。十万倍的 prover overhead 仍然很大，但不能只用“比直接运行慢多少”判断价值。SNARK 购买的是可验证性、可压缩的状态和不必信任某个执行者的能力。如果直接执行成本很小，证明没有意义；如果直接执行无法由网络中的每个节点重复，证明的相对价值就会快速上升。

Noam Nisan：我对 sum-check 的未来既有信心，也保持不满足。核心代数结构非常稳固，可能会被更好的编码或更好的实现包围。就像一个好的算法框架，可以有更有效的工程实现，也可以被放入新的系统，但它的基本洞见不会因为短期的应用形式变化就消失。

主持人 Tim Roughgarden：现在谈 Noam 的 blockchain economics 工作。区块空间是一种稀缺资源，交易在其中竞争。费用机制需要同时解决效率、激励和用户体验。

Noam Nisan：交易费本质上是一个市场设计问题。你要决定如何对不同资源收费，怎样让用户表达自己的需求，怎样避免验证者或生产者利用规则做不必要的套利。algorithmic game theory 可以帮助我们把“看起来合理”的设计写成可分析的机制。

Noam Nisan：EIP-1559 之所以有趣，是因为它同时考虑了 base fee、用户愿意支付的额外费用，以及区块容量随需求变化的机制。人们通过直觉和模拟找到了很好的设计，理论工作则揭示其 incentive compatibility、collusion 风险和 welfare 性质。工程直觉先行并不意味着理论多余，理论可以告诉你这个设计为什么有效，或者在哪些边界外会失效。

Noam Nisan：多维费用的困难在于资源不是单一的。计算、存储、带宽和 blobs 可能有不同的瓶颈。如果把它们强行压成一个 gas，价格信号会混合；如果分别定价，用户和生产者需要处理多个相互影响的市场。我们需要更好的模型来判断哪一种结构在长期和最坏情况下更有效。

主持人 Tim Roughgarden：EIP-1559 的 variable-size blocks 也有一个容易被忽视的效果。区块不是永远固定在 target，而是允许在一定范围内变大或变小。这样做既能吸收短期需求，也能提供价格调节的反馈。你们的理论结果显示，它不仅是学习价格的方便工具，也是福利接近最优的必要部分。

Noam Nisan：这说明生产中的好协议不一定等理论完全成熟之后才出现。开发者有经验、模拟工具和集体讨论，可以先找到一个有效结构。研究者随后把这个结构形式化，发现其中的必要条件。理论和实践不应被看成单向关系，生产系统也会向理论提出新的问题。

主持人 Tim Roughgarden：你说自己始终是 computer scientist，这和“理论研究终究会连接到现实”是同一个态度。不是每一项工作都要立即做产品，但问题要和计算、系统或真实激励保持某种联系。

Noam Nisan：对我来说，理论不是脱离计算的纯数学。即使研究对象是复杂性类别或代数证明，它最终仍然描述某种可以被机器执行、被网络使用或被人类组织的计算。连接可能很远，但它并不是虚构的。

Justin Thaler：SNARK 的历史就是这个连接的例子。1990 年的 sum-check 论文没有区块链，也没有今天的硬件和密码学工程。三十多年后，理论结构被编码进 Ethereum、Zcash 和其他系统。未来 AI、云计算和跨组织数据协作也可能再次打开新的应用。

主持人 Tim Roughgarden：节目最后，我们再谈一遍 multiplication property。Justin，你说它把“错误可检测性”和“两个变一个”联系起来。

Justin Thaler：error-correcting code 的作用，是让一个很小的错误不要继续隐藏。编码后的对象有距离，错误会扩大为可检测的差异。multiplication property 进一步保证，两个编码对象做坐标乘法后仍然落在一个可处理的编码空间里，或者落在一个和原编码密切相关的空间里。sum-check 可以在这种乘积结构上运行。

Justin Thaler：所以更抽象地看，SNARK verifier 需要两件事：一是把大量计算压缩成小的代数检查，二是把 prover 的局部错误放大成 verifier 能发现的错误。低次数多项式同时提供了这两种结构，这就是它从 1990 年代一直沿用到今天的原因。

主持人 Tim Roughgarden：你说正在准备一篇三十多页的《Sum-check is all you need》，听上去并不算一个小 survey。

Justin Thaler：相对于被总结的论文数量，它还是小的。它想表达的是，sum-check 不只在 polynomial IOP 里出现。很多看起来不同的 polynomial commitment scheme，也在密码学层面重复了“拆分、组合、压缩、检查”的结构。只要把术语抽象得足够一般，就能看到这些组件是同一个思想的不同实现。

Noam Nisan：即使 sum-check 最终不是绝对最优，它也已经证明了一个重要方向：证明系统不必和被证明的数据一样长。这个改变比某个具体协议更根本。它让验证从“重新做一遍工作”变成“检查一组经过设计的短关系”。

主持人 Tim Roughgarden：算法设计者永远不满足，但不满足也不等于否定已经成功的工具。更合理的路径是继续寻找新的使用方式、优化 prover、改进编码和减少通信，同时保留已经在现实中证明价值的结构。

Justin Thaler：未来的突破可能来自更好的方式来编排 sum-check，也可能来自把它和新的硬件、专用编译器、向量化计算或新的 commitment scheme 结合。我们不必在“原协议完全正确”和“必须换掉一切”之间二选一。一个三十五年前的理论结构可以继续被重新解释。

Noam Nisan：我希望继续研究区块链中的费用、激励和 tokenomics，也愿意回到证明系统问题。研究生涯会有多个章节，章节之间看起来不相干，但它们可能通过一个更大的问题连接起来：怎样让分散的计算者在有限信息和不同目标下，可靠地完成共同任务。

主持人 Tim Roughgarden：这也是今天最值得带走的结论。sum-check 不是因为它当时已经知道区块链会出现才重要，而是因为它抓住了一个更基础的计算结构。现实技术变化之后，新的系统找到了这把锤子，并发现了足够多的钉子。

主持人 Tim Roughgarden：感谢 Noam Nisan 和 Justin Thaler，也感谢大家收听 First Principles。我们下期再见。

主持人 Tim Roughgarden：从验证者的角度看，sum-check 的每一步都在降低问题维度。一个原本要枚举大量输入的求和，被拆成两个部分；两个部分又通过随机点组合；接着新的多项式关系继续被检查。验证者从不需要保存完整的指数级对象，却能够约束 prover 的回答。

Noam Nisan：这也是代数化的力量。对纯二进制字符串来说，两个子问题只是两个列表；一旦把列表嵌入多项式，随机线性组合就有了可追踪的性质。错误不是任意地散落，而是被一个非零多项式描述。非零多项式在有限域中不可能在太多点同时为零，于是随机性提供了发现错误的机会。

Justin Thaler：这条逻辑也解释了为什么 proof 的长度可以远小于输入。验证者不是逐位阅读原始数据，而是在一个有结构的表示上抽查。结构越好，抽查越能代表整体；结构越弱，压缩就越可能隐藏错误。SNARK 的工程工作，本质上是在寻找既便于压缩又便于承诺、查询和计算的表示。

主持人 Tim Roughgarden：而 commitment scheme 解决的是另一个时间顺序问题。没有 commitment 时，prover 可能先看到 verifier 的随机点，再临时挑选一份有利的数据。先承诺再挑战，才把数据固定下来。

Justin Thaler：对。commitment 可以理解为一个很小的盒子。prover 先把大对象放进去，发送盒子的指纹；verifier 后续提出随机查询，prover 必须证明盒子里对应位置确实有某个值。hash 是最直观的指纹，但 SNARK 需要在效率、可组合性、证明大小和安全假设之间作更复杂的选择。

Noam Nisan：如果把所有原始数据都交给 verifier，验证可能很简单，但通信成本和存储成本会失去意义。好的证明系统不是把工作从 prover 原样转移给 verifier，而是让 prover 承担大部分计算，让 verifier 只检查短而强的关系。

主持人 Tim Roughgarden：这也使得“验证很快”不能和“证明很快”混为一谈。SNARK 通常让 verifier 很轻，但 prover 可能要付出很大计算成本。区块链选择它，是因为网络中的大量节点更需要快速验证，而不是每个节点都重复昂贵计算。

Justin Thaler：研究者还必须区分 prover time、verifier time、proof size、通信量和 trusted setup 等不同指标。一个系统在 proof size 上很好，可能在 prover memory 上很差；一个系统验证很快，可能需要昂贵的预处理。没有单一数字能够概括 SNARK 的好坏。sum-check 的价值之一，是让这些成本的来源能够被清楚拆开。

Noam Nisan：这和区块链费用研究有相似之处。你不能只看某个局部参数。系统可能有二十个可以优化的变量，但价格、稀缺资源和参与者激励经常比程序员最先想到的参数更重要。算法设计与机制设计必须一起考虑。

主持人 Tim Roughgarden：EIP-1559 的经验说明，理论分析也应当关注已经运行的系统，而不是只为不存在的系统提出抽象模型。生产协议有真实数据、真实用户和真实攻击者，研究者能从中看到教科书模型没有表达的边界。

Noam Nisan：同时，理论家也有一个工程师不容易拥有的优势：可以正式分析还没有实现的系统。多维费用、多个资源市场和新的 tokenomics 机制，都可以在实际部署前被研究。最好的状态是理论和模拟帮助系统避免明显错误，生产反馈再反过来修正理论。

主持人 Tim Roughgarden：Noam 说到 tokenomics 时很谨慎。他没有把一个暂时的猜测说成成熟结论，而是承认宏观经济模型仍然不清楚。这种边界意识很重要。

Noam Nisan：我只能说哪些问题值得研究，不能假装已经有答案。代币的 mint、burn、供应量和长期使用，会影响通胀和增长，但区块链的参与者、规则和技术约束又不同于普通国家经济。把传统术语直接套用，可能会让人产生错误的确定感。先建立清晰的问题分类，比随意给出结论更有价值。

Justin Thaler：证明系统也一样。我们可以很有信心地说 sum-check 在一些通信模型中接近最优，但不能把这个结果夸大成所有 SNARK 目标下的完整最优性定理。清楚写出适用边界，才知道下一步突破究竟在哪里。

主持人 Tim Roughgarden：从 1990 年的理论结果到今天的部署，真正发生的不是某个单一发明突然跨越鸿沟，而是很多小改进叠加。更好的编码、更快的多项式运算、并行硬件、密码学承诺、编译器、区块链需求，共同把不可用的开销逐步降低。

Noam Nisan：研究者经常不知道自己的工作哪一天会被使用。我的早期工作没有为区块链设计，也没有把“SNARK”作为工程目标。但如果你研究了一个可靠的计算结构，几十年后可能出现一个恰好需要它的系统。最重要的是把结构理解清楚，并把研究结果传给下一代。

主持人 Tim Roughgarden：最后再回到“useless theory”这个标题。这里的 useless 不是说理论真的没有价值，而是说在提出时，作者很难知道它会有什么用途。理论研究常常先被认为离现实很远，随后技术条件改变，原来的抽象问题突然变成基础设施。

Justin Thaler：sum-check 的故事提醒我们，不要只按短期市场需求判断理论价值。它最初是关于复杂性和交互证明的漂亮结果，后来成为 SNARK 的核心构件，再后来进入区块链和可验证计算。下一次应用可能来自现在还没有被命名的系统。

Noam Nisan：而且应用一旦出现，也会反过来改变理论问题。以前我们只关心证明是否存在，今天还要关心 prover 的能源、内存、延迟、市场激励和部署成本。理论工具必须在新的约束下重新理解。

主持人 Tim Roughgarden：这正是 First Principles 想追踪的过程：基础想法如何从一张 email 里的纸，经过不同研究者的接力，成为真实网络可以依赖的组件。感谢两位嘉宾。

主持人 Tim Roughgarden：如果把整期节目压缩成一条工程链，它大致是这样的：先把计算写成可组合的代数关系，再用交互式证明减少 verifier 需要看到的信息；用 commitment 固定 prover 的数据；用随机性降低抽查成本；再用 Fiat-Shamir 消除互动。最后，密码学安全性、错误概率和实际硬件共同决定系统是否足够可靠。

Justin Thaler：这条链中的每一层都留下了不同的研究问题。多项式表示影响 prover 的计算量，代码结构影响错误是否容易被放大，commitment 影响通信和存储，Fiat-Shamir 影响非交互安全性，而区块链部署还会加入 gas、延迟、节点资源和攻击激励。不能只看一层的漂亮定理，就推断整套系统已经适合生产。

Noam Nisan：同样，区块链经济也不能只看一个 fee formula。要看参与者是谁、资源怎样稀缺、用户是否会改变行为、验证者是否有串通动机，以及代币长期如何流通。技术协议和经济机制彼此嵌套，任何一个局部优化都可能把成本转移给其他参与者。研究的第一步是把这些层次分开，再寻找它们的连接。

主持人 Tim Roughgarden：这也是为什么 sum-check 和 tokenomics 会在同一场对话里出现。一个处理“如何低成本验证计算”，另一个处理“分散参与者如何在稀缺资源上协调”。它们表面不同，背后都在研究有限信息下的可靠协调。

Noam Nisan：无论是 prover 和 verifier，还是区块链上的用户、验证者和区块生产者，最终都需要清晰的规则。规则不必一开始就完美，但必须能被分析、被测试、被改进。理论、系统和经济学的共同目标，就是让一个没有单一可信中心的网络仍然能够完成共同计算。

主持人 Tim Roughgarden：在 verifier 只检查短关系时，信任不再集中在某个云服务商、某台服务器或某个节点上。系统仍然需要相信密码学假设和协议实现，但不需要相信一个执行者永远诚实。这个信任边界的变化，是 SNARK 对数字基础设施最深的意义。

Justin Thaler：而且 proof 的短小让它能够被复制、广播和长期保存。一个节点可以把 proof 放进区块，一个客户端可以下载 proof 而不重新执行全部历史，一个应用可以把复杂计算交给 prover，再让任何人独立验证。这些场景都依赖同一个基本交换：把计算负担放在证明者，把验证负担压缩到接收者可以承受的范围。

Noam Nisan：当年我们只是在研究一个交互式协议的复杂性，没想到它会被放进价值数十亿美元的系统。这里的教训不是所有理论都会成功，而是不要因为当下看不到应用，就过早认为理论没有用途。更重要的是，研究者要诚实区分已经证明的内容、工程上看到的内容和仍然只是希望的内容。

主持人 Tim Roughgarden：这也是今天的收尾。sum-check 的“两个变一个”是一条简单、可复用的核心直觉；SNARK、区块链验证和 tokenomics 则是它遇到不同现实约束后的不同展开。感谢两位嘉宾，节目到这里结束。

主持人 Tim Roughgarden：对听众来说，最实用的理解方式不是记住每个复杂性类别，而是记住验证者的工作被重新设计了。验证者不再复制全部计算，而是检查随机挑战下的一组短关系；证明者先固定数据，再承担大部分计算；密码学把互动和承诺组合成可以公开发布的证明。

Noam Nisan：而在更广的系统层面，可靠协作也需要同样的分解。先明确参与者、信息和资源，再明确谁承担计算、谁承担验证、谁获得奖励，以及错误如何被发现。无论研究的是 SNARK 还是区块链费用，这种把大问题拆成可验证模块的思路，都是最值得保留的方法。

主持人 Tim Roughgarden：如果把这套方法带到下一代系统，问题就变成：哪些计算值得交给不受信任的 prover，哪些数据应该被 commitment 固定，哪些结果可以通过随机抽查验证，哪些经济激励会让参与者诚实。理论不会替工程师自动回答所有问题，但它能把模糊的信任假设变成可检查的协议，把“我们希望系统可靠”变成错误概率、通信成本、验证时间和参与者收益等可以讨论的指标。

Justin Thaler：这正是从“看起来很理论”走到“可以部署”的中间层。只有当每一项成本和安全假设都被写清楚，工程团队才能知道它是在用计算换验证、用互动换通信，还是用密码学假设换公开可验证性。把交换关系写清楚，才可能持续改进，而不是只用一句“更安全”或“更快”描述系统。

Noam Nisan：当这些关系被写清楚之后，未来的研究者才能知道哪里还有空间。也许是更低的通信量，也许是更快的 prover，也许是更合适的编码，或者是让经济激励和技术约束彼此匹配。清晰的边界本身就是下一步创新的起点。
